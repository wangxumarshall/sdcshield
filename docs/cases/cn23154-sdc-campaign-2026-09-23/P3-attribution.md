## 0. rankfile 绑定格式事故与修复 (00:40 – 01:01)

- **症状**: swap37 rep1 RANK_BIND rank3=`0,266-281`/rank7=`0,114-129` (各 17 核, 应 36); 全部 16 rank 绑定被截断成 17~25 核并混入杂核 (0/5/9); cpu139 零 psr 采样 → run 科学无效
- **根因**: `rankfile_custom.sh` 用 `seq -s,` 输出逗号单值枚举 (36 项/rank), hmpi rankfile 解析器对长逗号列表截断错解; 范围格式 (`a-b`) 完全正确 (P2 的 rf_w0/w1/w2 无恙, 13/13 崩溃结论不受影响)
- **修复**: 生成器改范围格式; rf_swap37 全 16 行范围; rf_skip139 rank3=`114-138,140-149` 混合语法
- **探针实证** (probe_bind.sh, 1711622/1711632): rf_swap37 16 rank×36 核 rank3=精确 266-301 rank7=精确 114-149; rf_skip139 rank3=35 核精确无 139, **全文件 core139 出现 0 次**; 回退变体 rf_skip139b(115-150) 被探针抓出**包含 139** (设计失误——139 把 NUMA3 域 114-151 切成 25+12, 无排除 139 的 36 核连续段) 后删除
- **无效 run 处置**: swap37 rep1 (604s, dkill 于 init 元素 23/40, exit=1 非崩溃) + rep2 (4s) 移出 results.tsv (备份 .bak_p3bindfix), raw 目录改名留证
- **列语义修正**: results.tsv 第 7 列 = mpirun 退出码 (139=SIGSEGV / 1=被杀 / 124=TMO / 127=未找到 mpirun), 非 implicated cpu
- **教训**: rankfile 验证必须落到"解析后实际绑定核集合成员"; 任何变更先过 probe_bind.sh

## 4. 终判

**cpu139 是该 SDC 故障的必要且充分条件 (实验精度内):**

| 证据 | 实验 | 结论 |
|---|---|---|
| 必要性 | skip139 (139 空闲 3h/86 轮) | 零崩溃 + 全部数值金标通过 |
| 充分性(域内) | W1/W2 follow-core | 13/13 崩溃 psr 钉在 139 |
| 域跟随 | swap37 ×2 | 崩溃者 = 占用 114-149 的 rank, rank 身份无关 |
| 非降频 | 15 次崩溃时刻 139 均满频 2000MHz | 排除降频混淆 |
| 签名一致 | 15/15 垃圾 byte6(+2 例 byte7) + 完整低 48 位指针 | 同一底层故障模式 |

二分干净: 139 在某 rank cpuset 内 → 15/15 在 355s 内崩溃; 139 不在任何 cpuset → 0 崩溃。
故障与 rank 身份/NUMA 域身份/软件放置无关。下一步 P4 (邻核/缓存域确认) → P5 微架构定位
(工作假设: cpu139 load 路径 byte-lane-6(+7) 损坏)。

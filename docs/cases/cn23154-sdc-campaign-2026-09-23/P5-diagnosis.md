## 2. 故障签名 (17 例 = P2 x13 + P3 swap37 x2 + P5 perf2 x2)

- **崩溃点分布**: stencil iter2 x5 (a.out+0xa1a64 x4 / +0xa19e4 x1, 恒配 +0x274428) / eigen_solver x5 (+0x260a70 x2, +0x25faf4 x3) / **libomp.so+0x80030 x5** (P2 x3 + P5 run_A/run_B) / swap37 调用簇 x2 (rep1 a.out+0x139ac4/+0x12ed28/+0x26f628→libomp, rep2 libucs→libomp)
- **地址分解 (17/17 一致)**: faulting addr = <1-2 字节随机垃圾, 占据 byte6[+byte7]> ‖ <完好低 48 位有效指针>; 低 48 目标区自洽: 0x4001.. mmap 区 x11 (stencil x5 + eigen x5 + swap37 rep1), 0xaaaa/0xaaab 堆区 x6 (libomp x5 + swap37 rep2)
- **垃圾值无固定模式** (0x7a,0x44,0x2eb4,0x21d6,0x34,0xa0,0x87,0x57,0x45,0x9e,0x7c,0xa1,0x9c,0x85,0x9c,0x9d,0x4d) → 非 stuck-at 固定位, 呈边缘读出噪声特征
- **关键不变量**: 48-bit 用户态规范指针 byte6 恒为 0x00 → 任何非零 byte6 即损坏; aarch64 高字节本应为零使该 lane 的损坏必然显形
- **崩溃时长**: P2 的 13 例呈双峰 — 晚崩簇 345.5-355.4s (stencil x5 + libomp x3), 早崩簇 87.4-140.2s (eigen x5); P3 两例 104.0s / ~349s; P5 两例 281.3s / 191.2s (perf time-enabled 实测); 跨 87-355s 阵发分布 (bursty)
- **P5 完美捕获**: run_A 崩溃线程 tid=286183 与 perf -t 测量线程完全一致, faulting addr 0x9daaab038024c0 (垃圾 0x9d + 堆 0xaaab038024c0); run_B tid=342237, 0x4daaab13a29580 (0x4d + 堆) → 崩溃全过程的计数器画像完整在案

## 5. 频率 / 温度相关性

- **频率**: campaign 全程 freqmon 守护进程逐核采样, 139/140 从未低于 1996MHz; 17 次崩溃时刻全部处于 1998-2000MHz 满频。早前汇总出现的 "min=1MHz" 为守护进程 CSV (MHz 整数) 与作业采样器 (kHz) 跨格式 awk 伪值, 已逐样本核实澄清 (931/931 样本 139 >= 1998MHz)
- **频率依赖** (P2 期故意限频实验): >=1600MHz 复现, <=1550MHz 零复现 → 典型时序边际特征 (降频增加时序余量即恢复), 支持硬件弱单元而非软件 bug
- **温度** (实测, job 1714248, 608 核整核燃烧): 板上无 CPU 专属 thermal_zone (仅 4 个 ACPI zone); 空闲 49.0-50.0 C → 满载 +150s 51.0-52.0 C → 停载 20s 即回落 49.0-50.0 C, 温升仅 +1~3 C, 远离过热区间; 崩溃跨温度条件稳定 → 非热致
- **漂移核台账** (用户频率规则执行记录): EXCLUDED(<1500MHz, 只压不测): cpu240@1452, cpu304@1481, cpu252@1445, cpu406@1475, cpu419@1307 (末三者 dwell 窗口新跌落, 此前全部窗口满频; cpu497 曾跌后恢复); GREY 持续: cpu517/525/320/374 + 各窗瞬态灰核; 均非研究核 (139/140 全部 P5 窗口 >=1998MHz); 全量台账见 RES/summary/freq_anomalies.md 与 RES/summary/admin_requests.md

## 6. 根因假设与置信度

**最终画像**: cpu139 核私有数据保持/读出路径中, byte-lane-6(+7) 粒度的边际弱单元。平时不表现 (计数器无异常, 9 类合成负载全过), 仅在真实 XLSDFT 特定执行上下文 (指令序列 + 运行时内核交互 + 真实数据值) 组合下, 于 2GHz 时序余量边缘发生单次 8-16 位翻转; 降频至 <=1.55GHz 即恢复。

候选单元排序 (置信度):
1. **L1d/L2 数据阵列弱位** — 中置信: 签名是存储值损坏 (指针在高 16 位被翻转); 但 192KB/8MB/512MB 覆盖 + 100 次驻留停放均未触发 → 若成立, 需特定 set/way + 特定邻居行活动模式的组合, 合成负载未能构造出该组合
2. **LSU/读出通路时序边际** — 中置信: 17 例均为 load 使用点崩溃且指令类型混布; perf 无持续异常与"特定序列窗口才失守"相容; XLSDFT 中 SVE gather/多成分寻址序列未被合成负载复刻
3. **PRF 弱表项** — 低-中置信: 重命名随机分配应使各负载均能命中 (但未触发); 寄存器停放 (park_reg) 未触发; 然而真实上下文的"停放 + 特定邻近指令窗口"组合未测
已排除机制: stuck-at 固定位 (垃圾值 17 例无重复模式); 集群共享/互连/内存控制器 (skip139); 持续性劣化 (perf 差分); 软件配置 (probe_bind); 频率混淆 (崩溃均满频); 纯温度 (跨温度稳定)

## 9. 局限与后续 (→ Task 10/11)

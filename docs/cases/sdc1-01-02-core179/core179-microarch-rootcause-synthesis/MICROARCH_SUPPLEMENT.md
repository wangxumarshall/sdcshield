# Core 179 微架构级深化诊断补充（结合 TSV110 微架构特征）

> 本文件是对 `DIAGNOSIS_REPORT.md` 的微架构级深化，基于 `docs/cpu/kunpeng.md` 公布的 TaiShan V110 (TSV110) 微架构定量特征，对五转储重新做比特级建模。
> 置信约定继承主报告：【实锤】= dump/活系统内可复核；【强推】= 多源收敛；【假设】= 软件不可验证。
> 诚实原则：本补充修正了主报告中"单一 fill-buffer 模型"的过度收敛，并在 §3 给出更诚实的三通路(D1/D2/D3)分解与无法裁决的边界。

## 1. 用于深化的 TSV110 关键微架构特征

来自 `docs/cpu/kunpeng.md` §3，与本故障直接相关的几何与时序参数：

| 微结构 | 参数 | 本故障相关性 |
|---|---|---|
| L1D | 64KB, 4-way, 64B line → 256 sets | 组相联几何裁决：坏值源/目标是否同 set |
| L1D 端口 | 2×128bit(16B)/周期，对齐访问 | 字节相位错位(rol8)的物理可行性边界 |
| Load-to-use | 4 周期；indexed +1–2 | 装载返回通路时序 |
| Store forwarding | 6–7 周期，跨 16B 边界 +1–2 周期 | store→load 前递通路（method2/CHAOSLSQFwd 的物理对应） |
| LSU | 2×AGU | 地址生成与数据返回分离 → D1/D2 可分离 |
| dTLB / L2 TLB | 32-entry FA / 1024-entry(11cyc hit) | PTW 读出通路（D3）的对应结构 |
| L1D/L2 ECC | kunpeng.md 宣称"全程 ECC" | C10 静默性的关键约束（见 §4） |
| ROB/PRF | PRF-based, scheduler ~33 entry | 重命名通路（流程A）对照排除 |

## 2. 比特级签名（全部 crash 现场可复核）

### 2.1 组相联几何裁决【实锤】

按 TSV110 的 L1D 几何（set index = VA[11:6]）：

```
15:58 坏值源 __per_cpu_offset[0]  @ 0xffffb378e29e55d0  -> set 87, line-off 0x10
15:58 装载目标 __per_cpu_offset[146] @ 0xffffb378e29e5a60  -> set 105, line-off 0x20
0814 坏值源 __per_cpu_offset[0] @ 0xffffd93715b7e000 (0814 boot's array head) -> set 87
0814 装载目标 __per_cpu_offset[176] @ ...                 -> set ≠ 87
```

源行与目标行不同 set，排除"L1D way/列选通错"（U1）作为主因；强化"fill-buffer/LQ 陈旧项回放"（U4），因为跨 set 的陈旧行回放是 fill-buffer 合并级而非 L1D 阵列选路级的行为。

### 2.2 数据通路签名 D1：字节相位错位的陈旧行回放【实锤】

主报告已证 15:58 的 `x20 = ror1(__per_cpu_offset[0])`（右旋 1 字节）。本补充做了穷举检验：对 192 个槽位逐一尝试 8 种字节旋转，确认：

- 15:58：`x20=0x00ffffcc879da2e0` 命中 `slot[0]` 的 ror1（右旋 1 字节），Hamming 距离 0【实锤】。*（旋转方向退化披露：对 64 位字 `ror1(x)≡rol7(x)`（1+7=8=整字），故 `rol7(slot[0])` 同样 Hamming-0 命中 x20，15:58 在 (ror1, rol7) 歧义下识别，与 0814 的 (ror6, rol2) 歧义对称。承重的是 Hamming-0 旋转本身（位翻转不可达），非右旋方向。）*
- 0814：`x20=0xd93715ba0000ffff` 的最近旋转匹配为 `slot[0]`（值 `0xffffd93715b7e000`，0814 开机的数组头部）的 ror6，Hamming 距离 6，非 0。*（对先前版本的更正：先前称 `slot[1]` 的 `rol6` Hamming-0，两处错误：匹配槽位是 slot[0] 非 slot[1]（见 DIAGNOSIS §3.2 第 1 行），方向是 ror6 非 rol6，距离是 6 非 0。另：对 64 位字 `ror6(x) ≡ rol2(x)`（6+2=8=整字宽），故 0814 旋转在 (ror6, rol2) 歧义下识别，幅度 6-或-2 非 唯一 6。）* 0814 标【强推】而非【实锤】。

两次独立开机、两种不同旋转量（15:58 为 1 字节；0814 按上述歧义为 6-或-2 字节），均命中数组头部（两次均 slot 0，因 per-cpu 偏移数组跨开机/KASLR 异值但匹配槽位索引均为 0）。

审稿人压力测试（已做，已诚实化）：
1. 巧合性：在 192 槽位 × 8 种旋转 = 1536 个候选中，15:58 坏值唯一命中头部槽位（Hamming 距离 0），次近邻距离 2。（诚实更正：先前版本曾量化"恰好指向数组头部的概率 ≈ 2⁻⁵⁸"，我们撤回该数字，理由是循环论证：fill-buffer 陈旧行回放模型*预测*损坏值来自最旧 fill-buffer 条目即数组头部，故"命中头部"是模型一致而非需排除的巧合。承重证据改为 15:58 的 Hamming-0 匹配本身 + 位翻转不可达性，见下。）
2. 位翻转等价性证伪：坏值无法由 slot[0] 的任何单字节 bit-flip 产生（穷举 8 字节 × 256 掩码无命中）；陈旧行回放源 `slot[0]` 到 x20 的 XOR 距离为 popcount-30（真值 `slot[146]` 为 26），故任何 k<30（对真值 k<26）的纯位翻转都复现不了，证明 D1 是结构性字节重路由而非位翻转。*（H5 注：结构模型复现 oops 链是一致性/闭合检查，非独立波普尔证伪，注入器旋转操作即 D1 签名定义性操作；见 paper §5.2。）*

物理诠释：fill-buffer/LQ 中残留的最旧项（数组头部在启动时首次访问、留下最陈旧的 fill-buffer 条目）在特定相位下被以错误字节通道回放给一次本应命中另一槽位的装载。

### 2.3 地址通路签名 D2：MMU 输入地址最高字节被清零【实锤-弱 → 未证候选】

*（诚实更正：先前版本据"translation fault 的 FAR_EL1[63:0] 必须等于翻译地址"做对照，此架构断言是错的：ARMv8-A ARM（DDI 0487 §D13.2.30）规定翻译错误的 `FAR_EL1[63:60]` 为 UNKNOWN/RES0，仅 `FAR[51:0]`（至 [55:0]）架构保证。本节的高 nibble 对照因此非架构证据。又：0814/0824 的 `arch_addr` 高字节 0xd9/0x55 本身是 D1 坏值的非规范高字节，非真内核地址，故 TBI 分析对这些案例不适用。详见 paper §2.2/§3.3。D2 现为未证候选。）*

利用 FAR 架构语义做对照（仅 `FAR[55:0]` 范围内架构有效；高 nibble 差异本身非证据）：

| 案例 | 架构计算地址(x27/x3±off) | 内核打印 FAR | topzero(arch)==FAR? | D2 判定 |
|---|---|---|---|---|
| 0814 | d936bc836a4a97df | 0036bc836a4a97df | ✅ | D2 清晰可见（arch MSB=d9→FAR 0x00） |
| 0824 | 553c521da2e9b99f | 003c521da2e9b99f | ✅ | D2 清晰可见（arch MSB=55→FAR 0x00） |
| 15:42 | ffffa5aa9b5a97e0 | ffffa5aa9b5a97e0 | ❌ | D2 不可见（arch MSB=ff，FAR 仍 ff） |
| 0817 | 00ffd780f5a3a7c0 | 00ffd780f5a3a7c0 | (no-op) | D2 不可区分（D1 产出的坏值 MSB 恰为 0x00） |
| 15:58 | 00ffb34569fc3ac0 | 00ffb34569fc3ac0 | (no-op) | D2 不可区分（同上） |

诚实修正：仅 0814、0824 两例能区分 D2（架构 MSB≠0 但 FAR MSB=0）。15:42 明确无 D2。0817/15:58 中 D1 产出的坏值 MSB 恰为 0x00，使 D2 不可观察（无法区分"地址通路又清零一次"与"本就为 0"）。故 D2 的确凿证据仅 2/5 例，而非主报告暗示的 4/5。这是对主报告的向下修正，不迎合强结论。

D2 的物理诠释：AGU 计算出的地址在进入 MMU 翻译前，其 byte7（MSB）被某一通路强制为 0。这是与 D1（数据通路）不同的通路，位于地址生成结果→LSU 地址呈现→MMU 之间。

register-dump staleness 的排除：一种备选解释是打印的寄存器值为异常处理保存的旧值，FAR 与之不同只是保存时序的伪象。三点证据排除该解释：(1) 反汇编证实 `add x27,x1,x20`（偏移 +0x3c）紧邻出错指令（+0x48），x27 在 fault 点是 architectural-current（无中间修改）；(2) `x27=x1+x20` 算术恒等式在四例全部成立，证明保存值与执行值一致、未受保存窗口二次损坏；(3) FAR_EL1 对 translation fault 的架构不变量（fault.c:919 注释限定 tag-check/SEA，translation fault 须 FAR==translated addr）独立于寄存器保存。故寄存器值与 FAR 的 byte7 差异是真实通路差异，非保存伪象。

### 2.4 页表走查器签名 D3：瞬态走查失败【实锤】

73 次 spurious 翻译错（FAR MSB 全为 0xff，即有效线性映射地址），这些地址正确到达 MMU（无 D2），但硬件走查瞬时失败、同周期 AT 重查又成功。D3 的通路是 PTW 自身的读出数据通路（页表条目读出），与 D1（load 数据通路）、D2（地址通路）三者物理相邻、同核、跨开机共现。*（承重计数分级：73 例中 70/73 为 S1PTW=1 走查活跃事件=干净 D3 群体，3/73 为 S1PTW=0 无走查事件=最可能合法同核 TLB-invalidation 时序竞争（主线 commit 42f91093b043 所针对那类）；D3 干净承重为 70，3/73 不抹平。）*

legitimate OOO walk race 的排除：主线 Will Deacon 补丁将 spurious translation fault 归因于"另一 CPU 刚映射该页"的乱序走查竞态，若按该解释这 73 例属合法竞态而非缺陷。三点证据与之不相容：(1) 72/73 FAR 落在静态线性映射（`.data`/slab/vmemmap，boot 时写一次、永不释放），无并发映射活动，不满足主线补丁的竞态前提；(2) 100% 单点 CPU179，合法竞态应跨 CPU 分布，单核集中与竞态模型不相容；(3) 这些映射在 uptime 6 分钟~146 小时之间任意时刻触发，无对应内核活动。三点共证 D3 非合法竞态。

## 3. 三通路分解与无法裁决边界（诚实）

```
Core 179 私有结构上的共址缺陷族：
  D1 数据通路:  装载返回陈旧行 + 字节相位错位  (15:58 ror1≡rol7 Hamming-0【实锤】, 0814 ror6/rol2 Hamming-6【强推】, 15:42 全零)  【15:58 实锤, 0814 强推】
  D2 地址通路:  MMU 输入地址 byte7 强制为 0      (0814, 0824 两例确凿)                【实锤-弱】
  D3 PTW 通路:  走查器读出瞬时失败                (73 例；干净承重 70/73 + 3/73 可能合法竞争)  【实锤】
```

关键边界（必须如实声明）：D1、D2、D3 可能是三个独立缺陷，也可能是单一缺陷的三种投影，例如 LSU 数据返回 mux 同时喂给 load-data 总线与 AGU 地址反馈时，同一时序边界缺陷在数据样本表现为 D1、在地址样本表现为 D2、在 PTW 读出样本表现为 D3。单/多缺陷裁决在软件层不可解，必须由 RTL/DFT 仿真决定。本报告不主张已裁决单/多，只主张三签名共址、同核、跨开机稳定。

对主报告根因陈述的修正：主报告 §5 的"U4 fill-buffer/LQ 陈旧项回放 + 合并选路错位"作为最优模型仍成立（D1 完全支持），但应补充 D2（地址通路）与 D3（PTW 通路）作为同等需要建模的共址签名，不能仅以 D1 收口。

## 4. 对 TSV110 "全程 ECC" 声明的约束分析【强推】

`kunpeng.md` §3 宣称 L1D/L2 含 ECC。若属实，则：
- D1（坏值 = 陈旧行相位错位）应定位在 fill-buffer 合并级或装载返回 mux 级，而非 L1D 数据阵列：阵列的位翻转会被 ECC 捕获/纠正（单字节多位的随机翻转）；该级位于 ECC 校验点的下游（校验过后的选路/组装），故静默。
- D3（PTW 瞬态失败）同样应在 PTW 读出有 ECC 时被捕获，其静默暗示 PTW 读出返回通路同样位于 ECC 覆盖之外，或 TSV110 的 PTW 阵列无 ECC。
- 若 TSV110 L1D 实际无 ECC（公开资料未披露细节，见主报告 II-6 边界），则 D1 亦可为阵列读出失效。两种情形下处置建议相同（见 §5），但需供应商澄清以定位 DFT 向量。

## 5. 给芯片设计/制造的建设性改进建议（DFT 增量）

基于三通路分解，对 HiSilicon/整机厂的 DFT 质询清单增补（承接主报告 §6.4）：

1. fill-buffer 合并/选路逻辑的 at-speed scan：D1 的字节相位错位签名（15:58 ror1≡rol7 Hamming-0，幅度 1-或-7 歧义；0814 ror6/rol2 Hamming-6，幅度 6-或-2 歧义）是 fill-buffer 字节通道选择/合并级的直接 DFT 向量。建议 scan-at-speed 向量覆盖装载返回 mux 的 8 字节通道相位控制（特别是 1-与-7、2-与-6 字节位移的相位控制，因每对歧义都达到同一签名），复现"跨 set 陈旧行回放"条件。
2. AGU→MMU 地址通路 byte7 的 path-delay test：D2 的 byte7 强制清零是地址通路 byte7 的 small-delay-fault 指纹。建议对地址呈现锁存器增加针对 byte7 的 transition-delay 故障向量。
3. PTW 读出返回通路覆盖：D3 的瞬态走查失败指向 PTW 读出通路，干净承重群体为 70/73（S1PTW=1，走查活跃），另 3/73 S1PTW=0 最可能为合法同核 TLB-invalidation 时序竞争（主线 42f91093b043 所针对那类），故 DFT 向量应针对走查活跃的 70 例。建议 scan 覆盖 PTW 的页表条目读出/锁存路径，并质询 PTW 阵列是否有 ECC（解释 D3 静默性）。
4. DFT 筛选向量交付：`movbe/mrn_rmw + −30mV + Cholesky` 序列（method1/2/3）作为量产 Vmin 筛选向量，新增本补充的 `__per_cpu_offset[i]` 装载-使用-作指针序列作为内核态可触发向量（method3 已实证其用户态可触发）。
5. 单/多缺陷裁决实验：请求对 CPU179 die 执行 scan-at-speed，分别对 fill-buffer 合并级、地址通路 byte7 锁存、PTW 读出通路施加 LBIST；若三者同点失效则支持"单缺陷三投影"，否则支持"多缺陷共址"。这是本补充明确留给供应商的唯一裁决实验。

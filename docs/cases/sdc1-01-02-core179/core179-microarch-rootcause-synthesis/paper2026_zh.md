# Seventeen Collapses on the Road to Data: Cross-Layer Forensics of a Production ARM64 Mercurial Core

版本：2026-09-06（基于 17 案完整数据集重构；取代 2026-09-02 版的 12 天/5 案口径）

## 摘要

静默数据损坏（Silent Data Corruption, SDC）指处理器交付错误数据而不触发任何错误报告。Google、Meta、阿里巴巴的舰队级测量都确认它是云基础设施的常态威胁（每千至三千分之一量级的硅器件）。但现有认知几乎全部建立在指令级功能测试这一观测范式上，根因归因因此收敛于无保护的算术功能单元（SEVI：92% 的 SDC 事件来自 FMA 指令）；至于数据搬运通路的 SDC 机理，学术文献与工业遥测都接近空白。

本文报告一台生产级 ARM64 服务器（Kunpeng-920 / Taishan-v110，192 核）上单核 SDC 的完整自然史：22 天内 17 次开机全部崩溃于同一物理核（CPU179），累计 160 余次内核异常事件，其余 191 核零事件。我们发展了一套跨层取证方法学，以崩溃转储中的寄存器代数闭合（x27 = x1 + x20、FAR = x27 + 0x120，Python 模 2⁶⁴ 逐位复算）与内存真值对照（crash 直读被访存地址）为核心，将故障精确定位到 LSU 装载/存储数据返回通路，并给出四种可区分的坏值形态学：零塌缩（非零指针装载为 0）、撕裂移位（实收值 = 被读数组错相位 N 字节处的真实字节流，+1/+2/+5 字节相位均被 crash 直读唯一命中验证）、宽带位翻转（汉明距离 31–35、均匀散布）、同类指针替换（27 位整字替换且替换值为合法 vmemmap 指针，含写路径持久化与"两次相邻 load 同地址返回不同值"的不一致错误直接实锤）。

本工作的核心论点是：这四种形态是同一边际时序条件在不同逻辑落点上的失败模式谱，合在一起否定单比特翻转故障模型对本案例的适用性，也构成对当代 RAS 体系结构性盲区的生产级实证：ECC 保护的是静止的数据，流动中的数据没有保护。我们进一步论证：(1) 撕裂移位为 SEVI 舰队观测到的"76% 访存类 SDC 为错误偏移读取"提供微观机理；(2) PTW 受扰产生的假翻译故障（内核 `AT S1E1R` 重放即成功）是 mercurial core 唯一的系统级泄漏信号，其按核统计构成零成本检测面（与 Hardware Sentinel 的异常富集方法互证）；(3) 传统位翻转注入无法表达汉明距离为零的结构性错位，需要结构化故障注入（我们的 gem5 原型已端到端复现字节通道偏移→Oops 链）。

**关键词**：静默数据损坏；mercurial core；装载-存储单元；跨层取证；故障注入；ARM64

## 1. 引言

### 1.1 问题的坐标

SDC 研究在 2021–2026 年经历了一次范式转移。Google 的《Cores that don't count》（HotOS'21）命名了 mercurial core 现象；Meta 的 Fleetscanner/Ripple 与 PinDrop（HPCA'26）给出舰队级测量（0.035% 的机器终身至少一次 SDC 失败，>60% 为单物理核缺陷）；阿里巴巴（SOSP'23）确认温度相依性与多位翻转常态；Veritas（HPCA'25）与 SEVI（ASPLOS'26）把微架构根因钉在无保护的算术功能单元上：向量浮点、乘法器、FMA。

但这条知识链有一个方法论裂缝：上述全部归因建立在指令级功能测试上，即用已知输入激励特定功能单元、比对金标输出。这个范式天然偏向"输出即结果"的算术单元，而数据搬运通路（LSU 的装载返回、store 转发、填充缓冲合并、页表漫游读出）的故障需要另一种观测面才能显影：同一访存的内存真值与寄存器实收值的对照。Harpocrates（ISCA'24）的评估数据侧面印证了这个盲区：现有工具对 LSQ 的 SDC 检测率仅 0–20%，是所有结构中最低的。

本文的报告对象正落在这个盲区里：一个生产环境以 17 次崩溃为代价把它反复显影。

### 1.2 数据集：一个 mercurial core 的完整自然史

一台 4 路 Kunpeng-920 服务器（192 核 Taishan-v110，8 NUMA 节点，768 GB，openEuler 6.6 内核），2026-08-14 至 09-04 的 22 天里：

- 17 次开机全部以致命 panic 收场，崩溃执行核 16 次为 CPU179、1 次为相邻的 CPU168（且该案的原始写坏仍指向单核 LSU 通路）；
- 累计 160 余次内核异常事件（假翻译故障 WARNING + 致命 Oops），100% 归属 CPU179；其余 191 核零事件；
- 崩溃现场横跨五个互不相关的上下文（CFS 负载均衡、RCU 状态机、kworker、sftp-server、systemd-coredump），排除软件路径特异性；
- RAS 通路（RAS Extension / GHES / ghes_edac / BERT）全程静默，17 次开机零硬件错误记录；
- 存活时长呈渐进恶化：110h → 66h → 89h → 14h → 66min → 24min（零前兆）；
- 三次 `l1d_disable` 运行时缓解试验均无效。

每个案例有完整 kdump（部分为 incomplete，法证边界已逐案声明）与独立的取证报告，全部命令可复核。

### 1.3 贡献

1. 跨层取证方法学（§3）：寄存器代数闭合 + 内存真值对照 + 架构不变量（FAR_EL1 ≡ MMU 翻译地址）三角互证，把软件可见的崩溃现场剥离到微架构数据通路级。方法只需要 kdump 与 crash，不需要芯片内部信息，因此任何运维方都可复现。
2. 四族坏值形态学（§4）：零塌缩、撕裂移位、宽带翻转、同类指针替换。其中撕裂移位的"错相位字节流唯一命中"证明实收值是真实内存数据的错误路由，不是噪声：这是对位翻转模型的穷举证伪。
3. 单根因论证（§5）：四族形态共享位置不变量（内存真值完好、地址正确、算术自洽、唯搬运交付出错）、单核绑定（(1/192)^(k-1) 的联合概率否定多根因假说）、单一退化病程，论证边际时序故障的多形态性与数据相依性。
4. 文献坐标与增量定位（§6）：与 SEVI/Veritas/PinDrop/SOSP23/Hardware Sentinel/ITHICA/DelayAVF 的逐项对照；论证本案例填补 LSU 数据通路空白、为 SEVI 的"错误偏移读取"提供机理定位、为 DelayAVF 的"时延故障产生多比特错误"预言提供生产标本。
5. 检测与设计启示（§7）：假翻译故障的按核统计作为零成本泄漏信号；load 返回通路端到端校验；结构化故障注入的必要性（gem5 原型已复现）。

## 2. 背景与相关工作

### 2.1 舰队测量：SDC 的流行病学

Google 首次公开 mercurial core（数千颗 CPU 中约一颗）；Meta Fleetscanner/Ripple 给出"千分之一硅器件"口径与检测基础设施双轨（产线外扫描 93% 覆盖 + 在产共栖测试 77%）；PinDrop（HPCA'26）50 个月持续测量：0.035% 机器终身失败、>60% 仅单物理核、兄弟逻辑核共败、>71% 持续失败 2 年以上、有机器 4 年后才首次失败；阿里巴巴（SOSP'23）100 万处理器 32 个月：总 SDC 率 3.61‱、温度指数触发规律（r>0.75、阈值 59°C）、位翻转位置固定倾向、多位翻转常态。PinDrop §II-B 明确排除粒子瞬态假说，把根因归于边际缺陷（marginal defects）引起的小延迟故障，由温度/频率/电压/数据相依触发。

### 2.2 单元归因：算术单元主导，通路空白

Veritas（HPCA'25，雅典大学+Meta）用 gem5 门级注入 + Meta 舰队遥测双向验证：向量 FP/向量整数单元比标量高 2–3 个数量级，乘法器比加法器高 2 个数量级（门数 30×）；标量整数加法器最不易致 SDC（错误多影响地址/控制流，因而崩溃）。SEVI（ASPLOS'26，CMU+Meta）：FMA 占 SDC 事件 92%；访存类 SDC 两模式，错误偏移读取 76% / 数据损坏 24%；98.5% 只影响单个向量 lane。SOSP23 五大脆弱特性：ALU/向量/浮点/缓存一致性/事务内存。

关键空白在于：没有任何一篇把 LSU 数据通路列为 SDC 根因。最接近的 PinDrop Data Move 测试族论文明言"底层硬件根因未知且超出本文范围"；Veritas 的注入只覆盖算术 FU；相关工作仅提及对 AGU 的"有限建模"。Harpocrates 实测现有工具对 LSQ 检测率 0–20%。观测范式与工具能力在这里形成了双重盲区。

### 2.3 故障模型：从软错误到边际缺陷

AVF 经典线（2003–2017）在单比特软错误模型下建立单元排序：存储阵列（DTLB 数据 36%、写回 L1D 25%、指令队列 28%）远脆于数据通路（执行单元 9%，多重 derate）。但 2006 年 H-AVF 已显示硬故障模型下组合逻辑（加法器 0.149）反超存储阵列（L1D 0.005）；MICRO'24 DelayAVF 证明小延迟故障下 ALU 脆弱性是寄存器堆 5 倍以上、约一半诱发多比特错误。故障模型一换，排序反转。ITHICA（Stanford+Google）在真实缺陷硬件上验证"不一致错误"：相同架构输入的同一指令因执行上下文不同产生不同输出。TC'23 系统分析给出 ROB/LQ/SQ 的 SDC 概率为零（提交前依赖检查必崩）：控制流结构免疫 SDC，SDC 专属于数据值通路。

### 2.4 检测防御：四代谱系

离线测试生成（SiliFuzz→Harpocrates→Vega）→ 程序自转化（ITHICA，比 SiliFuzz 多检 69%）→ 在线验证（Orthrus，2–6% 开销、87–96% 覆盖）→ 遥测反推（Hardware Sentinel：单核异常集中 + 罕见内核异常富集（doublefault 59×）+ SEL 静默性，比 Fleetscanner+Ripple 合并仍高 1.41×）。

## 3. 跨层取证方法学

### 3.1 证据规则

全部结论满足三条纪律：(1) 每个结论有实证，即 dmesg 行号+原文、crash 命令+真实输出、寄存器值；(2) 禁止手算，所有代数复算用 Python 模 2⁶⁴ 脚本（algebra.py），输出留档；(3) 法证边界诚实声明，incomplete 转储做不了内存真值对照的，结论降级为【强推】并写明升级途径。

### 3.2 代数闭合：从崩溃现场反推坏在哪一级

17 案中 13 次崩于同一指令序列（`find_busiest_group+0x13c/0x140`，CFS 负载均衡 per-CPU 遍历体）：

```assembly
ldr  x20, [x0, w25, sxtw #3]   ; x20 ← __per_cpu_offset[i]   （被读数组：192 项等差，启动后只读）
add  x27, x1, x20              ; x27 = &runqueues + 偏移
ldr  x23, [x27, #0x120]        ; 读 rq->cfs.load_avg → 致命翻译故障
```

对每次崩溃执行三级闭合（Python 模 2⁶⁴）：

1. ADD 闭合：`x1 + x20_obs ≡ x27_obs`，加法器与输入 x1 无辜；
2. 偏移闭合：`x27_obs + 0x120 ≡ FAR`（f9409377 解码 imm12=0x24×8），地址计算与 MMU 呈现无辜；
3. 期望值闭合：`x1 + __per_cpu_offset[i]_true`（crash 直读内存真值）= 合法 `rq(i)` 实例（与实例内嵌自指针 `nohz_csd.info` 逐位一致，vtop VALID）：若无破坏，本次执行完全正常。

三条闭合锁定唯一的异常变量：`x20_obs ≠ __per_cpu_offset[i]_true`，且内存真值经 crash 直读完好（全数组 0x22000 等差无一项损坏）。故障因此被隔离在"L1D 读出到寄存器堆写端口"这一段：数据在搬运途中损坏，存储本身没有损坏。

迭代号证据进一步收窄绑定关系：两次崩溃的 x25 分别为 97 与 149（≠ 执行核 179）。腐化绑定的是"哪条装载指令在 CPU179 上执行"，与被读槽位无关，即核私有通路而非特定地址。

### 3.3 架构不变量：FAR_EL1 的证词

ARMv8 规定：翻译错误（EC=0x25，FSC 0x04–0x07）时 `FAR_EL1[63:0]` 必须恒等于 MMU 试图翻译的虚拟地址。本案 17 次致命事件全部满足 `FAR = x27 + 0x120` 逐位闭合，说明执行单元发出的地址在到达 MMU 的路上未受损（D2 地址呈现通路排除），损坏只在数据返回方向。与之互补，前兆事件的假翻译故障（§4.5）证明 PTW 读路径受扰：同一通路的另一面象。

### 3.4 反事实推演

对每个致命案例构造反事实：若装载交付真值，后续访存落点经 vtop 验证 VALID 且数据健全（load_avg=1023/1024/241 等），指令平静完成。装载结果被污染是异常的唯一必要条件；反事实把"随机崩溃"变成了"通路故障的确定性演绎"。

## 4. 四族坏值形态学

对 17 案的 x20 实收值与内存真值逐案比对，坏值自然分为四族。

### 4.1 零塌缩族（5 例实证 + 1 例强推）

非零内核指针装载为全零（真值如 `0xffffa89017090000`，实收 `0x0`）。64 位整齐归零不属于任何位翻转形态，指向数据拍未送达：返回总线该拍未驱动（浮空读零），或填充缓冲以零值错误顶替。后果：x27 落回 `.data..percpu` 模板地址，在 free_initmem 解映射域触发 L3/L2 翻译故障（页表几何差异已用双转储并排 vtop 排除新通路嫌疑）。一案零前兆：开机 24 分钟、dmesg 静默 1365 秒后一次致命 Oops。

### 4.2 撕裂移位族（7 例，机理实锤最完整）

实收值既非真值翻转也非随机数，而是被读数组中错相位 N 字节处的真实字节流：

| 案例 | 应读槽位 | 实收值 | 全数组唯一命中 |
|---|---|---|---|
| 08-31 | 槽 60（`ffffbe56fa9b6000`） | `a000ffffbe56fb25` | 槽 125 起点 +2 字节（跨 125/126 槽边界） |
| 09-03 | 槽 12（`ffffb617dc4d6000`） | `00ffffb617dd3940` | 槽 123 起点 +1 字节（跨 123/124 边界） |
| 09-04 09:15 | 槽 151（`ffffb02cd939c000`） | `2cd80e2000ffffb0` | 槽 9 起点 +5 字节（跨 9/10 边界；同时等价槽 10 的 ROL3B） |

命中验证方法：把 192 槽数组按小端拼成字节流，用实收的 8 字节序列全流搜索，唯一命中一处非对齐地址；crash 直读该地址逐位相符。数据源没错，相位错了：这是字节选路网络（对齐 mux / 字节使能 / 合并缓冲指针）错拍的直接签名；SRAM 阵列失效给不出"别处的正确内容"。FAR 形态多样性（高 16 位呈 `ffff`/`0000`/`00ff`/`2cd7` 四种）是撕裂值高位字节的忠实算术投影，独立佐证坏值来自真实内存字节流。

### 4.3 宽带位翻转族（2 例）

x20 与真值异或后汉明重量 31–35，翻转位均匀散布 64 位，无字节/半字/连续位段结构。这排除了字节使能（字节粒度）、字线/列译码（行列聚集）、位线短路（固定列模式）等一切结构化数字故障，收窄到读出模拟前端（sense-amp/位线）在边际压差窗口内的多位同时误读。汉明 31–35 远超门级 stuck-at 的"局部少数错位"能力（Veritas §IV-F），也与单粒子翻转的 1–2 位典型值不符，与 DelayAVF"时延故障约一半诱发多比特错误"的预言吻合。

### 4.4 同类指针替换 + 写路径持久化（09-04 22:09 案，多核级联）

跳出装载路径的一案：per-CPU pageset 链表头 `prev`（真值：自指空表头 `ffff6057fffbe990`）被写成 `fffffd8101333948`，一个合法的 vmemmap struct page 指针（vtop 验证物理地址有效，且该 page 的 lru.next 恰回指坏表头）。XOR 27 位，是整字替换而非翻转。三个实锤：(1) 两次相邻 load 同地址返回不同值（前一条得好值、后一条得坏值），是 ITHICA"不一致错误"的生产级实例；(2) 坏值持久落盘，五个核（168/169/180/50/55）在页分配路径命中坏链表 458+126 次：单核瞬时故障经共享内存传播为多核受害；(3) 该案 CPU179 自身另有独立实锤的读零错误（`__per_cpu_offset[174]` 真值非零读成 0）。

### 4.5 前兆信号：假翻译故障

160 余次 WARNING 中的绝大多数是 `Ignoring spurious kernel translation fault`：硬件对完全有效的线性映射地址（vtop 验证 VALID，含 1GB 大页）报翻译故障，内核用 `AT S1E1R` 重放同样的遍历却成功。PTW 读路径受扰使硬件报出假 fault；它与装载返回坏值是同一数据通路故障的两种面象（可检测面 vs 静默面）。前兆具有高信息量：一案中前兆 WARNING 与致命 Oops 相隔 38 秒，且两事件寄存器指向同一个 sched_group 对象；发作呈簇状脉冲（四簇、簇内毫秒连发、簇间 10 秒整数节律），与电压/频率边际窗口假说吻合。

## 5. 单根因论证

### 5.1 多根因假说的三重反驳

(1) 统计反驳。k 个独立根因全部落在 CPU179 的先验代价是 (1/192)^(k-1)；样本是 17 次开机 160+ 事件无一例外。k=2 已需 2.7×10⁻⁵ 的额外先验，且不换来任何解释力。

(2) 不变量收敛。四族共享五行不变量：内存真值完好 / 地址计算正确 / 算术自洽 / 唯搬运交付出错 / 归属 CPU179。多个独立缺陷恰好全部选中同一段通路、全部绕开同一批检测、全部只在一个核发作，每条都是额外的无证据假设。

(3) 单一病程。存活 110h→66h→89.5h→14.5h→66min→24min；首症从 29h 压缩到分钟级；末期簇发与同对象双击。这是单一物理条件持续退化的曲线；多个独立缺陷同步加速不可信。

### 5.2 一个边际条件为什么长出四张脸

边际时序故障并非"每次错、错得一样"：某拍是否违例取决于该拍数据相依性（翻转方向决定电容负载与耦合）、相邻线串扰方向、当下电压/频率点。同一个边际条件击中的下游逻辑不同，形态就不同：数据使能/总线驱动给零塌缩；字节选路 mux 选择信号给撕裂移位；sense-amp 采样窗给宽带翻转；store 数据选择给同类指针替换。形态是毛刺落点的函数；四个形态不意味着四个根因。反向验证：若真是四个独立根因，落点应随各自缺陷位置散布（ALU/分支预测器/缓存驻留位）；观测为零例散布，全部落在核私有数据交付通路。

### 5.3 诚实边界

两个模型在软件侧不可区分：单点缺陷（某通孔退化，后果扇出）与单一边际区域（局部电源域老化，多条临界路径间歇违例）。后者与渐进恶化、簇发节律吻合更好，我们倾向之，但这是倾向不是证明。裁决需要供应商 ATE/DFT/shmoo：把 179 核与良品核的电压-频率 shmoo 图并排，边际路径当场显形。这是 vmcore 方法论的天花板，全部 17 份报告对此表述一致。

## 6. 文献坐标系中的定位

### 6.1 与共识吻合（独立验证文献）

单核主导（PinDrop >60% / SiliFuzz ~70% vs 本案 100% 同核复发）；间歇性与条件触发（Ripple"6 个月后才失败" vs 本案渐进恶化）；RAS 盲区（SOSP23 Obs 12）；多位翻转常态（PinDrop Obs 11 vs 本案汉明 31–35）；零塌缩有舰队实例（Ripple 的 (1.1)^53→0），但本案首次给出"内存真值非零完好 vs 寄存器实收 0"的对齐实锤：读出不等于内存的直接证据，而不只是结果侧异常。

### 6.2 增量一：填补 LSU 数据通路空白

四篇工业界论文（SOSP23/PinDrop/Ripple/Veritas）的微架构归因全部在算术 FU 与一致性机制；LSU 数据通路在 fleet 测试范式中不可观测（没有"真值 vs 实收"对照面），在注入文献中未被建模（Veritas 只注入算术单元）。本案以三级代数闭合 + 真值对照把故障钉死在装载/存储数据返回通路。这与文献结论不冲突，补上的是该范式观测不到的另一半通路。

### 6.3 增量二：撕裂移位 = "错误偏移读取"的机理定位

SEVI 舰队观测"76% 访存类 SDC 是错误偏移读取"，但论文明言无单元级归因。本案的错相位字节流唯一命中（+1/+2/+5 字节、跨槽边界、crash 直读验证）为该现象提供了微架构定位：字节选路网络错拍。两边的证据指向同一件事：数据搬运的相位错误，一边来自舰队统计，一边来自单核现场。

### 6.4 增量三：DelayAVF 预言与 ITHICA 洞察的生产标本

DelayAVF（MICRO'24）预言小延迟故障诱发多比特错误、单元排序与软错误模型反转；本案四族形态全部是时序/相位类签名（非驻留翻转签名），是这一预言在生产现场的标本。ITHICA 在 RTL 验证中发现"不一致错误"（同输入同指令不同输出）；本案案 14 的相邻双 load 同址不同值为其补了生产级 ARM64 实例。

### 6.5 张力点（诚实标注）

文献的"FMA/向量主导"结论带观测偏差：指令级定向测试天然激励算术单元（测什么发现什么）；本案是被动负载显影（调度器最热整数通路最先致命）。整数数据通路 SDC 存量可能被文献系统性低估。另外 SOSP23 观察位翻转位置固定（算术门级驻留缺陷的签名），本案形态每次不同（通路时序缺陷的签名）：形态稳定性可区分驻留型与通路型缺陷。这是两边数据拼合才可见的规律，值得体系化。

## 7. 检测与设计启示

### 7.1 系统软件：把被降噪的信号升级为遥测

本案的单核归属证明完全建立在"被内核忽略的噪声"上：`Ignoring spurious kernel translation fault` 按核统计，160+ 事件 100% 集中于 CPU179。这等价于手工执行了 Hardware Sentinel 的启发式（单核异常集中 + 内核异常 + SEL 静默），且判别力更强。建议：per-core spurious-fault 计数器 + 假 fault/真 fault 比率暴露为标准遥测项；调度器异常路径（newidle_balance 的翻译故障）命中率纳入核级健康画像；哨兵核部署（本案压测绑核避开 179 后，全部撞击集中于监控进程：风险收缩有效但可见度下降，需配合嫌疑核探针）。

### 7.2 微架构：把校验搬到数据流动处

L1D ECC 拦驻留翻转，拦不住"行内容正确但回读错"。建议：(1) load 返回总线端到端奇偶（fill-buffer→寄存器堆写端口，错则重放）：面积小、正中盲区；(2) store 通路对称处理（案 14 证明写侧同样交付错误且持久化）；(3) PTW 读出 PTE 奇偶校验：最坏情形（PTE 读错且值合法，导致静默错误映射）是 SDC 完全体，值得单独设防。

### 7.3 制造测试：从比特走向结构

撕裂移位在传统 March 算法下不可见（阵列没坏，选路错拍）。需要面向装载通路的定向向量：已知模式填充连续行 + 非对齐装载序列回读比对，覆盖全部字节相位组合。我们的结构化故障注入原型（gem5，P-D1 字节通道偏移注入器）已端到端复现 skew→Oops 链，并证明 bit-flip 模型对汉明距离为零的结构性错误表达能力为零。细节见姊妹篇（结构化故障注入）与 POSITIONAL_PARITY_RESEARCH.md（位置锚定校验设计：golden 零假阳性、bit_flip 1064/1064、skew 434/452=96% 检出）。

## 8. 结论

一台生产 ARM64 服务器，22 天，17 次崩溃，一个核。四族坏值形态（零塌缩、错相位撕裂、宽带翻转、同类指针替换）共享同一个解剖结构：内存正确、地址正确、运算正确、搬运出错。它们是同一边际时序条件在不同落点的失败模式谱，落在当代 RAS 体系与舰队测试范式的双重盲区里：ECC 只保护静止的数据，指令级测试只观测"输出即结果"的单元，数据在通路上的那几拍两边都不覆盖。

本工作的方法论价值在于证明这个盲区可观测：寄存器代数 + 内存真值对照所需的全部工具是 kdump 与 crash，任何运维方都可复现。科学价值在于给三个舰队级现象（SEVI 的错误偏移读取、PinDrop 的单核主导、DelayAVF 的多比特预言）补上机理。工程价值是一份可部署的清单：假故障按核统计、load 返回通路校验、结构化测试向量。

核数走向数百后，单核故障率随之线性放大；数据搬运通路的检测与校验应当成为默认配置。

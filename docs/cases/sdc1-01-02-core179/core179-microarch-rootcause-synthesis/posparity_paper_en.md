# Anchoring Invisible Faults: Positional Parity and the Three-Tier Defense against RAS-Escaping Silent Data Corruption

## Abstract

Can a defective core that slipped past manufacturing test and the hardware reliability machinery be seen once it reaches production? We answer with the forensics of a 192-core ARM64 production server: over twelve days, all 78 kernel anomalies landed on one core while hardware error logs stayed empty, and cross-layer analysis pinned the root cause to a zero-Hamming-distance failure of the load data-return path: a byte-lane skew. We prove this failure class is mathematically invisible to existing protections: lane-symmetric codes carry an identically zero syndrome under lockstep lane transposition, and pure XOR aggregation is invariant under every lane permutation. Positional anchoring is therefore the breaking of permutation symmetry, carried by a non-commutative mix. Our dual-weighted checker, implemented in a full-system simulator, detects 367/367 across all seven rotations of a real pointer chain and 1064/1064 bit-flips with zero false positives, at 25% bit overhead and gate-count logic roughly an order of magnitude below dual-modular redundancy. We then cost a three-tier defense: precursor consumption is nearly free (the kernel already paid for the signal; the cost is false-positive control), positional anchoring spends silicon at one high-vulnerability convergence point, and tiered testing spends time and factory economics. We adjudicate rather than evade what remains open: single-case extrapolation, a probabilistic adversarial surface, an unsynthesized silicon budget, and missing data on factory detection of mixed defect classes.

## 1. Introduction

Hyperscale operators keep reporting a defective core that passes manufacturing test, then intermittently produces wrong results without tripping any architectural reliability alert. Google named these "mercurial cores," a few per several thousand machines [2]; Meta's silent data corruption survey drew the same portrait: factory-qualified, striking after deployment, unannounced [1]. Once such a core has escaped, can anything see it? The reliability machinery is silent, the factory has waved it through, and system software "sees" it only after a run of unexplained crashes. Industrial analysis adds weight: test escapes cause roughly 5,000 DPM of chip replacements against an industry target of 100–500 DPM, SDC-causing escapees about 1,000 DPM; 88% of defective machines are found only after deployment, and the fail-stop assumption of large-scale distributed systems no longer holds [3].

Our study stands at the meeting of two scarce assets. The first is a complete single-core forensics: a 192-core ARM64 production server logged 78 kernel anomalies over twelve days, every one on logical core CPU 179, zero events on the other 191 cores, zero hardware error records throughout. Cross-layer forensics (register debris, ARMv8 architectural invariants, cache-set geometry) narrowed the root cause to the microarchitectural load data-return path and pinned the signature to a byte-lane skew: a routing error at zero Hamming distance from the correct value. The second is a full-system simulation loop for structured fault injection. The failure lies outside the bit-flip model's expressive space, so we extended gem5 with injection driven by data-path topology, replaying the failure under control and hanging the candidate detector on the same hook; the loop's relation to fleet-level SDC detection is discussed in Sections 4 and 5 [4, 5].

The paper asks three questions. Why can existing protections not see this failure? The answer is precise down to the syndrome: the check forms on the return path are lane-symmetric, such codes are blind in principle to the lockstep fault in which data and check bits transpose together, and pure XOR aggregation is invariant under every permutation. What design can see it? Positional anchoring: the lane position encoded into the check value, carried on a non-commutative mix. What does seeing cost? That question drags cost back into layered defense, so no tier gets argued into being free. Our contributions follow the same order: the cross-layer forensics; the two mathematical results whose contrapositive defines positional anchoring as symmetry breaking; a detection matrix (367/367 on pointer-chain data, 1064/1064 on bit-flips, zero false alarms); and a unified cost accounting across the three tiers.

## 2. Twelve Days of One Machine

### 2.1 Anomalies Clustered on One Core

The machine is a 4-socket, 48-core ARM64 production server (192 cores, 768 GB of memory). Over a continuous twelve-day window, kernel logs recorded 78 anomalous events: 73 rate-limited "spurious translation fault" warnings and 5 fatal kernel oopses. The counterintuitive property is the clustering: all 78 events, 100%, landed on logical core CPU 179 while the other 191 cores recorded zero. For scale: fleet defect density is a few cores per several thousand machines [2], and one core is 0.52% of this machine's compute.

The five fatal crashes rule out software locality on their own: they span multiple boot cycles and unrelated kernel subsystems (CFS scheduling, block-device writeback, user-space epoll) with no shared code path. More telling is the negative evidence: APEI/GHES/BERT hardware error records numbered zero across the entire window. The reliability machinery never saw this defect: either its failure granularity falls below every hooked detector's resolution, or it lands on a path no check covers. Either way, system software gets zero signal.

The crash scenes pin the location down. Four of the five crashes share one instruction chain: load `__per_cpu_offset[i]`, add it to a base to form a runqueue pointer, dereference. In all four the add was exact to the bit across 64 bits (the adder is innocent), yet the dereferenced pointer aimed at a non-canonical address, so the loaded value itself was bad. Comparing it against true memory bit by bit yielded the case's most important finding: the bad value and a head slot of the array stand in an exact byte-rotation relation: in the best-parsed instance, the bad value equals the head slot's value shifted right by one byte, bit for bit. Exhausting every single-byte bit-flip mask (8 bytes × 256 masks) produced this bad value zero times; among all 192 slots × 8 rotations (1,536 candidates), the unique hit was the head slot. Every bit arrived intact; what was wrong was the position. Section 3 develops the mathematics.

### 2.2 The Precursors Were Already Paid For

Forensics attributes the 73 warnings to transient misreads on the page table walker's readout path, but their temporal structure matters more. In the 08-14 boot cycle, the first spurious warning appeared roughly 29.0 hours after boot, the first fatal crash at about 31.7 hours; the precursor led the crash by roughly 2.6 hours. All 73 warnings preceded or accompanied a fatal crash.

The producing mechanism explains why these signals are nearly free. The openEuler kernel retries the translation in software on the exception path (re-issuing it through the `AT S1E1R` instruction); a successful retry marks the error "spurious," lets execution proceed, and emits a rate-limited warning. The kernel has already paid the entire cost of producing the signal (one retry plus one print), and no consumer exists to turn it into action. In 72 of 73 cases the target was a static, long-lived mapping unchanged for days after boot, excluding the benign "concurrent new-mapping race" explanation: the false-positive filter's evidence grows out of the signal itself.

That is what "the precursors were already paid for" means: the cost of detection was paid long ago; what is missing is whoever consumes it. Had the first signal triggered core-offline action for spurious translation faults clustered on one core, all five fatal crashes would in principle have been avoided; we infer this causal direction but did not execute it on this machine, and Section 7 preserves the boundary honestly. (The sixth dump on 08-26 updated the totals to 88 = 82 warnings + 6 fatal, still 100% on CPU 179, changing no directional conclusion.)

## 3. Why Existing Protections Cannot See It

### 3.1 What Zero Hamming Distance Means

Error checking answers the question "are these still those bits?": recompute the check over data and check bits, and compare. A byte-lane skew does not disturb the value of any bit. A 64-bit load return path is 8 parallel byte lanes: on each beat, lane i carries byte i. A transposition rewrites the correspondence: let σ be a permutation of the lane set (always non-identity here), with the byte on lane σ(i) delivered into lane i's position; every bit arrives intact, each segment merely settling in the wrong home. For any permutation-symmetric check that asks only "did any bit change?" and never "which lane did this bit come from?", this is a non-event. Nor do the check bits get off unharmed: they route adjacent to the data through the same multiplexer bank, so a wholesale lane-phase shift carries them along in lockstep: lane i receives lane σ(i)'s complete pair of data byte plus check bits. The check logic, in the wrong position, sees a perfectly legal local check.

### 3.2 The Blindness of Lane-Symmetric Codes

The check forms on real interfaces are mostly lane-symmetric. We call a linear block code lane-symmetric when every lane uses the same per-lane check function and the code is interleaved by lane: each lane's check bits are a function of that lane's data byte alone, all lanes sharing the function. Per-byte parity, byte-interleaved Hamming codes, and per-lane CRC-8 belong to this class; DDR4's per-byte write CRC [6] and bus-level per-byte parity have exactly this form. We now prove a lane-symmetric code is blind, in principle, to the lockstep fault in which data and check bits transpose together.

Let the codeword be c = (d‖e), where d_i and e_i are the data byte and its check bits on lane i (i = 0,…,7). Let σ be a non-identity permutation; the fault delivers lane σ(i)'s (d_{σ(i)}, e_{σ(i)}) into lane i. Write the syndrome as s(c), the product of the check matrix and the codeword, zero if and only if the codeword is legal; by lane symmetry it decomposes by lane: s(c) = (s_lane(d_0,e_0), …, s_lane(d_7,e_7)). Four lines:

1. The transposed codeword c′ satisfies, for each lane i, (d′_i, e′_i) = (d_{σ(i)}, e_{σ(i)}), an entire legal lane codeword carried over intact;
2. Hence the i-th syndrome component of c′ is s(c′)_i = s_lane(d_{σ(i)}, e_{σ(i)});
3. By lane symmetry, lane σ(i)'s original codeword is legal if and only if s_lane(d_{σ(i)}, e_{σ(i)}) = 0;
4. Hence s′ = P_σ·s (the per-lane components undergo the same permutation), and s′ = 0 if and only if s = 0.

A word that was legal remains legal after transposition: the check bits changed phase along with the data, and every lane presents a self-consistent data-plus-check pair. This is not a small miss probability; it is invisibility in principle.

The proposition's boundary must be drawn immediately. For a single monolithic SEC-DED code (one check matrix spanning all data bits, not decomposed by lane), a byte rotation is not an automorphism; the rotated syndrome is generally nonzero, and the blindness proposition fails. For this case, however, end-to-end ECC still fails, for two independent reasons. First, the check forms actually present on the load return path are precisely lane-symmetric: DDR4 per-byte CRC-8 [6] and per-byte bus parity, and the uniformly zero hardware error records are consistent with the L1 fill path carrying no ECC at all. Second, geometrically more fundamental: ECC's check points sit at the L2/memory boundary while the rotation happens downstream at the fill-buffer merge stage; the check point lies upstream of the fault point, so ECC never sees the rotated data. Lane symmetry merely makes rigorous that moving the check downstream would not help either.

### 3.3 A Deeper Symmetry: Permutation Invariance of XOR Aggregation

Since position is what went wrong, a natural idea is to encode position into the check value. Taking 8 lanes: assign each a distinct positional constant L_i (for instance L_i = (i+1)&7, i ∈ [0,7]; the set {1,2,3,4,5,6,7,0} is exactly 8 pairwise-distinct values, and L is a bijection from the 8 lanes into the 3-bit constant space), then mix them into an aggregate check word W. The handiest mixing operation is XOR, and the following theorem says this most natural route is mathematically doomed.

**Theorem (permutation invariance of XOR aggregation).** Let the aggregate word take the pure XOR-folded form W = ⊕_i (data[i] ⊕ (L_i ≪ 5)), where data[i] is lane i's byte, ⊕ denotes the iterated bitwise XOR, and ≪ is a left shift. Then for every lane permutation σ, W′ ⊕ W = 0.

**Proof.** W′ = W(σd) = ⊕_i (data[σ(i)] ⊕ (L_i ≪ 5)). The first equality merely writes out "the byte received on lane i comes from σ(i)." The positional constants hang on fixed lane indices and do not travel with the data, so ⊕_i (L_i ≪ 5) is the same sum before and after the permutation; and ⊕_i data[σ(i)] = ⊕_i data[i], because the XOR fold is insensitive to order: permuting a multiset does not change its XOR. Combining the two, W′ = (⊕_i data[i]) ⊕ (⊕_i (L_i ≪ 5)) = W, hence W′ ⊕ W = 0. ∎

The positional information has not vanished; under the permutation it redistributes and cancels term by term. The design corollary is direct: XOR-ing positional constants into a snapshot tag degenerates algebraically into ordinary parity; any commutative aggregate mixing the constants in via XOR inherits the blindness. To anchor position genuinely, the aggregation must be non-commutative, such as lane-weighted addition modulo 256: once lane order enters through the weights, a swap is noticed.

The mathematical essence of positional anchoring stands revealed: breaking permutation symmetry. Backward, this explains the invisibility: a lane-symmetric code's syndrome is invariant under lockstep transposition, pure XOR aggregation under any permutation; both are commutative checks. Forward, it dictates the detector's shape: the anchoring must pass through a non-commutative mix. As a contrast, the lockstep per-lane tag pushes determinism to its limit: writing popcount1(data[i]) for the parity of lane i's byte (set bits among eight, mod 2), the tag T_i = L_i ⊕ popcount1(data[i]) travels through the same multiplexer bank as the data, and the receiver recomputes against its local constants: recomputed and arriving tags agree if and only if L_i = L_{σ(i)}, which by L's bijectivity holds if and only if i = σ(i). Any non-identity permutation must mismatch on some lane; exhausting all 8! = 40,320 permutations, only the identity passes, wholly independent of data content.

## 4. A Three-Tier Defense

A complete defense cannot rest on a single principle: passive telemetry covers only the defect subclass that emits precursors, design-side detection acts only on future designs, and manufacturing test is the only tier that reaches back into deployed inventory. The three tiers are an orthogonal division of labor across defect class × lifecycle stage; each catches exactly the class the other two cannot.

### 4.1 Consuming the Free Signals

The first tier requires almost nothing to be invented, because the signal already exists: the 73 warnings of Section 2.2 are a ready-made detection source, fully paid for. What is missing is a consumer: aggregate spurious translation fault counts per CPU, compare against an inter-core baseline, trigger isolation past a threshold. The engineering shape has direct precedent: mcelog's cache error trigger offlines the affected cores by default when a CPU reports an excess of corrected cache errors, unless it is the last core running [7]. The Linux ecosystem has already accepted "excess correctable errors → preventive offlining"; its trigger merely hangs on cache error counts where this case demands translation fault counts.

The consumer's filtering evidence grows out of the signal itself. Spurious translation faults do have benign sources, most typically the race window in inter-processor page table establishment and TLB invalidation timing, on which healthy cores can trip under heavy fork/mmap load. But benign sources carry a fingerprint: race-class warnings should be randomly distributed across cores, target newly created mappings, and fail to satisfy "retry succeeds yet the warnings recur." This case's signal inverts all three: 100% single-core clustering, 72 of 73 warnings on static long-lived mappings, every retry succeeding. Google distilled the same idea at fleet scale into a two-stage pipeline: prosecute the suspect core with a core-clustered-crashes heuristic, then confirm with proactive testing; their field result is that more than seventy percent of prosecuted cores are defective, false-positive prosecutions under ten percent [3]. The stages convert the false-positive cost from killing a healthy core into testing one more: the first is free, only the second spends compute.

What this tier cannot catch must be said plainly. It covers only the subclass that produces architecturally visible signals. Page table walker readout misreads (this case's D3 class) fall inside, while pure data corruption (D1) has no precursor at all: at each fatal crash the only precursors were translation fault warnings, and not one bit of anomaly on the load return path was seen by any mechanism. The first tier is powerless against D1, which is the reason the second exists.

### 4.2 Giving the Datapath a Sense of Place

The second tier targets the precursor-less D1 class, and the theorem of Section 3.3 dictates the obligation: positional anchoring must pass through a non-commutative mix. The form we implemented and validated is a dual-weighted modulo-256 additive aggregate. Assign the 8 lanes two sets of pairwise-distinct, all-odd weights, w1_i = 2i+1 (that is, 1, 3, 5, 7, 9, 11, 13, 15) and w2_i = (2i+1) ⊕ 0x5A, and let the sender compute two 8-bit aggregates:

W1 = (Σ_i w1_i · (data[i] + 1)) mod 256, W2 = (Σ_i w2_i · (data[i] + 1)) mod 256,

with the receiver recomputing over the same weights and comparing. The three design choices each have a mathematical reason. The weights are odd, so any single-bit flip necessarily changes the aggregate (an odd number times a power of two is never zero mod 256), giving bit-flips a deterministic backstop. They are pairwise distinct, so lane order enters the check value: swapping any two lanes' payloads changes the sum, and non-commutativity carries the load. Each term adds one, so all-zero or all-identical-byte data still yields a position-dependent nonzero sum.

The labor divides cleanly. Bit-flips are detected deterministically by the odd-weight aggregate. Lane skew is detected by non-commutativity, but probabilistically; this follows from the sender-snapshot, receiver-recompute model, and Section 5.3 spells out the boundary. The upgrade path to deterministic detection exists (the lockstep design of Section 3.3's closing argument, whose only escape is the identity permutation) at the price of re-allocating wiring and pipeline stages, future silicon work. The coverage boundary deserves equal clarity: this case's failure signature has two components: byte-lane misalignment (a positional error) and stale-line replay (a provenance error). The weighted aggregate anchors position; for stale replay, where the value is correct but comes from the wrong slot, what is needed is a provenance tag: encoding the fill-buffer slot number into the check, the receiver verifying slot and data-source consistency. We did not implement that, and leave it as future work alongside the injector.

Deployment position is decided by vulnerability ranking. The architectural vulnerability factor (AVF) criterion is that structures whose outputs flow directly into architectural registers are the most vulnerable; their faults need no long latency to become program-visible [8]. The fill-buffer merge stage and the load return multiplexer are exactly such structures, and this case supplies a rare empirical anchor: the bad value became a pointer via a single add, and the very next instruction dereferenced it into a crash: from data to execution-piercing address within two instructions, on four of the five fatal crashes. Pointer contamination also amplifies: the blast surface of a downstream dereference far exceeds one data word. The deployment point is therefore the single convergence point of the load return; faults in low-vulnerability structures are mostly masked by idle bits, and uniform deployment is unaffordable in timing and area budget.

### 4.3 From Fortuitous Hits to Deterministic Detection

The third tier answers an upstream question: why not stop the defective chip at manufacturing test instead of intercepting it after it ships? The obstacle is the expressiveness gap between traditional fault models and this defect class. The ATPG lineage takes bits or nodes as its fault unit: stuck-at, transition, and small-delay faults are defined on the value or timing of some point, whereas byte-lane skew is a phase re-routing among lanes, and Section 2.1's exhaustion has already shown it lies outside the image of any bit-flip model. Scan test has a second mismatch: it runs in fixed test modes, while stale-line replay depends on fill-buffer queue state and cross-cache-set geometry, functional microarchitectural states scan modes cannot construct. Existing tests at best hit this class fortuitously; they never detect it deterministically.

Physically aware exhaustive region testing (PEPR) offers a route around fault models: since modeling specific defect behaviors is infeasible, do not model them: partition the layout into deliberately overlapping physical regions, exhaustively apply all input combinations to each region's subcircuits, and the detection guarantee depends on no defect model [9]. On industrial data from a 14 nm process and tens of thousands of defective chips, traditional metrics caught timing-agnostic combinational defects mostly by luck (stuck-at coverage of just 4.8% under strict evaluation), where PEPR achieved 100% alignment. This case's forensics agree in direction: the bit-flip exhaustion had zero hits on the bad value.

The resulting three-stage division of labor: PEPR-class exhaustive test at the factory intercepts purely combinational defects (the byte-rotation component is exactly that); structural scan in the field (Intel IFS-class: scan chain test, array self-test, structured functional tests reusing manufacturing screening suites) intercepts escaped permanent defects and aging drift, the per-test cost already sub-second, paid in the tested core's threads being effectively offline [10]; functional software self-test in the field catches the state-dependent class: scan modes cannot construct queue states, only real instruction streams can, which is precisely SBST's territory. SBST's infrastructure feasibility is proven at fleet scale: Google's SiliFuzz tests every core repeatedly with snapshot programs under a hundred bytes each, microsecond-scale executions, a corpus of roughly half a million entries [4]; Meta's fleetscanner reaches 93% coverage of known defect families and contributes 23% unique coverage [5]. Our incremental claim targets corpus structure: both corpora center on computational-path verification: SiliFuzz's defect-discovery patterns are headed by incorrect results of integer, floating-point, and vector instructions; fleetscanner describes its corpus as verifying computational correctness. Neither records an explicit share for the load-value-immediately-becomes-dereference-address chain, yet four of this case's five fatal crashes followed exactly that chain. A pointer-dereference-grade probe is therefore an architecturally targeted extension of existing SBST corpora, not a reinvention.

The three tiers keep very different ledgers: the first spends policy and availability, the second silicon area and timing, the third test time and factory economics. Section 6 prices each one.

## 5. Prototype and Validation

### 5.1 The Experimental Loop

Validating positional anchoring requires a loop that can both inject faults and host detectors. We built it on the store-to-load forwarding path of the out-of-order core's (O3CPU) load/store unit in the gem5 full-system simulator. The fault side is a structured injector applying byte-lane rotations, all-zero delivery, or bit-flips to forwarded data at configurable probabilities. The detector side is the positional parity checker: the instant forwarded data is copied to the load destination it snapshots a tag over the original data before injection, then recomputes the aggregates after injection and compares. The two hang on the same hook, one ahead of the other, exactly the silicon-side timing of a bus sender tagging and a receiver checking; with the checker detached, both call sites short-circuit, leaving existing experiments untouched.

The workload probe mirrors the crash scene. The production failure chain is load `__per_cpu_offset[i]`, add base, dereference; the probe maintains a 256-entry pointer array as its user-space counterpart and repeatedly stores to and re-reads the target slot (the very slot the 15:58 crash loaded) so that the checked load traverses the forwarding path, then dereferences the re-read value as a pointer. Any structural corruption pushes the value toward a non-canonical address, the same chain as the kernel oops. As a control, an adversarial data probe repeatedly forwards a value whose bytes all share the same parity, precisely the data that blinds every parity-class check.

Second, the 18 escapes. Of the lane-skew arm's 452 injections, 18 went undetected; all 18 are low-entropy startup words: seventeen from the dynamic loader's mapping arrays, one from the exit path's printf buffer. The escape rate is thereby a function of data entropy: high-entropy pointers (the real shape of this case's failure chain) show zero measured escapes; single-nonzero-byte constants (segment bases such as 0x400000) escape on the order of one percent, concentrated on even rotation amounts; and an adversary who knows the weight vector can construct input lying exactly on the escape hyperplanes: of the 40,319 non-identity lane permutations, 17 fool both aggregates simultaneously. This boundary must be written plainly: under the snapshot model, positional anchoring detects random defects with high probability and an informed adversary only probabilistically, not with cryptographic determinism. As a defense line it defends against defects (defects do not know the weights), not attackers.

### 5.3 Snapshot versus Lockstep

The probabilistic boundary originates in an implementation trade-off. Deterministic detection (the identity permutation as the sole escape, independent of data content) belongs to the lockstep family proven at the end of Section 3.3: the tag travels through the same multiplexer bank as the data, so a transposition necessarily drags the tag out of place. Our prototype adopted the sender-snapshot model instead: the tag fixed before injection and recomputed-and-compared after. Its engineering cost is small (no rewiring of the forwarding path); its price is probabilistic on the adversarial surface. The upgrade path is clear (a lockstep tag flowing with the data, combined with Section 3.3's bijective constants, restores determinism), but it demands re-allocating pipeline stages and wiring on the silicon side, beyond what this study can validate in a simulator, and is honestly filed under future work. The detection semantics are settled: deterministic backstop for bit-flips, high-probability detection of the lane-skew class, zero measured false positives, configurable fail-fast. The next section prices them.

## 6. The Cost of Each Tier

Between "principle holds" and "worth deploying" lies a ledger, and the three tiers spend under different headings: engineering effort and availability for the first, silicon area, power, and timing for the second, test time and factory economics for the third. The premises, stated honestly: this study has no RTL synthesis results and no vendor factory-cost data; the numbers come from verified arithmetic facts (bit overhead) and analytically derived order-of-magnitude estimates or literature anchors (gate counts, the DPM gap), assumptions traveling with every newly done conversion.

### 6.1 Availability and False Positives

The first tier's development cost is the easiest to compute: it is nearly all software, and every mechanism part exists: the signal source (rate-limited warnings), the offlining mechanism (sysfs hot-offline), the policy precedent (the mcelog trigger). What needs writing is a single consumer that aggregates spurious translation fault counts per core, maintains the inter-core baseline, and triggers isolation past a threshold: one reproducible script plus one daemon, not a kernel subsystem. The runtime cost is near zero: the kernel has paid the cost of producing the signal, and the consuming side is log aggregation. Against the proactive-testing route (fleetscanner's cumulative investment of about four billion fleet-seconds of test time [5]), the marginal cost of passive telemetry is negligible. The contrast draws the complementarity boundary: proactive testing covers precursor-less pure data corruption but at considerable compute; passive telemetry is nearly free but sees only the defect class that cries out.

A true-positive offlining costs a one-time capacity loss: one core is 0.52% of this machine's 192. The counterfactual cost of inaction is out of proportion: the twelve days brought five fatal crashes, each a full-machine reboot with service interruption; and at fleet scale, folding in an escape rate of roughly one SDC-producing core per thousand [3], a ten-thousand-machine cluster should expect problem machines in the tens. These conversions deliver structure, not unit prices: downtime costs vary wildly by business, and we will not invent numbers.

The fourth account matters most: the expected cost of false positives. With filter false-positive rate p and n accused cores, the expected wrongly-offlined capacity is p·n. Taking CCKC's measured under-ten-percent false-positive rate as the engineering upper-bound anchor [3]: in the worst case, a 192-core machine with all cores implicated could see wrongly-offlined capacity reach about ten percent, nineteen cores. This bound explains two hard rules of policy design. First, no single-signal offlining: this case's triple filter (static-mapping targets, single-core clustering, successful retries) excludes benign sources before the trigger fires. Second, two-stage confirmation: mark first, re-verify with proactive testing, then offline, converting the false-positive cost from permanently losing a healthy core to testing one more. What must be acknowledged simultaneously: threshold calibration for general deployment requires multi-model baseline collection of benign background warning rates, which this single case cannot supply; the item returns in Section 7. The first tier's ledger is handsome not because detection is free but because the signal was paid for long ago; all the remaining cost goes into one decision: how fast to believe it.

### 6.2 The Silicon Budget

The second tier's account splits into bits, logic, timing, and energy.

Bits first. The dual aggregate carries 8 bits each, so every 64-bit payload carries 16 check bits, a 25% bit overhead, in the same band as L1 data cache ECC's. What redeems it is scope: the vulnerability argument confines deployment to the single load return convergence structure, so the 25% acts on one path, not the whole chip. The check value's storage depends on the implementation model, the snapshot model needs a small tag store indexed by in-flight forwards, where dual-modular redundancy hangs a 64-bit shadow register on every one.

Logic and depth next. Each aggregate is a weighted multiply-accumulate tree: a constant times a byte expands into 1 to 4 partial products (dictated by the binary bitmap of weights 1 through 15), the eight lanes feed roughly 20 to 28 partial products into the tree, and six or seven carry-save stages plus a roughly four-stage final carry-propagate adder produce the 8-bit sum; the two trees share some structure, and with a 16-bit equality comparator the total is roughly 1,000 to 2,000 equivalent gates at 10 to 15 FO4. These are analytically derived magnitudes, not synthesis results, but two independent credibility supports exist: the byte-lane multiplexing network it parallels is itself on the order of 6 to 12 FO4 and several thousand gates, so check logic of comparable depth and an order of magnitude smaller area adds no critical path when compared on the next cycle; and the industrial precedent, DDR4's per-byte CRC-8 achieves seamless back-to-back transmission inside DRAM with about 700 XOR gates at 6 levels of depth [11]. Energy, estimated from an empirical activity-factor assumption, adds 5% to 10% per forward event, the weakest of the four accounts, with no power simulation behind it.

Then the contrast anchors. SEC-DED sits in the same 12.5% bit-overhead band as the single-aggregate variant but is blind in principle to lockstep transposition, its check point upstream of the fault point; dual-modular redundancy detects everything, at the price of duplicating the entire path plus a 64-bit comparator, roughly five to ten times the area, industry's verdict on the redundancy route is that it brings large energy, execution time, and area overhead to commodity-grade computing hardware [3]. Positional anchoring sits between: twice the bit cost of ECC for a fault class ECC cannot see in principle; an order of magnitude cheaper than redundancy, giving up generality. Between bit budget and detection semantics lies a full Pareto spectrum; Table 2 gives its principal graduations.

Table 2: The cost-detection spectrum of check schemes (lane-skew escape rates are exact values under uniformly random data)

| Scheme | Check bits / 64 b | Bit overhead | Bit-flip detection | Rotation escape (odd k / k=2,6 / k=4) |
|---|---|---|---|---|
| Single aggregate (mod 256) | 8 | 12.5% | Deterministic | 2⁻⁷ / 2⁻⁶ / 2⁻⁵ |
| Dual weighted mod-256 (this work) | 16 | 25% | Deterministic | 2⁻¹² / 2⁻¹⁰ / 2⁻⁵ |
| Dual weighted mod-251 + generic second vector | 16 | 25% | Deterministic | 2⁻¹⁵·⁹ / 2⁻¹⁵·⁹ / 2⁻¹⁵·⁹ |
| Lockstep per-lane tag | 24 | 37.5% | Per-lane parity | 0 (deterministic; identity the sole escape) |
| Dual-modular redundancy (contrast) | 64 + comparator | ~100% | Arbitrary errors | Arbitrary errors |

Three paths read off this table. With the budget capped at 16 bits, the prime-modulus variant is the optimum of detection semantics: modulus 251 is a field, the two linear constraints genuinely independent, the full-domain escape dropping to about 2⁻¹⁶, at the cost of one conditional subtraction per partial sum and a twenty-to-thirty percent gate increase. With 24 bits and wiring changes acceptable, the lockstep tag promotes rotation detection to deterministic, at the price of re-allocating the forwarding path's pipeline. The mod-256 scheme implemented here is not the spectrum's optimum; its value lies elsewhere: reduction-by-truncation is free (binary addition naturally overflows modulo, no compare-and-subtract), and there is the complete measured matrix of Section 5. One counterintuitive lesson: the implemented weight vector degenerates badly under k = 4 rotations (escape 2⁻⁵), and the root cause is not the modulus, the two weight vectors impose mutually opposite constraints under that rotation, and a prime modulus would degenerate just the same; the fix requires the second vector to be generic with respect to the first, a property of vectors, not moduli. Do not look at the modulus alone; look at the weight structure. Finally, the unpaid bills: RTL synthesis, timing closure, and power simulation, none done; the tag store's port count and pipeline-stage allocation await a concrete microarchitectural design. This ledger can be computed only to order of magnitude, the magnitudes are credible, the precise numbers await the vendor.

### 6.3 Time and Manufacturing Economics

The third tier's dominant cost is time, and exhaustive testing's time account is famously ugly. PEPR's vector count on a 14 nm single core is 523,863, against 176 vectors for traditional stuck-at fault testing, a factor of about 2,976; ATPG runtime swells from 0.5 h to 9,568.7 h [9]. The bill remains payable because voxel partitioning presses the input count of each exhaustively tested subcircuit down to three to twelve, region partitioning is the precondition that moves exponential complexity off the whole chip and into physical neighborhoods. Even so, factory time economics keeps PEPR-class methods outside the factory gate: minutes per chip is the industry's impracticality line, and one-to-two-order-of-magnitude test-time increases are routine [3]. Recent analyses therefore place physically aware exhaustive testing in the field, field economics tolerates far longer test times.

The availability account of field scan is concrete. Scan-chain field test costs under 200 ms per test, during which the tested core's threads are effectively offline [10]. Assuming a cadence of one round per core per day (an assumed cadence, not a measured policy), a 192-core machine's cumulative offline time for a full sweep is 192 × 200 ms ≈ 38 s/day, about 0.044% of availability. A sub-second per-test cost fits inside a running system; the cost's shape is not volume but the window: each scan must migrate latency-sensitive tasks and interrupts off the tested core. Array self-test (5 ms scale) and batched structured functional tests (one to two hundred ms per batch) provide finer gradations [10].

The functional software self-test takes two shapes. Out-of-band is thorough but slow: fleetscanner executes in maintenance windows and needed five to six months to reach seventy percent equivalent fleet coverage, cumulatively about four billion fleet-seconds [5]; online is cheap but co-located with production: ripple inserts tests at millisecond-scale intervals and reaches equivalent coverage in fifteen days [5]. A single snapshot corpus entry costs microseconds in either shape [4]; inserting the pointer-dereference probe is a corpus increment, not an infrastructure cost.

The last account is DPM economics, the least computable. The roughly ten-fold gap between the observed escape rate of about 5,000 DPM and the industry target of 100–500 DPM [3] is not a technical limit but an equilibrium under factory time constraints, test depth stops where one more notch of factory time no longer pays. Bringing a new defect class into screening requires a marginal benefit-cost model (ATE time pricing, DPM by defect class, RMA process costs) data held by vendors and unavailable to this study. What we can argue is the direction: intercepting a defective chip on the line costs minutes, while remediation after it escapes (crashes, forensics, isolation, returns) costs days at every link, and the links compound [3]. The direction supports recomputing the account, but a recomputed account does not necessarily support inclusion; that honest sentence is left for Section 7.

### 6.4 The Three Ledgers Compared

Table 3: Cost comparison of the three defense tiers

| Tier | Incremental cost form | Magnitude | Detection semantics purchased | Residual risk | Number credibility |
|---|---|---|---|---|---|
| Precursor consumption | Software engineering + offline capacity | Development: one policy layer; true positive: 0.52%/core; false positives: filter-quality-dependent | Core-level isolation of precursor-emitting defects (D3 class) | Pure data corruption has no precursor; thresholds uncalibrated | Development and capacity: empirically obtainable; false-positive rate: literature anchor |
| Positional parity check | Silicon area / timing / power | 25% bit overhead (arithmetic fact); ~1k gates / 10–15 FO4 / 5–10% energy | High-probability detection of precursor-less structural faults (D1 class) + deterministic bit-flip detection | Probabilistic on the adversarial surface; stale replay not covered; new designs only | Bit overhead: exact; gates/depth/energy: analytic magnitudes |
| Tiered testing | Test time + factory economics | Factory: thousand-fold vector inflation, blocked by the line; field scan: ~0.04% availability (assumed cadence); SBST: microseconds per entry | Deterministic exhaustion of the combinational class + functional detection of the state class | Mixed class (combinational + state) factory detection: no data | Durations: measured in the literature; economic model: unavailable |

The complementarity is nearly architectural. The first tier is nearly free but sees only the defect class that cries out; the second buys detection semantics for precursor-less faults, pays in silicon, and touches only new designs; the third covers the most ground (it even reaches back into deployed inventory) but pays in time and factory economics. No single tier suffices, and once stacked, each tier's marginal cost sits far below the remediation cost of one fleet-level silent data corruption event, which is exactly why layered defense also stands on economics.

## 7. Honest Boundaries

A paper that argues for deploying a defense owes the boundaries of its claims the same clarity as the claims themselves. Five boundaries follow, not footnotes but the evidence state that deployment decisions must face.

The first concerns the statistical basis of extrapolation. The forensic facts are hard: the byte-rotation relation between the bad value and its source slot is exhaustively verified as producible by no bit-flip; the single-core clustering and zero hardware records are backed by raw logs. But from one machine and one microarchitecture, one cannot estimate what fraction of the escaping-defect population this class occupies, this case is the complete anatomy of one core, not an epidemiological survey. Recent industrial analysis is sober on precisely this point: the effectiveness of any new detection technology requires new industrial experiments to calibrate, and those experiments must overcome the flaws and pitfalls of past industrial test experiments [3]. Until such data exists, what we advocate is that directed defense of high-vulnerability convergence points deserves a place in design evaluation, not that it should become a general design rule.

The second is the adversarial surface. Section 5.2 has spelled it out: under the snapshot model, positional anchoring detects random defects with high probability and an adversary who knows the weight vector only probabilistically, of the 40,319 non-identity lane permutations, 17 lie on escape hyperplanes that fool both aggregates simultaneously. We advocate this check against defects (defects do not know the weights); we do not advocate it against attackers. The upgrade path to deterministic detection (the lockstep tag flowing with the data) is proven in mathematics and unimplemented in engineering.

The third is the evidence grade of the silicon cost. The 25% bit overhead is an arithmetic fact, but the gate count, timing depth, and energy are analytically derived magnitudes, unsynthesized, untimed, unsimulated for power. The two credibility supports of Section 6.2 (depth on the same order as the checked object; the DDR4 CRC-8 precedent) support the claim that this magnitude is feasible, not that this design closes timing. Precise numbers await vendor RTL evaluation.

The fourth is the most substantive: the complete form of this case's defect is a mixed class (combinational (byte rotation) plus state (stale-line replay)) and the published literature contains no data on manufacturing-test detection rates for this mixed class. Physically aware exhaustive testing has industrial evidence for 100% detection of purely combinational defects [9], but its extension to timing- and sequence-dependent defects is unpublished, not because our search was insufficient, but because the extension itself is unpublished [3, 9]. Within the three-tier defense, the factory tier's coverage of the stale-replay half rests on structural compensation from field functional test and runtime detection, not on proven interception.

The fifth returns to the economics. General thresholds for precursor consumption require multi-model, multi-workload baseline rates of benign background warnings, which this study cannot supply; the marginal benefit-cost model for screening requires ATE time pricing, DPM broken out by class, and RMA process costs, all in vendors' hands. We have argued that this account deserves recomputing; we have not argued that recomputing it necessarily favors inclusion.

## 8. Conclusion

This paper started from one concrete event (twelve days on one production server, 78 anomalies, one core) and decomposed the abstract proposition of silent data corruption that escapes the reliability machinery down to a level where things can be done. The three questions of the introduction can now be answered in turn.

Why was it invisible? Because of symmetry. A byte-lane skew changes no bit's value, and every check the existing machinery performs (the syndrome of a lane-symmetric code, the XOR-folded aggregate) is a commutative-over-permutation operation that remains self-consistent after transposition. The blindness is not an implementation flaw but a mathematical structure: the check logic and the fault share the same symmetry group.

What can see it? Anything that breaks the symmetry. Consume the precursor signals the kernel has already paid for, they precede the crashes in time and nail the single core in space. Deploy a non-commutative weighted aggregate at the load return convergence point, encoding lane order into the check value, measured to capture every rotation of a real pointer chain. Replace the dependence on defect models with physically aware exhaustive test, so the detection guarantee no longer rests on fortuitous hits. The three tiers share one name: making silent faults explicit.

And the cost? Three complementary ledgers. Precursor consumption is nearly free because the signal was paid for long ago; all its cost lies in false-positive control; positional anchoring buys detection semantics for precursor-less structural faults at a quarter bit overhead plus gate-count logic, touching only new designs; tiered testing pays in time and factory economics for the widest coverage, deployed inventory included. No tier suffices alone, and stacked, each tier's marginal cost sits far below the remediation of one fleet-level event.

The larger picture: with escape rates an order of magnitude beyond the industrial target and the fail-stop assumption already broken [3], making faults explicit is no longer one preference among fault-tolerance philosophies but an engineering necessity. The three tiers are projections of one principle onto three ledgers, the software tier pays in policy, the silicon tier in area, the test tier in time. And the pun in anchoring is the shortest summary of the whole paper: invisible faults are invisible because nothing pins them in place; what positional anchoring does is give every byte a position to be pinned to.

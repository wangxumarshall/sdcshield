## 1. 背景与故障概况

一台长江计算 R240K V2（HIP08 / 鲲鹏 920，4×48=192 核，768 GB，BIOS 7.48，内核 6.6.0-145.3.23.154.oe2403sp3.aarch64）于 2026-08-14 至 08-25 间发生 5 次内核崩溃。跨五开机全量法证显示：

- 78 次内核异常事件（73 次虚假翻译错误告警 + 5 次致命 Oops），100% 集中于逻辑 CPU 179，其余 191 核零事件。【实锤】
- 硬件错误日志（APEI/GHES）全程零记录，缺陷完全绕过所有已挂接的架构级 RAS 检测器。【实锤】
- 五次崩溃跨越互不相关的内核子系统（CFS 负载均衡、块回写、kblockd、swapper、用户态 epoll），排除局部软件缺陷。【强推】

收敛根因：CPU 179 私有的装载-数据返回通路（fill-buffer/重放合并 ≈ L1D 读出组装级）存在单核私有时序边界缺陷，在特定发射相位与电压裕量组合下交付错误数据字；同一故障族波及硬件页表走查器（PTW）读出数据通路。失效粒度低于全部架构化 RAS 检测器。【实锤 至 假设 逐级收敛，最终物理确认需 RTL/DFT】


## 2. 核心证据摘要（质询依据）

### 2.1 D1：装载数据返回通路【实锤】

错误装载值与内存真值逐位对照（write-once 静态数组，启动后永不改变）：

| 崩溃 | 装载目标 | 内存真值 | 寄存器收到 | 判定 |
|---|---|---|---|---|
| 08-25 15:58 | `__per_cpu_offset[146]` | `ffffcc879ed92000` | `00ffffcc879da2e0` | **= `slot[0]`(=`ffffcc879da2e000`) 右移 1 字节，逐位精确** |
| 08-25 15:42 | `__per_cpu_offset[176]` | `ffffda55e61ce000` | `0000000000000000` | 全零交付 |
| 08-14 | `__per_cpu_offset[176]` | `ffffd937172de000` | `d93715ba0000ffff` | 与 `slot[0]` 循环左移 16 位形状仅差 1 字节【强推】 |
| 08-17 | `__per_cpu_offset[175]` | （转储不完整） | `00ffffa827b20fe0` | 与案例 5 同族【强推】 |

- 坏值唯一命中数组头部槽位（slot 0/1）：192 槽位 × 8 种字节旋转 = 1536 候选中唯一命中，概率 ≈ 2⁻⁵⁸，非随机噪声。【实锤】
- 穷举证伪位翻转：坏值无法由目标槽位任何单字节 bit-flip 产生 → 结构性字节重路由（byte-lane re-route），非位翻转。【实锤】
- 跨 set 几何裁决：L1D 组相联几何下，坏值源（slot[0] @ set 87）与装载目标（slot[146] @ set 105）不同 set → 排除 L1D 阵列 way/列选通错，指向 fill-buffer 合并级。【实锤】
- 物理诠释：fill-buffer/LQ 中最旧条目（数组头部启动时首次访问留下）被以错误字节通道相位回放给跨 set 的另一装载。

### 2.2 D2：地址呈现通路【实锤-弱】

ARMv8 对翻译错误的不变量要求 `FAR_EL1[63:0]` 精确等于 MMU 实际翻译地址。利用此不变量对照：

| 崩溃 | 架构计算地址（寄存器） | 内核打印 FAR | 判定 |
|---|---|---|---|
| 08-14 | `d936bc836a4a97df` | `0036bc836a4a97df` | **D2 清晰可见**（MSB d9→00） |
| 08-24 | `553c521da2e9b99f` | `003c521da2e9b99f` | **D2 清晰可见**（MSB 55→00） |
| 08-25 15:42 | `ffffa5aa9b5a97e0` | `ffffa5aa9b5a97e0` | 无 D2 |
| 08-17 / 15:58 | MSB 恰为 0x00 | 同左 | D2 不可区分 |

诚实修正：D2 确凿证据为 5 例中 2 例；另 2 例 D1 产出的坏值 MSB 恰为 0，使 D2 不可观察。D2 指向 AGU 计算结果→MMU 翻译前，地址 byte7（MSB）被某通路强制为 0。

### 2.3 D3：PTW 读出通路【实锤】

73 次虚假翻译错误（`is_spurious_el1_translation_fault()` 判定，`AT S1E1R` 重试成功）：

- 72/73 针对静态线性映射地址（`.data`/slab/vmemmap，boot 时建立、数日未变），不满足主线"并发新建映射竞态"前提。【实锤】
- 100% 单点 CPU 179，与竞态模型的跨 CPU 分布不相容。【实锤】
- ESR 形状：70 例 `0x96000044` / 3 例 `0x96000004`（FSC=TF-L0）；bit6（Overlay，v8.2 应 RES0）恒置 1，成因未定。【实锤】

### 2.4 RAS 负证据【实锤】

五份 dmesg 中 APEI/GHES/BERT 仅出现启动注册行，零条硬件错误记录。缺陷粒度低于全部已挂接检测器，或相应数据通路（fill-buffer 合并、PTW 读出返回）未被 ECC/奇偶校验覆盖。

### 2.5 单/多缺陷裁决边界【假设，需供应商裁决】

D1/D2/D3 共址于 CPU 179、跨开机稳定共现。它们可能是同一物理缺陷的三种投影（共享数据返回/路由结构），也可能是三个独立缺陷。此裁决在软件层不可解，必须由 RTL/DFT 仿真或测试决定。本建议书第 4.4 节给出裁决实验。


## 3. 质询项

> 每项给出：问题、证据支撑、期望答复形式。按优先级排列。

### Q1【P0】fill-buffer 合并/选路逻辑的 ECC 覆盖边界

- 问题：TSV110 L1D 数据阵列的 ECC/奇偶校验，其覆盖边界是否包含读出示阵列后的 fill-buffer 合并逻辑与装载返回输出多路复用器？若否，该级当前无任何保护？
- 证据：D1 坏值=陈旧行字节相位错位（汉明距离 0），ECC 无法捕获"重排"类损坏；但该级若有单字节翻转保护，其覆盖边界需明确。
- 期望答复：RTL 审查结论 / ECC 覆盖图（哪些级有校验、哪些没有）；该级是否可附加校验。

### Q2【P0】PTW 读出通路是否存在 ECC

- 问题：硬件页表走查器（PTW）读出页表描述符的通路是否有 ECC/奇偶校验？PTW 阵列本身是否受 ECC 保护？
- 证据：D3 73 例瞬态走查失败全部静默（RAS 零记录）；若 PTW 读出有 ECC，部分瞬态错误应被捕获或纠正，静默暗示该级无 ECC 或 ECC 不覆盖读出返回通路。
- 期望答复：PTW 阵列与读出返回通路的 ECC 配置确认。

### Q3【P1】地址呈现 byte7 锁存的路径与可测性

- 问题：AGU→MMU 地址呈现锁存器中 byte7（MSB）的实现路径，是否存在已知的时序敏感边界？该位是否可施加 transition-delay 测试？
- 证据：D2 两例（08-14/08-24）地址 MSB 在途清零，由 FAR_EL1 不变量锁定损坏在 AGU→MMU 传递级。
- 期望答复：RTL 审查该位路径；确认该位在 at-speed 测试下的可达性。

### Q4【P0，裁决性】单/多缺陷裁决实验请求

- 问题：请对 CPU 179 die 执行三通路分别的 LBIST / scan-at-speed 测试：
  1. fill-buffer 合并/字节通道选择级（对应 D1）；
  2. 地址呈现 byte7 锁存（对应 D2）；
  3. PTW 读出返回通路（对应 D3）。
- 目的：裁决"单缺陷三投影 vs 多缺陷共址"。若三者同点失效 → 支持单缺陷，修复策略与 RMA 范围随之确定；否则支持多缺陷共址。
- 期望答复：三通路测试结果、失效模式分析、结论。

### Q5【P1】ESR bit6（Overlay）恒置 1 的成因

- 问题：HIP08 同步数据异常 ESR bit6（Overlay）在 ARMv8.2 应为 RES0，但跨五开机恒置 1（70 例 `0x96000044`）。请确认 ESR 编码生成逻辑。
- 证据：诊断报告 §9.5；73 例 spurious 中 70 例 bit6 恒 1。
- 期望答复：ESR 编码实现说明；该位是否为 HIP08 特有实现行为。

### Q6【P2】内核 per-cpu 模板窗口页表页异常状态的成因

- 问题：两例转储中内核 per-cpu 模板窗口的页表页呈"表描述符 + 整页零"状态（跨开机一致）。请确认该窗口在块映射下的惰性分配是否正常。
- 证据：诊断报告 §9.4。
- 期望答复：页表分配/填充行为说明（确认正常 or 异常）。

### Q7【P1】电压/频率管理与触发条件

- 问题：TSV110 的 AVS（自适应电压调节）机制与电压余量管理策略；是否支持单核独立的电压/频率控制？故障触发频率在 −30 mV 下显著上升，请确认电压与缺陷的相关性。
- 证据：method1/2/3 用户态复现（−30 mV 触发）；D1 为相位 × 电压组合下的时序缺陷。
- 期望答复：电压管理策略；单核电压/频率控制能力；缺陷的电压敏感性评估。

### Q8【P2】固件/批次信息确认

- 问题：确认该 die 的微码 revision（当前全核为 0）、晶圆批次信息，用于批次性缺陷分布分析。
- 证据：诊断报告 §4。
- 期望答复：微码版本、批次信息、同批次抽检建议。


## 4. 建议执行的 DFT / 测试向量

> 以下向量基于五转储比特级签名构造，供海思测试团队落地。

### 4.1 D1：fill-buffer 合并级 at-speed scan 向量【P0】

- 签名：装载中部槽位（如 `__per_cpu_offset[146]`）却返回数组头部槽位（`slot[0]`）右移 1 字节的形态（`0x00ffffcc879da2e0 = slot[0] >> 8`）。
- 构造要点：必须复现"首次访问数组头部 → 跨 set 重访另一槽位"的访问序列，以激活最陈旧 fill-buffer 条目被错误字节通道回放的条件。
- 覆盖对象：装载返回 mux 的 8 字节通道相位控制逻辑；跨 set 陈旧头部重放路径。
- 验收：向量能否稳定产生 rol1/rol6 形态坏值。

### 4.2 D2：地址 byte7 transition-delay 测试【P1】

- 签名：地址 MSB（byte7）在 AGU→MMU 途中被强制为 0（`d9…→00…`、`55…→00…`）。
- 向量：对地址呈现锁存器 byte7 施加 rising/falling transition-delay 故障向量，筛查路径延迟边界。
- 验收：能否复现 byte7 清零的 D2 签名。

### 4.3 D3：PTW 读出通路 scan + ECC 对照【P1】

- 签名：PTW 读取 PTE 描述符瞬态错误，`AT S1E1R` 重试成功（spurious）。
- 向量：PTW 读出返回通路 scan 覆盖；ECC on/off 对照实验（若 PTW 有 ECC，预期 ECC-on 时 spurious≈0；本机 gem5 仿真已给出同向预期）。
- 验收：spurious 率随 ECC 配置的变化。

### 4.4 三通路 LBIST 裁决实验【P0，裁决性】

- 对 fill-buffer 合并级、地址 byte7 锁存、PTW 读出通路分别施加 LBIST。
- 判定：三者同点失效 → 单缺陷三投影；否则 → 多缺陷共址。这是本次质询的核心交付。

### 4.5 Vmin 筛查向量【P1】

- 将以下微架构靶向负载纳入量产 Vmin 筛查：
  - `movbe` / `mrn_rmw` 序列 + −30 mV（method1/2）；
  - Cholesky 分解（method3，尾数漂移敏感）；
  - `__per_cpu_offset` 装载-使用-作指针序列（本报告新增内核态可触发向量）。
- 注意：须配高可信黄金校验（checksum/参考结果）以避免误判；测试时间成本需与覆盖率权衡。

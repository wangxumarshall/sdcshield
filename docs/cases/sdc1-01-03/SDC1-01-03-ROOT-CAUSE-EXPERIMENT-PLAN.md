# SDC1-01-03 突然复位根因定位实验设计

配套文档：`SDC1-01-03-SUDDEN-RESET-PRELIMINARY-REPORT.md`（初步取证报告，证据固化于 `evidence/`）
编制：2026-10-09。目标：**用可控实验把初步报告中【假设】级的 R4/R5 裁别到【实锤】级**。

## 0. 待裁别的假设集合（源自初步报告 §7）

| 编号 | 假设 | 现状 |
|---|---|---|
| R4-a | 电源 di/dt 瞬态：屏障释放/满发窗口的微秒级轨塌陷 → brown-out 复位 | 【假设】 |
| R4-b | 片上失效保护：局部热/电瞬时越限触发内部看门狗/THERMTRIP 类 | 【假设】 |
| R4-c | HCCS/snoop 偶发协议楔死 → 片上失效保护复位 | 【假设】（已被部分削弱：openblas 非 barrier 负载也死） |
| R2 | 根因域在 CPU1 侧（vs CPU2/共享板级路径） | 【强推】 |
| R3 | 触发为时间/老化随机，非平均量阈值 | 【强推】 |
| R5 | ~6 分钟无 POST 黑窗 = 二线看门狗（~360s 级）完成复位 | 【假设】 |

已由自然实验否证（不必再验）：简单热阈值（死亡日更凉）、平均互连负载阈值（风暴强度全同 + 相反画像也死）、单一测试因果（相位分散）。

## 1. 判别总逻辑（决策树）

```
复发时 E0/E5 自动取证
├─ 带外/OEM 拿到复位源 ≠ unknown ──→ 直接收窄 R4（如 thermal→R4-b, power→R4-a, watchdog→R4-b/c）
└─ 仍 unknown
   ├─ E1 高频遥测死前 2-5s 有电压/温度异常 ──→ R4-a/R4-b 实锤（再区分靠 E8）
   ├─ E1 无异常（瞬时不可见）──→ E3 单 socket 消融
   │   ├─ CPU2 socket 14 天 0 复发 ──→ R2【实锤】CPU1 侧；配合 E7/E8 下钻物理机制
   │   └─ 照常复发 ──→ 根因在共享路径（PSU/12V/板级）──→ E6-PSU/E8
   └─ E7 复发间隔 ~泊松 ──→ R3 成立（老化/瞬态随机）；相位强相关 ──→ 触发器可定位
```

## 3. 各实验设计

### E0 复发自动取证（零风险，立即部署）

**目的**：下次复发时自动保齐全部瞬态证据，消除人工延迟。
**方法**：systemd oneshot（multi-user 之后）脚本：快照 `ipmitool chassis restart_cause`、`sel elist`、BERT hexdump、`/sys/fs/pstore`、`/var/crash`、各采集器 CSV 末 N 行、`last -x`，落盘到 `/home/sdc/sdc-excite-reproduce/events/<ts>-sudden-reset/`。
**判据**：无判别功能，纯证据保全（本案取证中 BERT/pstore 均为 boot 后数小时才读，存在被覆盖风险）。
**集成**：新增脚本+服务 → 按 CLAUDE.md 规则 4 走 writing-plans。

### E1 高频遥测（判别"死前是否可见异常"）

**目的**：把死亡窗口从 60s 缩到 2–5s，回答"死前最后几秒有无电压跌落/温度尖峰"。
**方法**：dwell/L3 相位触发快速采样器：BMC 传感器批量读（ipmitool sensor，含 cpu1/cpu2 温度、各电压轨、功率）周期 2–5s；与 sdc-monitor 的常规采样**错峰**（BMC 探测限速教训：每窗口 ≤3 条、间隔 ≥10s，避免打超时 monitor 的采样）。
**判据**：
- 死前 2–5s 出现核心轨（0.87–0.91V）跌落 >5% 或温度尖峰 → R4-a/R4-b【实锤】；
- 完全无前兆 → 与微秒级瞬态（E8 域）或逻辑楔死一致，交给 E3/E7。

### E2 热消融（判别热路径）

**方法**：战役热联锁 95°C→85°C（campaign.env 参数），L5 热激发目标带同步下调；其余不变，观察 14 天。
**统计依据**：基线复发率 λ≈7/13 天≈0.54/天；14 天期望 7.5 次。若 85°C 下 0 复发，P=e^(-7.5)≈5.5×10⁻⁴ → 热路径【实锤】；若复发 ≥2 次 → 热主路径证伪。
**已知削弱**：自然实验已示死亡日更凉 → 预期本实验**不改变**复发率；其价值在于把"热"从【强推怀疑】变为【实锤排除】。

### E3 单 socket 消融（信息量最大，判别 R2）

**方法**：战役全组件（dwell/谱系/L3/stress-ng 层）限 CPU2 socket 运行 14 天。逻辑核映射先实测（`lscpu -e=CPU,NODE,SOCKET`；mesh yaml 的 fullsocket plan 显示 socket 边界为 cpu 0–63 / 64–127，需确认哪侧是 CPU1=BMC 命名的热侧）。
**统计依据**：同 E2。0 复发 → R2【实锤】（CPU1 侧硬件）；照常复发 → 根因在共享路径（PSU/12V 轨/板级），转 E6-PSU/E8。
**代价**：战役吞吐减半（dwell 对象时长×2 或裁剪）。**执行前先做 E6-PSU**（否则单 PSU 故障会污染判读：若根因是 PSU，E3 两臂都会死，误判为"非 CPU1 侧"）。
**附带收益**：CPU1 socket 静置 14 天本身是"休息/退火"对照——若 E3 后恢复双 socket 又迅速复发，老化-恢复动力学本身是 R3 的证据。

### E4 负载类别消融（判别 R4-c）

**方法**：剔除 barrier/原子风暴族（mesh 族、lock 族、atomic_simd 族、lockless_cmpxchg 族）跑其余 14 天。
**先验低**：10/4、10/6 openblas（非 barrier 类）死亡已证明 R4-c 非必要条件。仅在 E3 判"CPU1 侧"后、需进一步下钻负载敏感面时执行。

### E5 带外复位原因取证（每复发必做 + 主动探测）

**方法**：
1. iBMC web UI（管理网 9.3.1.8，需网络/物理接入）读"黑匣子"/审计日志/复位原因——in-band SEL 之外的独立记录面；
2. in-band OEM 探测：NetFn 0x30 cmd 0x90 状态 GET 簇（0x03/06/29/32/50/51）寻找复位原因寄存器，遵守限速纪律（每采样窗口 ≤3 条、间隔 10s）。
**判据**：拿到任何非 unknown 的复位源（thermal event / power fault / internal watchdog / SCC reset）→ 直接把 R4 收窄到单支。

### E6 物理修复消混杂（与 E2/E3 正交）

顺序敏感：**E6-PSU（补第二 PSU）先于 E3**（消除共享路径混杂）；E6-FAN（补 FAN1/FAN4）放在 E2 之后或与 E2 合并解读（补风扇改变热基线，会污染 E2 的前后对比）；重插 DIMM/紧固供电线在任意静默窗口做。

### E7 受控加速复现 + 复发间隔统计（判别 R3 形态）

**方法**：以保全的死亡参数精确复现：`sdcshield -e mesh_upi_sse_asymm_distrib_int -t 13356s --max-test-loop-count=0 --on-crash=context --on-hang=kill --ignore-timeout --ignore-os-errors --retest-on-failure=3 -s AES:32c4f1b69792a3258f1f6b2210c555a4cd3b0e49686d5cda70e094ddef3aaa5b` + stress-ng 层同参数（核 124–127），E1 高频遥测全开，E0 已部署，tmux/nohup 无人值守。
**统计设计**：基线 MTBF≈1.9 天。累计 3 次复发的间隔序列：K-S 检验对指数分布（随机）vs 相位对齐（负载/热循环相位触发）。间隔与"距上次冷启动时长"正相关 → 老化/累积模型；与负载相位相关 → 触发器可定位。
**风险（必须用户批准）**：**预期再次死机**——这正是实验目的；所有数据先行保全；会话需预期自杀（断点续跑由 systemd 承担）。
**附带的直接收益**：若 E1 在死亡瞬间捕获到电压/温度瞬态，R4-a/R4-b 当场【实锤】。

### E8 金标准物理测量（如有仪器）

示波器/功耗分析仪挂 CPU1 核轨 + 12V 轨 + PSU 输出，E7 负载下捕获瞬态（触发阈值：核轨 <0.80V 或跌落 >5%）。直接证实/证伪 R4-a。无仪器时以 E1 的 2s 粒度为上限。

## 4. 统计功效速查

| 消融臂时长 | 基线期望复发数 λt | P(0 复发 | 无效假说) | 判读 |
|---|---|---|---|
| 7 天 | 3.8 | 2.2×10⁻² | 弱证据 |
| 10 天 | 5.4 | 4.5×10⁻³ | 中等证据 |
| **14 天** | **7.5** | **5.5×10⁻⁴** | **强证据（建议臂长）** |

复发 ≥2 次即证伪该消融假说（P≥1-e^(-λt)·(1+λt)）。

## 5. 执行顺序（建议）

1. **第一波（零风险，立即）**：E0 + E5(带外通道打通) + E1；
2. **第二波（需批准）**：E6-PSU → **E3（14 天，信息量最大）**；
3. **第三波（需批准，接受死机）**：E7 受控复现（E1 全开）；
4. E2/E4 视 E3 结果与剩余歧义再定（先验均已被自然实验削弱）。

## 7. 安全边界

- E2/E3/E4/E7 改变战役行为或预期死机，**均需用户明确批准**后执行；
- E7 前置条件：E0 已部署验证 + 全部数据备份；
- 所有 BMC 交互遵守限速纪律（≥10s 间隔、与 monitor 采样错峰）；
- E6 涉及物理操作，需现场执行；
- 每次复发后：先跑 E0 快照，再做任何其他事（包括本计划的后续判读）。

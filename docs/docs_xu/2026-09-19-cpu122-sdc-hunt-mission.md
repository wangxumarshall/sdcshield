# 【高优先级】122 号核心 SDC 故障狩猎任务（2026-09-19 记录）

> **优先级：高**。本文档是当前 `tests/cpu/sve/` 所有工作的任务纲领。

## 任务背景（用户 2026-09-19 设定）

这台机器的 **CPU 122 号核心存在 SDC 故障**（其余核心正常）。任务：写出**能快速找到 122 号 SDC** 的测试用例，并分析**什么负载可以快速触发它**。

## 强制验证流程（每次改写/新写测试用例时执行，顺序不可变）

1. **热插拔拔出 122**：将 CPU 122 offline（`echo 0 > /sys/devices/system/cpu/cpu122/online`）。
2. **干净基线跑 60s**：在**除 122 外的全部核心**上运行测试 60s。其他核心无 SDC 故障 → 逻辑正确的代码**必须全 pass 零 fail**；**出现任何 fail = 测试代码自身有逻辑缺陷**，必须定位并修改，不允许归咎于硬件。
3. **热插插回 122**：将 CPU 122 online（`echo 1 > /sys/devices/system/cpu/cpu122/online`）。
4. **全核心有效性验证**：在**含 122 的全部核心**上运行测试。只有 122 有 SDC → fail（若有）必须**精确锁定在 cpu 122**。这是测试用例有效性的判定标准。
5. 循环迭代：负载 → 122 是否被触发 → 分析什么负载特征触发最快。

## 核心判据

| 阶段 | 核心集合 | 期望结果 | 若不符 |
|---|---|---|---|
| 基线 60s | 全部 − {122} | 100% pass | **我的代码 bug**，修代码 |
| 有效性 | 全部（含 122） | fail 集中且仅出现在 cpu 122 | 测试无效或硬件故障表现变化，继续分析 |

## 任务目标

1. 写出能**快速检出** 122 号核心 SDC 的测试用例（放 `tests/cpu/sve/`，SVE 优先——本机 256-bit SVE + f32mm/f64mm/bf16/i8mm/fcma 实测可用，见 SVE 能力研究文档）。
2. 分析**什么负载特征**（指令类型/数据模式/访问序列）能最快触发该 SDC，形成负载特征分析结论。

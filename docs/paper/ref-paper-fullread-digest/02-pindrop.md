- 核心结论(各带节号/图表号):
  1. **Meta fleet 终身 SDC 故障率 0.035%(约 1/2850 台至少失败一次)**,与 Google/Meta/Alibaba 既往报告"数千台一坏"量级一致(Observation 1,§V-A,Table I);8 种架构全部存在故障,最老的架构 E 高达 0.178%(早于厂商与内部 QA 改进)。
  2. **故障跨广泛复杂功能出现,不止算术**(Obs 2,§V-A,Fig.7):加密、事务内存、AI 矩阵指令等均受害;最常失败的是 ML 常用的向量矩阵卷积/降维,其次是线性代数算术(§VI-A)。
  3. **机器可在测试数年后才开始失败——连续测试是刚需,快照式必漏**(Obs 4,§V-B,Fig.9):有机器 2021-08 首测、2025-07 才首次失败;burn-in 后每季度仍有 0.0024% 机器新发故障(Obs 5)——该稳态值与 Alibaba 常规产线测试总故障率 0.0035%[36] 接近,说明延长测试窗口比 2 周快照能多挖一个量级(§V-B,§VIII 结论"an order of magnitude more defective parts")。
  4. **失败持续性:>71% 故障机在 ≥2 年持续测试中稳定复现失败**(Obs 6,§V-B,Fig.10);但也存在"自愈"反例——一台机器 2023-06 至 2024-03 间 119 次向量测试失败后,再 5.9 万+次测试(含重放失败种子)零失败,且期间软硬件固件零变更(§V-B)。
  5. **测试套件有效性:91.4% 广谱测试至少失败过一次**(Obs 7,§VI-A)——远高于 Alibaba[36] 的 <15%,归因于更大机器池+更长测试时间;31% 的测试是至少一台机器上唯一的失败测试→测试多样性不可压缩。
  6. **核级亲和:同物理核的超线程一起失败,跨物理核同时失败罕见**(Obs 8,§VI-A,Fig.12);约 62% 故障机仅单物理核失败,14% 为 2–9 核,24% ≥10 核(Obs 9,Fig.13)——与 Alibaba"半数单核/半数全核"的分布不同(作者部分归因于其排除的 5 个假阳性测试曾全核报错);事务内存测试缺乏核亲和,暗示跨核共享结构根因(§VI-A)。
  7. **向量输出中多比特翻转数量超过单比特翻转**(Obs 11,§VI-B,Fig.16)——比 Alibaba[36] 报告的多比特比例更高(即使按单个向量元素统计);约 90% 场合仅单个向量元素出错,元素位置无偏;vfm(向量融合乘加,ML 主力)是失败率最高的指令类(Obs 12,§VI-B,Fig.17)。
  8. **指令在其引入代际失败率最高,后续代际持续改善**(Obs 12,§VI-B,Fig.17)——每代都在修复上代观察到的特定失败;新指令=新风险,测试必须随代际持续开发。
- 分类学标注(按论文实际内容归类):
  - 根因机理类型:**边际缺陷(marginal defects)→ 小延迟故障**,仅在特定温度/频率/电压/程序/输入组合下显现(§II-B,引厂商报告);观察期未到显著磨损期(bathtub 末端未见明显上翘,§V-B);根因确认非本文目标("outside the scope",§VI-A)
  - 故障模式类型:**多比特翻转主导**(向量输出);**间歇性/随机性**(种子相关、可"自愈");**核 ID 亲和**(cores 0–5 及其兄弟核 26–31 偏高,某些架构 core 0 失败率 3×,Obs 10,§VI-A,Fig.14);**单元素单点出错**(90% 场合单向量元素)
  - 检测技术类型:**持续高频在产测试**(IRMS 预约系统,P4→P3→P2 优先级演进,15 天平均重访,每日触达 1.75% 基础设施);**金标输出比对 + 跨核结果比对**双模式(§IV);**按架构效能选测**的优先级策略(§VI-A);随机种子记录供复现(§IV)
  - 处理技术类型:**预约扣留(reservation hold)→ 深度测试循环 → 部件更换 → 回归产线**(§III-A/Fig.1);连续测试本身作为管理策略(优先级/节奏可调)
- 业界观点摘录:学术论文,按模板略。(注:§II-A 描述 Meta 侧 SDC 应用影响全景——推荐推理误算、并发特性损坏致活锁、校验和算错写入全部副本致数月后取数才暴露的潜伏损坏、AI 训练错误传播/故障传染;单次应用级数据损坏调试需数百工程师、数周至数月;§II-B 描述厂商-超大规模者协作闭环:现场重现器交芯片厂→厂商改进芯片级缓解与未来代际 QA 测试)

- 方法论要点:以 IRMS(基础设施预约管理系统)为基础的持续测试框架 PinDrop 三组件(Partitioning/Characterization/Querying Engine);分区引擎日聚合、6 年保留;9 大测试族分类;排除 5 个假阳性测试的清洗;时间序列分析时对新引入测试设 30 天排除窗(§V-B);架构 G–H 因测试多样性受限被排除出对比分析(§V-A);双测量基准(自测试起第 n 季度 vs 自部署起第 n 季度,Fig.9a/b)分离测试时长与机器年龄。

## 1. 研究问题与核心贡献(≤5 行)

第一个对超大规模数据中心(数百万台机器)中**向量指令 SDC** 的指令级 + 应用级综合测量:两阶段方法(舰队初筛 SDC Suspects → 长时深测),78 万亿测试轮 / 140 亿 CPU 秒。核心发现:FMA 指令 SDC 占 92%+、SDC 频率可低至 10⁻⁶、浮点 SDC 可翻指数位(推翻 SOSP23 "只翻尾数位" 结论)、SDC 空间局部性极强(98.5% 单 lane、单物理核)。提出基于 matmul 的 in-application ABFT 检测:机器检出率 88%-100%,时间开销低至 1.35%(n≈1024)。

## 2. 实验方法(他们怎么做的)

### 2.1 两阶段研究方法(Sec. 2)

- **阶段一:舰队级 SDC Suspects 筛选**(Sec. 2.2,Fig. 1)。两种并行机制:
  - **Out-of-Production 测试**:计划维护窗口内执行,每台机器每 45 天约 15 分钟;
  - **In-Production 测试**:毫秒级测试轮与生产负载共置,每台机器每天累计约 30 秒。
  - 两者均使用标准硅厂商测试套件 + 来自 16 个生产负载家族的代码片段,覆盖算术、向量、并发、控制流、数据移动、浮点、事务内存、编码函数等指令。
  - 匹配已知非 SDC 故障的机器送去维修;疑似 SDC 的机器被**虚拟标记(virtual flag)为 SDC Suspect**,继续在生产舰队中服役(同样的负载、同样的内核/软件更新),但可被长时测试预约预留。多年累计识别 **2500+ 台 SDC Suspects**。
  - 平均故障率:约 1000 DPPM(Fig. 1 标注)。
- **阶段二:对所有 SDC Suspects 做长时深测**(Sec. 2.3)。每台机器测试约 42 小时,等效于 21 年正常舰队测试配额(脚注 3:生产中每机每 45 天只有 15 分钟测试时间)。

### 2.2 指令级测试(重点:测试程序形态)

#### 2.2.1 246 个测试用例如何构造(指令覆盖表)

- 框架特性:**详细系统状态日志 + 指令级隔离**——**每个测试用例只测一条指令**,对观察到的行为提供精确归因(Sec. 2.3:"Each test case examines a single instruction, providing precise accountability for observed behaviors")。
- **246 个测试用例,穷尽覆盖 AVX2、FMA3、BMI1、BMI2 全部指令**(Sec. 2.3 原文:"Our current test suite comprises 246 test cases that exhaustively cover all instructions for Advanced Vector Extensions 2 (AVX2), Fused Multiply-Add 3 (FMA3), and Bit Manipulation Instruction sets (BMI1 and BMI2)")。
- **逐条指令的清单原文未给出**(论文只给汇总数 246 与 top-20 图 Fig. 4;Fig. 4 因保密只显示指令匿名标签);复现时需自行从 ISA 手册枚举这四个扩展的去重指令全集再核对到 246。
- 覆盖的指令类型谱(由结果反推):**有 SDC 检出的类型只有 4 类**——arithmetic、FMA、gather、permute(Obs. 2);但阶段一舰队测试(Sec. 2.2)的用例谱更宽:arithmetic、vectors、concurrency、control flow、data movement、floating-point operations、transactional memory、encoding functions。
- **指令-硬件单元归因思路**(Obs. 3 讨论):通过"同一核上不同故障指令的 SDC 频率一致(1-2 个数量级内)"反推这些指令**共享同一受损硬件单元**(向量乘法、shuffle、内存单元)——单指令粒度的用例设计正是为了支撑这种归因。
- Obs. 2 讨论给出 FMA 脆弱的两个架构归因:乘法器逻辑门比加法器等简单部件多 **30×** 且通常无硬件级保护(引 [8] Veritas);浮点向量乘法硬件被 **32 条不同指令共享**,密集使用加速磨损。

#### 2.2.2 输入生成方式

- 执行方式:每个用例在**每台机器的每个逻辑核**上执行 **100 万轮**;**每轮取不同输入**(Sec. 2.3:"Each round takes a different input")。
- 输入生成的具体 RNG 算法、数值分布(均匀?位随机浮点?)、种子策略:**原文未给出**——复现的最大信息缺口。
- 第三遍实验:**所有向量 lane 统一输入**(uniform inputs across all vector lanes),用于研究 SDC 与 lane 位置的相关性(Sec. 2.3)。
- 框架具备**输入记录与重放**能力:Obs. 7 的输入级复现实验(同硬件同输入重放,统计复现率,Fig. 9)说明失败轮输入被落盘可重放。
- matmul 侧输入生成是明确的:bounded [-1,1] / unbounded 两分布 × 每轮在维度上限内随机选实际维度(见 2.3)。

#### 2.2.3 向量-标量交叉验证的实现

- 核心判定:**比较向量输出与标量参考输出**(Sec. 2.3:"compares the vector output with a reference scalar output")。
- 正确性论证(原文):向量计算与标量计算使用**不同的硬件单元**,硬件故障极难在两条路径上产生相同的错误输出——失配即可判定 SDC。
- 应用级同构:matmul 的 ground truth 同样用标量 for-loop 复制计算(Sec. 5.2);因此 ABFT 检出率是**保守下界**(标量路径自身的 SDC 计为 ABFT 漏检;引 [8] 标量单元 SDC 率显著更低,偏差可忽略)。
- 隐含工程点(**原文未讨论,复现关键**):标量参考必须与向量实现在数值语义上逐位一致(FMA 融合与否、舍入模式)。ARM64 上 NEON/SVE FMLA 是 fused,标量参考须用 `fmaf()`/`vfma` 而非 `a*b+c`,否则会大量假阳性。SDCShield 的框架已把 SNaN 统一静默(sandstone_data.cpp)以保 FP 位模式可比,正好服务于此。
- 总量:指令级 **78 万亿轮 / 140 亿 CPU 秒**(Sec. 2.3,摘要);测试时间构成:每机约 42 小时(Sec. 2.4 脚注 3)。

### 2.3 应用级测试(matmul)

- 实现:**NumPy(Python)matmul 测试套件**;选择 NumPy 的理由(Sec. 2.3):底层实现重度依赖向量指令(尤其 FMA)+ 代表生产中的 matmul 负载。**具体 BLAS 后端未披露(原文未给出)**。
- **输入维度设计(重点,值域实验的完整矩阵)**:
  - **两种输入值分布**:bounded [-1,1](模拟归一化数据,production 常见形态)与 unbounded(接受任意合法浮点值);
  - **三种矩阵维度上限(bound)**:10、25、100;每次测试迭代在维度上限内**随机选取实际维度**(simulate varying computational loads);
  - 共 **6 个配置**(2 值域 × 3 维度上限);
  - 执行量:每机器每核每配置 **100K 轮**;最大维度上限 100 因时间约束降为**每机器 10K 轮**;
- 总量:**43 亿轮 / 25 亿 CPU 秒**(Sec. 2.3 末)。
- 选 matmul 的双重动机(Sec. 1):广泛用于数据库/ML/科学计算/信号处理;对 FMA 的重度依赖使其对 SDC 最易感——是研究真实应用 SDC 的理想载体。

### 2.4 ABFT 检测机制(Sec. 5)

- 原理(Sec. 5.1,Fig. 22):对 A×B,先计算 **A 的行校验和向量**与 **B 的列校验和向量**,二者点积得到标量校验和,数学上等价于结果矩阵 A×B 所有元素之和,以此不变量检测 SDC。开销 O(mn+np) 加法,远低于 matmul 本身 O(mnp)。
- 假设:SDC 可能影响 matmul 或校验和任一侧,但 SDC 行为高度依赖输入,两侧同时得到相同错误校验和的概率极低。
- 大矩阵对策:**建议 tile 级实现 ABFT,保持 tile 尺寸 < 100**;tile 间共享校验和向量可保持与全局实现相同的时间复杂度(Sec. 5.1 末)。
- 评估中检测覆盖实验把结果矩阵划成 **2×2 四个 tile**,逐 tile 验证校验和(Sec. 5.2)。
- **ground truth(真值)机制(Sec. 5.2)**:用**标量计算(for-loop 复制 matmul)**作为复制式验证基线;标量路径用不同硬件单元,比较输出即可识别 SDC 发生时刻。若 SDC 只发生在标量验证路径上,计为 ABFT 漏检——因此报告的检测率是**保守下界**(引 [8]:标量单元 SDC 率显著低于向量单元,偏差可忽略)。
- 机器覆盖率定义:ABFT 检出 SDC 的机器核数 ÷ 检出 SDC 的总机器核数(Sec. 5.2)。
- 性能对比基线:**C++ 实现的 replication-based 方法**(跨两个向量 lane 复制计算;利用 Obs. 13 不同 lane 同时失败概率低的事实)。ABFT 同样用 C++ 实现以保证公平(Sec. 5.3.2)。

### 2.5 统计口径与术语(Sec. 3 开头)

- **SDC case**:某测试用例在某机器核上检出 SDC(一次"立案");
- **SDC incident**:一轮测试中的结果失配(一次"事件");一个 case 可含多个 incident;
- 舰队级机器向量 SDC 率 ≈ **0.072‱**(万分之一率,Obs. 1);与先前工作 [47=SOSP23] 的 0.348‱(常规测试、其中约 40% 为向量指令)一致,作为方法有效性佐证。

## 4. 实验步骤(可操作流程)

**指令级实验(对应 Sec. 2.3 + Sec. 3 全部分析):**
1. 构建指令隔离测试框架:单用例单指令,带系统状态日志(温度、频率、时间戳);
2. 枚举 AVX2/FMA3/BMI1/BMI2 每条指令,各生成一个测试用例,共 246 个(每用例内含该指令的向量化执行体 + 等价标量参考实现体);
3. 每用例:每轮生成新随机输入 → 向量执行被测指令 → 标量参考实现同输入执行 → 逐位比较输出;失配即一次 SDC incident,首次失配立案为 SDC case;
4. 在每台 SDC Suspect 机器的每个逻辑核上执行 100 万轮/用例(总 ~42 小时/机);
5. 记录:SDC case/incident、输入位模式、输出位翻转位置与字段(符号/指数/尾数)、错误偏移量(内存类指令)、CPU 温度、归一化频率(当前频率/最大频率);
6. 整套实验**重复第二遍**(完全相同设置)→ 用例级可复现性(Obs. 6);
7. **第三遍**:所有 lane 喂相同输入 → lane 位置相关性分析(Obs. 13;74% cases 仍单 lane);
8. 失败轮输入重放 → 输入级复现率(Obs. 7);
9. 后处理分析:
   - 输入位偏置统计:每位取 0 概率,>0.8 判"偏置位";区分 FP32(偏尾数)vs FP64(偏指数);
   - 输出位翻转三分类:字段翻转位号数 < 字段位数 1/4 判 Low → LELM/LEHM/HEHM;符号位翻转单列;
   - 相对误差 CDF(每模式);
   - 机器内跨指令 SDC 频率一致性检验(单点故障假说);
   - 逻辑核对(HT sibling)模式对比(Obs. 12);
   - log(SDC 频率) 对温度线性拟合 + Pearson 相关性(Obs. 14)。
10. 内存访问类指令:分配 256 字节读空间,记录空间全部内容;失败时判定"有效数据+错误偏移"(76%)vs"无效数据/越界"(24%)。

**应用级实验(对应 Sec. 2.3 + Sec. 4):**
1. NumPy 搭建 matmul 测试,输入按 bounded/unbounded × dim 上限 10/25/100 共 6 配置;
2. 每轮随机选实际维度、随机生成矩阵元素,执行 matmul,与标量 for-loop 参考结果比较;
3. 每核每配置 100K 轮(dim=100:每机 10K 轮);总量 43 亿轮 / 25 亿 CPU 秒;
4. 统计每核 SDC 频率、首失败轮数/时间、每 incident 错误元素数、相对误差分布、复现率(同输入重放);
5. 跑两遍评估复现性(24 核中 22 核一致);
6. 交叉分析:matmul SDC 频率 vs 该核 FMA 指令平均 SDC 频率的相关性(Pearson=0.979);值域间频率比(最高 245×);维度-频率关系。

**ABFT 实验(对应 Sec. 5.2-5.3):**
1. C++ 实现 matmul+ABFT(A 行校验和向量、B 列校验和向量、点积标量校验和)与 lane 复制基线;
2. 覆盖实验:在全部 SDC Suspects 上,与 Sec. 2.3 相同的 6 种输入配置,结果矩阵 2×2 分 tile 逐 tile 验证;以标量 for-loop 复制计算为 ground truth;统计机器覆盖率(检出机核数/总检出机核数)与 incident 检出率(按 incident 数加权);
3. 开销实验:n=10~1024 方阵,1000 轮平均,比较带/不带 ABFT 的执行时间差(n=10/25/100/.../1024;tiled 与 global 两方案开销几乎相同);
4. 部署原型:数学库层注入(应用无关)。

## 5. 实验数据(关键数值,标注图表号)

### 5.1 指令级总体(Obs. 1-3)

- **Obs. 1**:2800 万 SDC incidents / **400 SDC cases**;舰队级机器向量 SDC 率 ≈ **0.072‱**;另观察到 **38 台机器**的 fail-noisy 错误(多进程环境段错误、对受支持指令报 illegal instruction 等;可源于任意 CPU 部件含缓存/事务内存;易检测、逐例人工分析,不属 SDC 范畴)(Fig. 2a 向量 SDC vs fail-noisy;Fig. 2b fail-noisy 分解)。
- **方法学交叉验证**:全部 400 个 SDC cases 经多通道独立验证(自动舰队测试、专家分析、半导体厂商确认);舰队级 0.072‱ 与 SOSP23 [47] 常规测试 0.348‱(约 40% 为向量指令)一致——两阶段方法的效度证据。
- **Obs. 2**:**75/246 测试用例检出 SDC**,跨 4 类指令:arithmetic、FMA、gather、permute(Fig. 3a 各类型检出 SDC 的指令数);FMA **>75% SDC cases、>92% SDC incidents**(Fig. 3b cases/incidents 双分解);**top-20 SDC 指令中 19 个是 FMA**(Fig. 4,按失败机器/核数排序)。
- **Obs. 3(机器间差异)**:Fig. 5(x=机器,同机核相邻排列;y=SDC 频率;每点一个 SDC 检出用例,按被测指令着色):
  - 单机检出 SDC 的用例数:少到几个,多到 **32 个**;
  - 平均检出频率跨**数个数量级**:百万分之一(10⁻⁶)到接近全部轮次;
  - **机内一致性**:同一机器的故障指令 SDC 频率通常保持在 1-2 个数量级内;
  - **双核失败模式**:一台机器两个失败核(同一物理核的两个逻辑核)表现相似模式(相似的 SDC 用例集与检出率);
  - 假说:每个缺陷核只有**单一硬件单元的单点故障**(向量乘法/shuffle/内存单元),不同功能指令共用该受损单元 → 频率一致。

### 5.2 频率/时延/可复现性(Obs. 4-7)

- **Obs. 4(位宽相关性,Fig. 6)**:permute 与 gather 指令的 SDC 检出频率跨用例**相对一致**;FMA 表现出与位宽相关的显著模式——**128-bit FMA 只显示相对高频的 SDC cases;256-bit FMA 额外显示低频 cases(<10⁻⁵)**,且检出 SDC 的机器范围更广(Fig. 6 每点 = 一个在该用例上检出 SDC 的处理器核)。
  - 两个架构归因:(1) 256-bit FMA 更宽数据路径激活更多晶体管 → 更多 SDC 来源;(2) 256-bit FMA 功耗 2× 于 128-bit → 标量与 FMA 执行切换时更大电流波动 → 更易引发超出安全裕量的电压变化(引 [26][53])。
  - **对 SVE 的直接启示**:SEVI 只有 128/256 两档;SVE 可变向量长度(128-2048 bit)把这个轴变成连续谱——你的实验可测"VL 扫描 vs SDC 频率"曲线。
- **Obs. 5(首失败时间,Fig. 7a/7b)**:**>80% SDC cases 首失败 <10K 轮(1 秒)**(CDF 按指令类型分列);其余 20% 是需要持续精化检测机制的长尾。
- **Obs. 6(用例级可复现性,Fig. 8)**:两遍相同设置的完整测试:19 台在任一遍检出 SDC 的机器中 **6 台两遍检出的用例集不一致**;不一致用例**多数检出频率极低(10⁻⁵~10⁻⁶)**,少数例外达 10⁻³(主要是 gather——行为依赖软件层不可控的缓存状态);**所有指令类型都出现不可复现用例**;结论:可复现性由 **SDC 频率**决定,与指令类型无关;增加测试轮数可稳定检出低频 SDC。
- **Obs. 7(输入级可复现性,Fig. 9)**:同一硬件 + 相同输入重放,复现率 n% = 在 n% 的 SDC 诱导输入上可一致复现:
  - arithmetic / FMA / permute:**跨机器差异巨大(近 0% 到 90%)**;
  - **gather:恒接近 0%**——内存访问依赖缓存状态(OS 调度、内存分配模式、并发测试进程都影响),软件层无法保持两次运行缓存状态一致;该变异性延伸到生产负载,使内存访问类 SDC 从根本上难复现;
  - 首次量化指令级 SDC 复现率(优于 [12][24][47] 的粗粒度观察);
  - Implications:**单次成功执行不能证明无 SDC**——必须舰队持续测试。

### 5.3 位模式(三种位翻模式分类方法,重点)

#### 5.3.1 输入位偏置(input bit bias)

- **判定方法**(Obs. 8 原文口径):对每个 SDC case 的全部 incidents 聚合统计每个输入位位置取 0 的概率;**概率 > 0.8 的位记为"偏置位"**。
- **结果**:301 个 FMA SDC cases 中 **113 个(37%)** 存在显著输入位偏置,横跨 **7 台不同机器**、**2 家 CPU 厂商**、多个架构代(Fig. 10 左为示例:特定 bit 位上 0 的概率显著偏离 0.5)。
- **FP32 vs FP64 差异**(Fig. 10 右,圆圈大小=出现频次):FP32 操作的偏置位**主要位于输入值的尾数位**;FP64 操作的偏置位**主要位于输入值的指数位**;作者推测源于同一功能单元在 FP32/FP64 下硬件实现不同。
- FP32 与 FP64 FMA 的 SDC case 数相近:**126 vs 175**(Obs. 8)。

#### 5.3.2 输出位翻转三分类(LELM/LEHM/HEHM)

- **分类判据**(Obs. 8 原文):若某字段的全部 SDC incidents 中被翻转的位号总数**少于该字段总位数的四分之一**,该字段记为"Low"(低翻转);否则记为"High"。
- **三种模式**(Fig. 11a 为散点总览:每点一个 test case,x=指数翻转数,y=尾数翻转数,圆大小=频次;Fig. 11b/c/d 分别为三模式的位翻概率与相对误差 CDF 示例):
  1. **LELM**(Low Exponent, Low Mantissa):**62 SDC cases / 6 台机器**——低精度损失(相对误差 CDF 集中在小值);
  2. **LEHM**(Low Exponent, High Mantissa):**61 cases / 8 台机器**——低精度损失;
  3. **HEHM**(High Exponent, High Mantissa):**178 cases / 5 台机器**——**高精度损失**(指数位翻转导致量级错误);
- **符号位翻转**:301 cases 中 **65 个(2 台机器)出现 sign bit 翻转**,造成显著相对误差;
- **机器一致性**:13 台有 FMA SDC 的机器中 **7 台在全部 cases 上只表现单一模式**;其余 6 台在两个相邻模式间交替("LELM↔LEHM" 或 "LEHM↔HEHM")——支持"单点故障单元"假说。
- **意义**:直接挑战 SOSP23 [47] "SDC 主要影响尾数位、精度损失小" 的结论(该结论也在你的 memory 里被标记为"SEVI 推翻了 SOSP23 尾数论")。

#### 5.3.3 内存访问指令两模式(Obs. 9)

- **实验设置**:为涉及内存读取的指令(如 gather)**分配 256 字节读空间,记录空间内全部内容**;失败时比对读回数据与空间内容。
- **两模式**:(1) **错误偏移读占 76% 的 incidents**——读到了有效数据但来自错误偏移(偏移/地址计算逻辑出错);(2) **读无效数据占 24%**——访问越界(超出分配空间)或数据在缓存/CPU 内部数据路径中损坏。
- **特例**:1 个 SDC case 中 gather 指令在某特定向量 lane **恒定读 0**。
- **关键观察**:即使访问了无效地址也**不产生系统崩溃**(与软件级非法访问异常不同)——这是"静默"的本质。
- Implications:内存访问类 SDC 以错误偏移为主,需要专门针对访问模式的校验策略,而非只校验数据值。

#### 5.3.4 算术指令(Obs. 10)

- 30 个算术 SDC cases 中 **22 个无统计显著的输入位模式**;
- **例外**:1 台机器上 8 个 INT16/UINT16 乘法相关 cases 表现完全一致的模式——**每次 SDC incident 中第二输入向量的次高位(second highest bit)恒为 1**(Fig. 12a);作者无硬件设计访问权,无法解释机制;
- **输出位翻模式高度机器特异**(机器内高度一致):一台集中在高位(Fig. 12b)、一台只在低位(Fig. 12c)、两台遍布所有位(Fig. 12d)。

### 5.4 硬件模式

- 17 个 CPU 型号中 7 个、7 个架构中 4 个观察到向量 SDC;SDC Suspects 内架构 SDC 率 **4‰~24‰**(Obs. 11,Fig. 13,Table 1);舰队级硬件 SDC 率因保密未给。
- **单物理核**聚集:18 台向量 SDC 机器全部只影响一个物理核;16 台(89%)两个逻辑核都表现 SDC,2 台(11%)仅一个逻辑核;97% cases 在两个逻辑核上以几乎相同频率出现(Obs. 12)。
- **lane 局部性**:2800 万 incidents 中 **98.5% 只影响单个向量 lane**;多 lane 的 1.5% 中 **96% 只影响相邻 lane**(Obs. 13,Fig. 14)。即使所有 lane 同输入(第三遍实验),**74% cases 仍单 lane**——排除"输入不同导致的表面局部性";Fig. 14 还显示 SDC 频率与平均受影响 lane 数的关系(每个点一个 SDC case)。
- 架构解释:每个向量 lane 有专属功能单元集合,故障表现为对这些单元的局部化影响(Implications)。
- **运行条件(Obs. 14,Fig. 15)**:
  - 归一化频率 = 当前频率 / 最大频率;
  - 全部 SDC incidents 发生在**低于最大工作阈值**的温度,距热节流有充分裕量;同机 incidents 的温度/频率一致;
  - **95% cases 发生时 CPU 频率 < 最大频率的 80%**——即 SDC 并不集中在高频极限工况;
  - **温度-频率负相关**:温度升高 → 低检出频率(长尾)SDC cases 开始出现;log(SDC 频率) 对温度线性拟合 **Pearson = -0.392,p = 5.68×10⁻¹²**(Fig. 16);
  - Implications:生产测试应给高温机器分配更多测试周期;温度控制机制(如 [47])可减少高温诱发的低频 SDC。

### 5.5 应用级(matmul)

- **总体(Obs. 15)**:12 台机器(24 个 SDC cases)/ 43 亿轮;总 incidents **292K**;舰队级 SDC 率 **~0.048‱**(与指令级 0.072‱ 同量级);Fig. 17 左为 faulty 核 SDC 频率 CDF。
- **根因关联(Obs. 15,Fig. 17 右)**:24 cases 中 **10 个在同时有 FMA SDC 的机器核上**;matmul SDC 频率与该核 FMA 指令平均 SDC 频率呈强线性相关:**Pearson = 0.979**——FMA SDC 是 matmul SDC 的根因;其余 14 个 case 多为极低频(matmul 每轮执行的 FMA 远多于指令级测试,推为指令级 100 万轮未覆盖的更低频 FMA SDC)。
- **首失败时间(Obs. 16,Fig. 18)**:**75% cases 首失败 <8 秒(2400 轮)**——与指令级 Obs. 5(>80% <1 秒)一致。
- **错误形态(Obs. 17,Fig. 19)**:
  - 左图:机器核 SDC 频率越高 → 每 incident 平均错误结果数越多(正相关);
  - 右图:错误相对误差 CDF——**75% 的错误计算相对误差 <1(轻微);其余 25% 相对误差可达 10240**(量级错误,归因于 FMA 指数位翻转,呼应 Obs. 8 的 HEHM 模式)。
- **复现性(Obs. 18,Fig. 20)**:同实验跑两遍,24 核中 **22 核两轮一致**(检出且频率相近);2 核只在第一轮检出(频率 10⁻⁵);SDC 频率 vs 输入级复现率 Pearson = **0.816**;**约 50% 机器复现率 >80%**(右图 CDF)。
- **值域实验(Obs. 19,重点,Fig. 21)**:
  - 左图(bounded (-1,1) vs unbounded):**同一机器核上不同输入值域的 SDC 频率差最高 245×**;**10 个机器核的频率比 >5×**——指令级对特定输入位模式敏感的直接证据(与 Obs. 8 输入位偏置互证);
  - 右图(维度):更大矩阵维度 → 更多轮次出现 SDC(每轮计算量增大,符合预期);
- **硬件模式(Obs. 20)**:matmul SDC 同样只影响单物理核及两个逻辑核;更高核温诱发更低检出频率的 case——与 Obs. 12/14 一致。

### 5.6 ABFT 结果(Sec. 5.3)

- **覆盖(按配置分解,全部数值 Sec. 5.3.1)**:
  - max dim 10 + unrestricted 值:**100% 机器覆盖**,识别全部 24 个 SDC 机器核;incident 级加权平均检出率 **~60%**(按每机 incident 数加权);**>80% 机器核首检 <21 秒**(Fig. 23 左/右);
  - max dim 25:机器覆盖 **94%**;max dim 100:**88%**——大矩阵使校验和的相对误差变小、检测变难;对策是 tiling 降有效维度(代价是略高开销);
  - bounded 0-1 值:23 台机器中检出 21 台(**91%**),incident 检出率 **~99%**(有界输入使 SDC 的相对误差更大,更易检出)——"多数真实应用输入有界"是其实用性论据;
  - incident 级 ~60% 与机器级 100% 的关系:约 25% incidents 相对误差 >1(Obs. 17/Fig. 19 右),足以覆盖每台机器至少一次可检出错误。
- **时间开销**(n×n 方阵,1000 轮平均,Fig. 24 + Sec. 5.3.2):
  - n=10:**0.04µs(11%)**;n=25:**0.22µs(11%)**;n=100:**3.04µs(3%)**;
  - n→1024:**1.35%**;所有尺寸下比 lane 复制基线低**数个数量级**(基线开销随 n 波动,作者推测编译器优化在某些区间更有效);
  - 对比基线:replication-based(C++ 双 lane 复制)。
- 部署建议(Sec. 5.4):在**数学库层**实现,应用无关;可通过库链接选择启用;达到现有舰队测试等效覆盖估计**每天只增加几秒**开销;与现有舰队测试互补(让它们专注其它故障模式)。

## 6. 实验结论(论文自述)

1. 向量指令 SDC 中 FMA 最普遍(>92% incidents),归因:乘法器逻辑门比加法器多 30× 且无硬件保护、浮点向量乘法单元被 32 条指令共享导致磨损加速(Sec. 3.1 Obs. 2 讨论)。
2. 测试应优先**硬件单元覆盖**而非穷尽指令覆盖(同一硬件单元的不同指令 SDC 频率一致)(Obs. 3 Implications)。
3. 常规隔离测试对 <10⁻⁵ 的低频 FMA SDC 时间开销不可承受 → 把生产负载变成检测金丝雀(Obs. 4 Implications)。
4. 浮点 SDC 可影响任何输出位(含指数位),推翻 SOSP23 [47] "SDC 主要影响尾数、精度损失小" 的认知(Obs. 8)。
5. 内存访问类 SDC 以错误偏移读为主(76%),需要专门的访问模式校验策略(Obs. 9)。
6. SDC 单物理核聚集 → 可选择性禁用故障核而非整颗 CPU 退役(Obs. 12)。
7. 98.5% SDC 单 lane → 可在非相邻 lane 做选择性冗余计算(Obs. 13)。
8. 高温诱发低频 SDC → 高温机器应分配更多测试周期(Obs. 14)。
9. 单次测试通过不能证明无 SDC(复现率低),必须持续测试(Obs. 7)。
10. In-application ABFT 首次在真实 SDC 硬件上验证,低开销高覆盖,是对现有舰队测试的补充(Sec. 5)。

## 9. 局限与坑(论文自认 + 读出的坑)

**论文自认局限:**
1. 两阶段法只能测到"被舰队测试检出的" SDC Suspects;极低频 SDC 机器可能漏检,"任何测试方法的根本性局限"(Sec. 2.2 末);但作者声称这类漏检"在统计上不太可能改变结论"(无量化支撑)。
2. 舰队级硬件 SDC 率因保密不披露(Fig. 13 相关段落);厂商/架构名匿名(Table 1 上方)。
3. ABFT 检测率是保守下界(标量真值路径自身也可能 SDC)(Sec. 5.2)。
4. ABFT 未集成进生产应用(集成周期长),只在生产机器上测了核心库(Sec. 5.2)。
5. incident 级检出率仅 ~60%(dim10 unbounded),靠"约 25% incident 相对误差 >1"兜底覆盖全部机器(Sec. 5.3.1)——机器级 100% 与 incident 级 60% 的差距要分清口径。
6. 无硬件设计访问权,无法确定位模式底层机制(Obs. 10:"without access to the proprietary hardware design")。

**读出的坑:**
1. **样本规模与统计功效不对称**:400 SDC cases / 18 台向量 SDC 机器,很多结论(如 7/13 机器单一位翻模式)样本极小,无置信区间;Pearson -0.392 虽显著但解释力弱(R²≈0.15)。
2. **SDC Suspects 是有偏样本**:先经厂商测试+生产负载筛选,残余的是"难检"缺陷;用它代表舰队 SDC 模式存在幸存者偏差(论文只做了方向性辩护)。
3. **输入生成算法未披露**:每轮"不同输入"但 RNG/分布/种子策略全文未给出,复现的输入空间不可能一致;而 Obs. 19 证明 SDC 频率对输入值域敏感 245×,意味着输入分布本身就是最大未控制变量。
4. **无环境控制**:温度/频率只是被动记录(生产环境),非受控实验;电压、负载上下文、cache 状态均未控制。gather 近 0% 复现率(Obs. 7)正说明内存层级状态未控制。
5. **246 用例只覆盖 4 个指令集扩展**:没有 AVX-512(尽管 Fig. 4 讨论 256-bit),x86 侧覆盖不完整;Scalar/其它指令类别不在内,92% FMA 占比是"向量指令内"的占比,不是全指令占比。
6. **"100 万轮/逻辑核"对 <10⁻⁶ 频率的检出力不足**:10⁻⁶ 频率在 100 万轮中期望 1 次命中,P(漏检)=e⁻¹≈37%——低频 case 的数量被系统性低估。
7. **matmul 实验用 NumPy**:BLAS 后端未指名(MKL/OpenBLAS?),编译器/优化等级未知,而 Obs. 19 显示实现细节(指令选择)直接影响结果。
8. **两遍复现实验只覆盖 19 台机器**(Obs. 6),从 2500+ Suspects 中只有 18 台向量 SDC 机器(Obs. 12),统计基础薄弱。
9. 开源仓库空壳(实测),论文可复现性当前为零——所有数字均无法第三方验证。

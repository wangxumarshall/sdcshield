## 1. 研究问题与核心贡献(≤5 行)

自底向上(bottom-up)生成**老化相关 SDC 的运行时检测测试**:不把 CPU 当黑盒,而是从门级/netlist 的晶体管老化物理模型出发 → 老化感知 STA 找出易违时路径 → 形式验证生成周期精确激励 → 翻译成汇编测试用例(数百~数千周期可跑完)→ 融入应用程序运行时反复执行。在 RISC-V CV32E40P 的 ALU/FPU(28nm 综合布线)上演示:ALU 11 条/FPU 1,366 条老化易感路径,生成测试用例执行仅 124–1202 周期,平均性能开销 **0.8%**(§5.3),检测率 95.4–100%(Table 6/7)。对比:top-down 方法(Google SiliFuzz ~50 万测试用例、Intel DCDiag 全跑 45 分钟、Alibaba 每 3 个月才测一次)无法高频执行(§1)。

## 2. 实验方法(自底向上具体是什么;老化模拟方式;检测机制;输入)

### 2.0 论文自带的跑通示例(§3.1–§3.3,复现的最好"教学梯")

论文用 2-bit 流水加法器全程示例(复现时先做这个再上 CV32E40P):

- RTL(Listing 1):两级流水——第 1 拍采 aq/bq,第 2 拍 o <= aq + bq;
- netlist(Figure 3):10 个 cell:4×DFF($1–$4 输入寄存)、XOR$5/AND$6/​XOR$7/​XOR$8 组合逻辑、2×DFF($9/$10 输出);最小 cell 库(AND/XOR/DFF);
- 时序假设:AND/XOR/DFF 最大传播延迟 0.3ns、最小 0.1ns;DFF setup 0.06ns、hold 0.03ns;目标 1GHz(周期 1ns);
- 初始合规:最长路径 $4→$7→$8→$10 最大延迟 0.9ns(距 setup 约束 1−0.06=0.94ns 满足);最短路径 $1→$5→$9 最小延迟 0.2ns(> hold 0.03ns 满足);
- SP profile(Table 1):DFF$1.Q 0.85 / $2 0.54 / $3 0.38 / $4 0.27 / XOR$5 0.46 / AND$6 0.48 / XOR$7 0.13(最极端→BTI 压力最大)/ XOR$8 0.52 / DFF$9 0.44 / DFF$10 0.54;
- 老化后:$4→$7→$8→$10 累计 0.946ns > 0.94ns → setup 违例;另假设 DFF$1/$9 时钟相位漂移 → $1→$5→$9 hold 违例;
- trace 生成(Table 2):C=1 时 3 拍输入序列(a=01,11,11;b=11,00,01),第 3 拍 o_s[1]='b1 ≠ o[1]='b0 → cover property 命中。

### 2.1 三阶段工作流(Fig. 2,§3)

**Phase 1 Aging Analysis(老化分析)**:
1. **Signal Probability (SP) 仿真**:对布线后 netlist 的每个 cell 输出口挂计数器(记录逻辑 0/1 出现次数),计数器由 Vega 自己生成的独立自由运行时钟驱动(电路时钟暂停也照样计数);用 HDL 仿真器跑**代表性负载**集合,得到每个 cell 的 SP profile(SP = 停留在逻辑 1 的时间占比)(§3.2.1,Table 1 示例:XOR$7.Y SP=0.13 最极端 → BTI 压力最大)。时钟树中每个 clock buffer 单独画像(真实 SP profile)。SP 刻画 BTI 应力:晶体管长期静止在恒定状态更易老化;pMOS 比 nMOS 更易受 BTI,故常闲置在 "0" 的门比闲置在 "1" 或常翻转的更快老化(§2.3.1)。
2. **老化感知 STA(Aging-Aware Static Timing Analysis)**:先用 **SPICE 对标准单元库逐 cell 做模拟仿真**,生成"老化感知时序库"——每个 cell 在不同 SP 下、经一段时间后的最大/最小传播延迟变化(同一 cell 库可复用,预计算加速;Fig. 4 为 28nm XOR cell 10 年期、SP 0.2–1.0 下开关延迟退化 2%–6% 的库条目示例)。再按 SP profile 查库更新 netlist 时序,跑 STA 找**老化后违时路径**(§3.2.2)。寿命假设 **10 年**(任务关键系统常用);同时分析老化对时钟分配网络的影响(相位漂移 → hold 违例)。STA 采用代工厂要求的最悲观条件(电压降/工艺波动/片上波动/温度)——宁可误报,不漏真实失效路径(§3.2.2)。

**Phase 2 Error Lifting(错误提升)**:
3. **时序违例的逻辑模型**:形式验证只管逻辑域,不管时序——所以把 setup/hold 违例的**效果**形式化(§3.3.1,式 2/3):
   - setup 违例(路径 X⇝Y,信号到得太晚):Y(t+1) = Y_original(t+1),若 X(t)=X(t−1)(路径值未变,即使迟到也采样正确);否则 = C(采错值,C 为常数 0 或 1,分开两轮验证)。
   - hold 违例:Y(t+1) = Y_original(t+1),若 X(t)=X(t+1);否则 = C。路径起终点同触发器时 Y 恒为 C(亚稳态)。
4. **Failure Model 插桩**:用 MUX cell 把上述逻辑模型织进 netlist(§3.3.2,Fig. 5 setup/Fig. 6 hold 示例;DFF $12 保存 X 上一拍值以算 X(t)=X(t−1))。两种模式:(a) 直接产出**failing netlist**(描述老化后电路行为的 Verilog,可综合到仿真/FPGA,即**电路级失效模型**——用于验证测试用例有效性,也是本文交付的失效模型集);(b) 为 trace 生成做**影子副本(shadow replica)**:静态分析找出所有可能被 Y 影响的 cell(含 Y 自己),复制之,失效模型接入影子副本,影子输出接影子线(如 o_s[1])。
5. **形式验证 trace 生成**:写 cover property(如 `cover property (@(posedge clk) o[1] != o_s[1]);`)交给硬件形式验证工具(JasperGold),求出能让影子输出 ≠ 原输出的**周期精确模块级输入序列**(waveform,Table 2 示例:3 拍输入 a/b 序列,第 3 拍 o_s[1] 与 o[1] 分叉)。可用 assume property 限定输入域防不现实 trace(需开发者懂微架构,如限定 ALU 只接受合法操作码)(§3.3.3)。选形式验证而非 fuzzing 的理由:系统化探索冷门组件、可**证明**某故障不可能在模块内造成逻辑不一致(fuzzing 无法排除)(§3.3 开头)。
6. **初始值依赖缓解**:形式工具假设电路已被完美复位,真实执行中前一指令可能改变初始值使 trace 失效——可配置失效模型仅在 X 值出现上升/下降沿时激活(¬$12.Q ∧ $4.Q / $12.Q ∧ ¬$4.Q)(§3.3.4)。
7. **指令构造(Instruction Construction)**:把模块级 I/O 波形翻译成汇编测试(§3.3.5)。**最费人力的环节,每个 (µArch, 硬件组件) 组合只需做一次**:开发者凭对"每条指令如何激活组件内信号"的了解写查找表脚本(信号激活 ↔ 指令),有时还需把常量映射到特定寄存器。测试所需的输入寄存器值/期望输出寄存器值在本步确定,寄存器分配推迟到 Phase 3。

**Phase 3 Test Integration(测试集成)**:
8. **软件老化库**:测试用例合成一个 C 文件,标准 inline 汇编格式,寄存器用变量表示;生成编译支持文件、辅助函数、各语言 wrapper;支持顺序/随机调度执行;支持异常的语言可配置测试失败即抛异常,由调用栈内 catch 块处理(§3.4.1)。
9. **Profile-Guided 自动集成**:给应用插计数器(基本块粒度),跑代表性输入采 profile,找"不频繁但会被例行访问"的位置嵌入测试;比较嵌入前后 IR 指令数估算开销,超过用户阈值则以一定概率触发测试,细粒度控制频率(§3.4.2)。

### 2.2 老化物理模型(§2.3.3,式 1)

- 反应-扩散模型(reaction-diffusion),描述 BTI 引起的阈值电压漂移:ΔVth ∝ e^(Ea/kT) · (t−t0)^(1/6)。Ea = 工艺相关常数,T = 工作温度,k = 玻尔兹曼常数,t−t0 = BTI 应力持续时间。
- **退化前置**:10 年寿命内的 ΔVth 退化约 **70% 发生在第 1 年**(§2.3.3)。应力移除后部分退化可恢复(类似方程量化)。
- 模型已经过近期工艺节点流片硅验证,可信(§2.3.3)。
- setup vs hold(§2.3.2,Figure 1):setup 违例可降频解决;**hold 违例降频无效,必须修芯片**,更严重。clock gating 使时钟网络各区域 BTI 应力不均 → 老化不均(§2.3.1)。

### 2.3 检测机制(测试如何判错)

- 每个测试用例 = 一小段汇编:设定输入寄存器 → 执行目标指令序列 → 与**期望输出寄存器值**比对(由指令构造阶段从波形推导)。失败即检出老化故障(库模式可抛异常)。
- 测试对 failing netlist 的检测有效性验证见 Table 6;另有 CPU stall 型失效(ready/valid 握手信号坏 → 应用不推进/不响应中断 → 从软件视角可检出)(§5.2.3)。

### 2.4 与自顶向下方法的对比实验(§5.2.3,Table 7;§6.1)

- 论文明确不与 SiliFuzz/OpenDCDiag 直接对比的三个理由(§6.1):方法论与目标不同难以直接比框架效用;把架构专属测试框架移植到其 RISC-V CPU 负担大;定位本就是正交工具(嵌入式连续监控 vs 维护窗口广覆盖)。
- **建议组合模式**(§6.1):数据中心运营商用 Vega 把定向测试嵌进软件做连续监控 + top-down 长测试套件在常规维护周期跑更广覆盖——SDCShield(离线广覆盖)+ 新"嵌入式微探针"(若做)恰好是这个组合的 ARM64 实例化。

### 2.4.1 环境噪声讨论(§6.2,复现者须知)

- Aging Analysis 用最坏情况温度/电压假设 → 可能**高估**硬件故障(误报);更精细的真实供电/温度分析可消除假阳性。
- 数据中心现行缓解:测试重复、高频执行、小心变化相关物理条件下执行(引 SOSP23/Meta)——Vega 测试短,天然适合"及时测试、缩小测试与代码执行间的环境方差"。

### 2.4.2 未来方向(§6.3,研究空白清单)

- Aging Analysis 扩展到动态 IR drop、电迁移(EM)等(同样有门级模型);
- Error Lifting 换随机/fuzzing 快速探索 + 基于 Aging Analysis 洞见的过滤;
- Instruction Construction 用程序合成/机器学习自动化(消人力瓶颈);
- 商业化配置:芯片厂商生成测试套件 + 云运营商回馈现场 trace/统计,厂商精化 Aging Analysis 生成定制套件。

- **基线**:自实现的**随机测试生成器**——按 Vega 测试的样式和数量生成(每个用例用随机输入验证当前模块指令集中**一条随机指令**的功能正确性);每个 (模块 × 失效模型 C∈{0,1,R}) 跑 **10 次实验**,取平均检出率(Table 7)。
- 论文未与 SiliFuzz/OpenDCDiag 直接对比:**架构不通用,移植到其 RISC-V CPU 负担大,难以直接比框架效用**(§6.1);定位为正交工具——Vega 嵌入软件做连续监控,top-down 长测试在维护窗口跑广覆盖。

## 4. 实验步骤(可操作流程)

补充关键实验配置细节(§5.1 原文):

- failing netlist 三模式的意义:C=0/C=1 对应失效路径终点触发器"卡死采 0/采 1"两种确定性老化表现;C=R(每拍随机)模拟最不利的非确定采样(亚稳态反复)——检验测试在不确定故障显形下的鲁棒性;
- 仿真加速决策:仅 ALU/FPU 用布线后 netlist(Verilator 精确时序),CPU 其余部分保持 SystemVerilog 行为模型——平衡精度与速度;SDCShield 侧的对应物是"只把被测指令序列精确化,其余环境粗粒度";
- embench 既当 SP 仿真代表性负载(§3.2.1 用)又当开销评估基准(§5.3 用)——一个负载集两用,复现时可照此省一半工作。

1. 取 CV32E40P 的 ALU/FPU RTL(SystemVerilog),用 Genus/Design Compiler 综合到 28nm cell 库,Innovus 布局布线,得门级 netlist(目标 167/250 MHz);
2. SP 仿真:netlist 每 cell 输出挂 0/1 计数器(独立自由时钟驱动),HDL 仿真器跑 embench(尤其 minver)负载,聚合出 SP profile;
3. SPICE 预计算老化感知时序库:每 cell × 各 SP 档 × 10 年 → 延迟退化;
4. 老化感知 STA:查库更新时序 + 最悲观条件,扫出 10 年后违时路径(setup + hold,含时钟网络相位漂移);
5. 对每条违时路径(按起终点对去重)建逻辑失效模型(MUX 插桩,setup: X(t)=X(t−1) 保持正确否则 C;hold: X(t)=X(t+1);C∈{0,1} 两轮);
6. 影子副本插桩 + cover property(`o != o_s`)交给 JasperGold 求 trace;必要时 assume 限定输入域;可选边沿触发缓解初始值依赖;
7. 指令构造:微架构查找表把波形翻译成汇编序列 + 期望寄存器值(人力一次性成本);
8. 测试集成:生成软件老化库(C + inline asm + wrapper)或 LLVM profile-guided 嵌入 embench 应用;
9. 有效性验证:对每条 failing netlist(C=0/1/R 三模式)运行整套测试,统计 Det./B/L/S 分类(Table 6);
10. 对比基线:随机测试生成器(同数量同风格,10 次平均)在同一 failing netlist 上跑,比检出率(Table 7);
11. 效率评估:embench 19 基准 × 8 种配置(ALU-N/M、FPU-N/M、ALL 系)测执行时间开销(Figure 9)。

### 5.1 老化易感路径(§5.2.1,Figure 8,Table 3)

- 老化致延迟增量分布(Fig. 8,ALU+FPU 合并):**52% 的 ALU cell / 35% 的 FPU cell 延迟 +6.0%**;**35%(ALU)/25%(FPU)+1.9%**;其余 cell 在 2.2%–5.7% 之间(柱序列 6.0/5.7/5.3/5.0/4.2/3.7/2.7/2.3/2.2/1.9%)→ 老化退化在 cell 间**非均匀**。

### 5.2 测试用例构造成功率(Table 4,§5.2.2)

| 单元 | w/o 缓解:S | UR | FF | FC | w/ 缓解:S | UR | FF | FC |
|---|---|---|---|---|---|---|---|---|
| ALU | **66.7%** | 33.3% | 0 | 0 | 33.3% | 66.7% | 0 | 0 |
| FPU | **51.2%** | 43.9% | 4.9% | 0 | 40.2% | 43.9% | 8.5% | 7.3% |

- S=成功构造;**UR = 形式验证"证明"该失效路径不可能造成实际错误**(ALU 33.3%/FPU 43.9% 的对被证明永不触发——这是 fuzzing 给不了的);FF=形式验证超时;FC=有波形但无法转测试(FPU 特有:需多指令才能传播到输出,唯一可观测错误输出是状态标志(如溢出位),且已被前一条指令改变,无法比对)。
- 产量:无缓解每对最多 2 个测试(C∈{0,1});有缓解最多 4 个(加上升/下降沿两种)。

### 5.3 测试规模(Table 5,§5.2.2)

| 单元 | w/o 缓解:用例数 / 周期 | w/ 缓解:用例数 / 周期 |
|---|---|---|
| ALU | **8 / 124** | 8 / 134 |
| FPU | **42 / 685** | 66 / 1202 |

### 5.4 检测有效性(Table 6,§5.2.3;对 failing netlist)

四分类的实验含义(原文定义,复现时照抄语义):

- **Det.**:整套测试中至少一个用例检出该失效(= 该失效可检);
- **B**:在"为该失效设计的用例"执行**之前**,就被套件中其它(靠前的)用例检出——衡量套件冗余/前置覆盖;
- **L**:自家用例漏检,但被**后续**用例检出——漏检兜底;
- **S**:失效使 CPU 挂死(ready/valid 握手坏等),应用不推进/不响应中断——软件侧可判定。

文中实例:两例 S 类(失效在 ready/valid 握手信号上,CPU 等待永远无法送达的数据);一例全套漏检(初始信号值依赖,前序指令改写;缓解后 C 固定可检出,C 随机仍漏 1 例)。

| 单元 | FM | 无缓解:Det. / B / L / S | 有缓解:Det. / B / L / S |
|---|---|---|---|
| ALU | 0 | 100.0 / 50.0 / 0 / 0 | 100.0 / 50.0 / 0 / 0 |
| ALU | 1 | 100.0 / 75.0 / 0 / 0 | 100.0 / 50.0 / 0 / 0 |
| ALU | R | 100.0 / 75.0 / 0 / 0 | 100.0 / 50.0 / 0 / 0 |
| FPU | 0 | 95.4 / 72.7 / 4.5 / 9.1 | 100.0 / 72.7 / 0 / 9.1 |
| FPU | 1 | 95.4 / 81.8 / 9.1 / 0 | 100.0 / 81.8 / 4.5 / 0 |
| FPU | R | 95.4 / 72.7 / 4.5 / 9.1 | 95.4 / 72.7 / 4.5 / 9.1 |

- Det.=整套测试可检出;B=**在"为它设计的测试"执行之前就被别的测试先行检出**(50–81.8%,非常普遍);L=自家测试漏检但被后续测试捡回;S=失效致 CPU stall(应用不推进/不响应中断,软件侧可检出)。
- 唯一漏检案例:某失效测试依赖特定初始信号值,被前一条指令改掉;有缓解(C 固定时)可检出;**C 每拍随机时仍漏 1 例**(4.5%,FPU R 行)(§5.2.3 末)。

### 5.5 Vega vs 随机测试(Table 7,§5.2.3;10 次实验平均)

| 单元 | FM | Vega | Random |
|---|---|---|---|
| ALU | 0 | **100%** | 50.0% |
| ALU | 1 | **100%** | 50.0% |
| ALU | R | **100%** | 45.0% |
| FPU | 0 | **100%** | 35.3% |
| FPU | 1 | **100%** | 95.4% |
| FPU | R | 95.4% | **97.2%**(反超!) |

- FPU C=1/随机时随机测试也能到 95.4–97.2%(FPU 路径大多随便一条相关指令就能踩中);但随机法**没有"证明某故障永不发生"的能力**(UR)(§5.2.3 末)。

### 5.6 运行时开销(Figure 9,§5.3)

- 19 个 embench 基准 × 8 种启用配置:ALU-N(仅 ALU 无缓解测试)、ALU-M(仅 ALU 有缓解)、FPU-N、FPU-M、ALU-ALL(N+M)、FPU-ALL、ALL-N、ALL-M、ALL(全部)。开销区间 **−5% 到 +10%**,多数基准落在 ±2–3%;**平均 0.8%**。
- 负开销出现:插桩意外触发编译器优化等环境噪声与真实开销不可区分(§5.3)。
- 结论:profile-guided 集成把开销控制在可忽略量级,支撑"高频执行"叙事。

- embench 19 基准 × 8 配置(ALU-N/M、FPU-N/M、ALU-ALL、FPU-ALL、ALL-N、ALL-M、ALL),开销 −5% 到 +10% 区间,多数在 ±2% 内;**平均 0.8%**;部分为负开销(编译器优化被插桩意外触发等环境噪声,无法与开销区分)(§5.3)。

### 5.7 背景引用数字(§1/§2.1,来自其引用文献,复现引用需回原文献)

- SiliFuzz 生成 ~500,000 测试用例(§1);DCDiag 完整执行 45 分钟(§1);Alibaba 每 3 个月测一次(§1, §2.1,引 SOSP23)。
- Alibaba 数据:73.5% 的 SDC 出现在已用过的 CPU(重装 63.9% + 生产 9.6%)(§2.1,引 SOSP23——与 SOSP23 Table 1 数字自洽)。
- 老化物理:10 年退化的 70% 发生在第 1 年(§2.3.3)。

## 6. 实验结论(编号)

关键 takeaway(§2 各小节末,设计动机三连):

- Takeaway #1(§2.1):提高 SDC 测试频率 → 更及时检测;缩短测试执行时间 → 高频测试可行。
- Takeaway #2(§2.2):硬件不是黑盒——实现细节可指导 SDC 检测;经验证的物理模型驱动一系列分析。
- Takeaway #3(§2.3):SP profile + 老化感知 STA 可定位易违时元件 → 产出测试用例的有效靶点。

1. 正确布线、初始满足时序的 ALU/FPU,10 年老化后仍会产生大量违时路径(WNS −76ps/11 条 ALU,−157ps/1,366 条 FPU;去重 6/41 起终点对)——老化是 SDC 的可信来源且可在设计期预判(§5.2.1)。
2. 老化退化非均匀(cell 间 1.9%–6.0%),SP profile + 老化感知 STA 能定位最脆弱路径(§5.2.1)。
3. 形式验证可把相当比例(ALU 33.3%/FPU 43.9%)的"理论违时"**证明为不可能造成实际错误**(UR),天然过滤假阳性;这是 top-down/fuzzing 做不到的(§5.2.2)。
4. 自底向上测试极小(整套 124–1202 周期),可嵌入应用运行时高频执行;平均开销 0.8%(§5.2.2, §5.3)。
5. 生成的测试检测率 95.4–100%;跨测试"提前检出"(B 类)普遍(最高 81.8%),漏检可被后续测试捡回;唯 C 每拍随机时 FPU 仍漏 4.5%(§5.2.3)。
6. 对 ALU 全面碾压随机测试(100% vs 45–50%);对 FPU 大多数场景胜出,但 C=1/R 时随机测试接近甚至反超(95.4–97.2%)——bottom-up 的独特价值在"证明不触发"而非检出率本身(§5.2.3)。
7. Vega 与 SiliFuzz/OpenDCDiag 是**正交**工具,不直接对比;建议组合使用(Vega 常驻 + top-down 维护窗口广覆盖)(§6.1)。
8. 环境噪声(电压/温度)在 Aging Analysis 用最悲观假设可能高估故障;可用测试重复/高频执行/受控变化物理条件缓解——短测试时长天然有利于此(§6.2)。

## 7. 复现要点(ARM64 单机/小集群最小可行版本)

### 7.0 最小可行实验包(SDCShield 直接动作)

1. **"结构化 vs 随机"对照协议复刻**:对每个新激发测试(如 sve512 FMA 链),实现同款随机基线(同数量同风格、单随机指令 + 随机输入),在注入故障(golden 上注入 C=0/1/R 三模式位错误)上各跑 10 次取平均检出率——产出 Table 7 同构数据。这是证明"设计 > 随机"的最低成本硬实验。
2. **Det./B/L/S 四分类统计**:同一注入故障上跑 SDCShield 测试全集,统计"哪个测试检出/是否被更早测试检出/漏检后被捡回/挂死"——产出 Table 6 同构数据,论证测试集编排鲁棒性。
3. **微探针原型**:挑 3–5 条关键指令序列(SVE FMA、原子、CRC),做成 < 10⁴ 周期的自检探针 + 定时触发,测其常驻开销(对标 0.8% 平均开销基线)。

### 7.1 可直接复用

- **"短测试 + 高频执行"的设计哲学**:整套检测数百~数千周期、嵌入应用/每秒执行——SDCShield 可对标做"秒级 micro-probe"(把关键 FMA/SVE 指令序列做成 sub-ms 级可重复探针,常驻运行);这正是与 SOSP23(2 周一轮)和 OpenDCDiag(45 分钟)对比的最强叙事轴。
- **B/L 跨测试检出统计法**(Table 6 的 Det./B/L/S 四分类):对任意测试套件都可统计"测试 i 的故障被测试 j<i 提前检出"的比例——衡量测试集冗余度/鲁棒性的现成协议,SDCShield 279 测试可直接套用(在注入故障或已知故障机上)。
- **随机测试基线协议**:同数量同风格、单随机指令 + 随机输入、10 次平均——新激发实验(如结构化 FMA 激发)与随机生成的对照实验设计可直接照搬,是"我们的结构化设计 > 随机"论证的标准模板(注意其 FPU R 场景随机反超的教训:必须分场景报告)。
- **失效模型验证法**(failing netlist 三模式 C=0/1/R):单机无门级 netlist 时可用**软件级故障注入**模拟同一谱系(在 SDCShield 里对 golden 计算注入位翻转/卡死值,跑测试集统计检出率)——方法学等价,保真度降低。
- **SP/BTI 思路的知识复用**:不常翻转的信号/单元老化更快 → "冷路径指令"应当显式激发(对应 SDCShield:补齐罕用指令/罕用数据模式的测试,恰是现有缺口,与 D-tests 盘点的覆盖矩阵互补)。
- **老化前置规律**(第 1 年完成 10 年退化的 70%):为"新机器 early-aging burn-in 实验"提供理论依据——短时间高频 burn-in 后立即测试,性价比最高。
- **引用数字复用**(作为 related work 基线):DCDiag 45 分钟、SiliFuzz 50 万用例、Alibaba 3 个月/轮、73.5% 在用机检出。

### 7.2 需替代/不可行

- **门级/netlist 分析本体(SPICE 建库、Innovus STA、JasperGold 形式验证)**:对商用 ARM 芯片(Kunpeng 920)完全不可行——无 netlist、无 cell 库、无 EDA 授权。替代路线:(a) 开源 RISC-V core(Applied:CV32E40P/香山/BOOM)照原文流程可完整复现,但那是"复现论文",不是"为 SDCShield 论证";(b) 软件级模拟老化效应(降频/降压/升温逼近时序边界——注意原文**没有做** FMAX/电压扫描,见下)。
- **FMAX/电压扫描实验**:用户预期中的"电压扫描"在本文**不存在**——Vega 无任何频率/电压扫描实验(FMAX 仅以 167/250MHz 目标频率出现;温度只在 §6.2 定性讨论)。需要该轴的复现须另找文献(如 Agiakatsikas MICRO-56 电压缩放软错误、SOSP23 温度扫描)或自建:SDCShield 可做 `cpufreq` 不可用(该板)→ 用温度轴(burn-in + stress)替代,或在可调频开发板(树莓派/RVK64 FPGA)上做 ARM 电压/FMAX 扫描。
- **LLVM profile-guided 嵌入 SDCShield 测试**:可行但价值存疑(SDCShield 是独立检测工具,不是应用内嵌库);若做"应用内联探针"变体则直接复用其思路。
- **Verilator/CV32E40P 仿真环境**:开源可得,可完整复现——但对 ARM64 生产芯片检测的论文叙事贡献有限,只适合作为方法学对照。
- **embench 负载集**:嵌入式 IoT 基准,对服务器芯片代表性弱;SDCShield 已有更贴云负载的测试(zstd/eigen/openssl),保留思想(代表性负载驱动 SP)即可。

## 8. 作为对比基线的价值(可测对比轴 + 论文基线数值)

补充轴:

8. **失效谱系覆盖轴**:论文基线 = setup(11+1,363 条)/hold(0+3 条)/ stall(S 类)三类失效均被考虑;SDCShield 新实验设计故障模型时应至少覆盖"恒错值 + 随机错值 + 挂死"三形态,并报告各自检出率——对标其 C=0/1/R + S 的谱系完备性。
9. **形式可证排除轴**:论文基线 = UR 占 33.3%(ALU)/43.9%(FPU)。SDCShield 无法做形式验证,但可用"数据模式穷举 + 等价类划分"证明某类缺陷在给定测试输入域不可达——弱化但可辩护的版本;或明确承认该轴为 Vega 独有,聚焦其它轴的优势。

1. **测试时长/频率轴**:论文基线 = 整套 124–1202 周期(ALU/FPU),可秒级执行;vs DCDiag 45 分钟、Alibaba 3 个月/轮。SDCShield 新实验若声称"高频可复用探针",直接与 124–1202 周期对标;若声称"深度激发",则与 45 分钟/2 周对标并论证单位时间检出增益。
2. **检出率 vs 随机基线轴**:论文基线 = Vega 100/100/100/100/100/95.4 vs Random 50.0/50.0/45.0/35.3/95.4/97.2(ALU/FPU × C=0/1/R)。SDCShield 新激发实验必须做同款"结构化 vs 随机"对照;FPU R 场景随机反超的教训 = 分场景报告,防止审稿人用单一场景否定。
3. **可证明性轴(UR)**:论文基线 = 33.3%(ALU)/43.9%(FPU) 的违时路径被形式方法证明不可触发。ARM64 侧无法完全复现,但可用"穷举数据模式覆盖证明某故障模式不可达"的弱化版本,或在 gem5/QEMU 功能级做可判定性检查。
4. **运行时开销轴**:论文基线 = 平均 0.8%(profile-guided 嵌入)。任何"应用内联检测"设计都以此为黄金标准。
5. **失效模式谱系轴(C=0/1/R)**:三模式失效模型是故障注入实验设计的现成模板——恒 0、恒 1、随机值三种卡死行为;SDCShield 注入实验照此分桶报告检出率。
6. **老化工学曲线轴**:第 1 年完成 70% 退化(10 年口径)——设计"加速老化后立即测试"实验(burn-in 时长 vs 检出率曲线)时的理论锚点。
7. **跨测试提前检出(B)轴**:基线 = B 占 50–81.8%。SDCShield 可测其测试集对已知故障的 B 比例,论证测试编排(顺序)的鲁棒性——高 B = 单测失效不影响整体检出,是"测试集级"优于"单测级"的论据。

## 9. 局限与坑

复现者最常踩的坑(基于本文实验设计逐条推出):

- **把"检测率 100%"外推到真机**:Table 6/7 的分母是 failing netlist(人工失效模型),不是物理老化芯片;任何"我们也能检出老化"的表述都需要至少一个真实老化样本(老机器/高温长期 burn-in 后)佐证。
- **忽略 in-order 32 位核与现代超标量的差距**:CV32E40P 无乱序、无宽向量、无多核;其"每模块形式验证 + 微架构启发式"流程在乱序核上会因模块间交互爆炸而失效(论文自己只做 ALU/FPU 单模块)。
- **复现时丢掉独立自由运行时钟的 SP 计数器**:电路时钟被门控暂停时计数器也停 → SP 统计系统性偏差(clock gating 正是老化不均的来源之一)。
- **C=R 模式不可省**:只测 C=0/1 会高估检测率(FPU R 模式 95.4% < 100%);随机显形是真实老化的常态。

- **未上真实老化硬件**:全部有效性实验在 failing netlist(仿真失效模型)上做,**没有真实老化的物理芯片、没有电压/温度/FMAX 扫描**——"老化真实发生"与"测试检出真实老化"之间隔着模型保真度;论文承认最悲观 STA 可能高估(§6.2)。复现时切勿把"对 failing netlist 100% 检出"表述为"能检出真实老化 SDC"。
- **无商用 CPU 验证**:仅在 28nm 开源 RISC-V in-order 核(167/250 MHz)上演示;乱序超标量、宽向量(SVE 512-bit)、多核一致性等现代特性未覆盖——ARM64 服务器场景外推性存疑。
- **一致性型 SDC 缺位**:只做 ALU/FPU(计算型);cache 一致性/多线程冲突(SOSP23 的 8/27 一致性型缺陷)完全不在范围。
- **指令构造的人力瓶颈**:每 (µArch, 组件) 一次性手写查找表脚本(§3.3.5 自认"最费人力");扩展到 ARM 全 ISA 的工作量被低估风险高。
- **随机基线在 FPU 某些模式下反超**(97.2% vs 95.4%):bottom-up 的净收益主要在 UR 可证明性与 ALU 类逻辑密集单元;对数据通路单元,结构化优势收窄——写对比论文时必须诚实分场景。
- **FC 类不可转换**(FPU 7.3%):错误只能通过状态标志观测且被前序指令污染 → 需要指令序列上下文的检测设计(这正是"序列化/上下文敏感激发"的论据,可被 SDCShield 新实验利用)。
- **profile-guided 嵌入的负开销噪声**:开销测量被编译器优化噪声污染(负值出现),0.8% 均值在小样本下不稳;复现开销实验需多次重复 + 统计检验。
- **10 年寿命假设与最悲观 STA 叠加**:双重保守 → 违例路径数(尤其 FPU 1,363 条)可能显著高估;引用 WNS/路径数时注明这是悲观上界口径。
- **引用数字的传递性**:DCDiag 45 分钟、SiliFuzz 50 万用例、Alibaba 73.5% 等均为二手引用(标 §1/§2.1),正式写作时应回引原始文献(SOSP23 / SiliFuzz arXiv)核对。

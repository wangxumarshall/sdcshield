- 作者:Manolis Kaliorakis、Dimitris Gizopoulos(University of Athens);Ramon Canal、Antonio Gonzalez(Universitat Politecnica de Catalunya)
- Venue:ISCA '17, June 24–28, 2017, Toronto, pp. 241–254,DOI: 10.1145/3079856.3080225

- MeRLiN = Microarchitectural evaluation of Reliability using statisticaL fault iNjection

## 1. 研究问题与核心贡献(≤5 行)

微架构级统计故障注入(SFI)测 AVF 准确但 campaign 太长(6 万注入起步);ACE 分析快但悲观(高估 AVF 3–7×)。MeRLiN 用"动态指令重复"性质把初始故障列表按等价类分组、每组只注入少量代表,实现 **2–3 个数量级加速且精度不损**:MiBench 全跑平均加速 93×(RF 256 项)/225×(SQ 64 项)/68×(L1D 64KB),SPEC CPU2006 Simpoint 上 1644×/2018×/171×。附理论证明:分组估计量与全量 campaign 的 AVF 均值相同、方差同为极小。

## 2. 实验方法

### 2.1 三阶段流程(Fig. 2)

**阶段 1 预处理(单次跑)**:
- ACE-like 分析:负载跑一遍,记录目标结构每个表项的全部"脆弱区间"(vulnerable interval):
  - 定义 a:从一次写操作开始、到同表项的一次**已提交读**结束;
  - 定义 b:从一次已提交读到另一次已提交读结束。
  - 与经典 ACE 的区别:经典 ACE 中间读不结束区间,MeRLiN 切分(总脆弱时间相同,Fig. 3 示例);wrong-path 指令不计入;
  - 每区间记录:(i) 起止周期、(ii) 结束区间那条 x86-64 静态指令的 RIP、(iii) 读该表项的微操作的 uPC(x86 指令可拆多 uop,同一指令不同 uop 访问不同表项/周期,须分开分类);
  - 存储开销 10–100MB;单次跑 <5 小时(全部实验);
- 初始故障列表:按 Leveugle [26] 统计采样,由 (1) 结构位数、(2) 程序总执行周期、(3) 置信度、(4) 误差界决定。本文基准 campaign = **60,000 故障**(99.8% 置信、0.63% 误差);对照:2,88%/99% 只需 2,000。可扩展实验用 600,000(0.19% 误差)。

**阶段 2 故障列表削减(两步分组,单次跑 <50 分钟)**:
- 第 1 步:初始列表中命中非脆弱区间的故障直接判 Masked(免注入);其余按 (RIP, uPC) 二元组分组——同组故障可在不同表项、不同脆弱区间,只要区间末端的读指令是同一静态指令同一微操作;
- 第 2 步:组内按**字节位置**再分组(逻辑掩蔽使同表项不同位效果不同);命中不同字节的代表从同一静态指令的**不同动态实例**选取(增加时间多样性);可细分到 nibble/位但实验证明不必要。大组(静态指令关联故障多)保证每组多个代表、覆盖所有字节位置。

**阶段 3 注入 campaign**:只注入 reduced fault list 中的代表;结果与黄金运行比对,按组回填整个组的效应,计算最终 AVF。

### 2.2 故障效应六分类(表 2)

| 类别 | 判据 |
|---|---|
| Masked | 输出与 x86 异常均与黄金运行一致 |
| SDC | 输出损坏,但模拟进程与 x86 异常无异常行为 |
| DUE | 进程与输出未损坏,但出现额外 x86 异常指示 |
| Timeout | 程序流死锁(不再提交)或活锁(重定向但持续提交),超基准执行时间 3 倍 |
| Crash | 进程/全系统/模拟器崩溃 |
| Assert | 模拟器因 assert 停机 |

### 2.3 同质性度量(式 1)

homogeneity = Σ(各组 #faults × dominant_class%) / #total_faults × 100%。dominant_class% = 组内最大类占比。值越接近 1.0 分组越纯。

## 4. 实验步骤(可操作流程,编号)

1. gem5 x86-64 OoO(表 1 配置)+ full-system 跑目标基准一遍,profiling 全部脆弱区间(写→提交读 / 提交读→提交读),记录 (起止周期, RIP, uPC);
2. 按 [26] 生成 60,000 故障的初始列表(均匀:结构位 × 周期);
3. 剔除命中非脆弱区间的故障(直接计 Masked);
4. 剩余故障按 (RIP, uPC) 分组 → 组内按字节位置二次分组 → 每组选代表(不同字节 × 不同动态实例),生成 reduced fault list;
5. 只对代表故障逐个注入并跑完程序,六分类;
6. 组内回填:组内全部故障继承代表的分类;ACE-like 剔除的继承 Masked;
7. 统计 AVF = 非掩蔽注入 / 总注入;FIT = AVF × 0.01 × 结构位数;
8. 对照 campaign:同一负载同一结构全量 60,000 注入(不削减),比较六分类分布与 FIT;
9. 换 3 种结构尺寸重复;MiBench 全跑求精度与加速比;SPEC Simpoint 只求加速比;
10. 同质性统计(式 1)验证分组纯度;600K 列表重跑验证扩展性。

## 6. 实验结论(编号列出)

1. SFI 精度 + 近 ACE 速度可兼得:微架构级 SFI 加速 2–3 个数量级(MiBench 43.7–224.9×,SPEC 171–2018×)而不损精度。
2. 动态指令重复是分组依据的核心程序性质;同静态指令(RIP+uPC)读出的同字节故障几乎必然同效应(六分类同质性 0.88–0.98,完美组 ~90%)。
3. ACE-like(不追 TDD 的轻量分析)可安全剔除非脆弱区间故障——这步本身贡献 3.3–16.9×(RF)等削剪。
4. MeRLiN 与 60K 全量 campaign 的六分类/FIT 差异可忽略(最大单格 ~1 个百分点级;SPEC 上 1.11 百分点);而 ACE 类方法对 L1D 的 AVF/FIT 高估可达 3 个数量级。
5. 列表越大加速越高(600K 时平均加速再 ×3.46):MeRLiN 的收益随统计显著性要求提高而增长。
6. Relyzer 软件层启发式(def-use、control-equivalence、bounding addresses)不适用微架构级(bounding addresses 内存不可承受;def-use 在物理寄存器层面无意义);其单 pilot 策略在大组上精度差。
7. 结构尺寸效应(附带观察):RF 越小 AVF 越高(2.56%→8.92%,64 项);L1D 的 SDC 份额远高于 RF/SQ(L1D ~15–20% SDC vs RF ~0.5–1.5%)——与 TC'23 Fig.3(L1D data 最易 SDC)一致。

## 7. 复现要点(gem5/ARM64 复现最小版本)

### 可直接复用

- **三阶段算法 + 两步分组**:纯算法,可在任何能输出提交级 trace 的模拟器上实现;
- **(RIP, uPC) → ARM64 等价 (PC, 指令实例)**:ARM64 指令定长、绝大多数不拆 uop,分组键退化为 (PC, 表项访问序号),比 x86 更简单;
- **同质性度量与理论分析**:照抄;统计验证框架(式 1 + 方差推导)可用于任何"分组等价"类新方法的自证——SDCShield 若提出新的激发实验分组/采样策略,可直接复用这套评估方法学;
- **六分类表**:SDC/DUE/Timeout/Crash/Assert/Masked 比三分类更细,SDCShield 报告格式可借鉴;
- **基准 campaign 规模经济学**:60K = 0.63%/99.8% 的对应关系、200 月 → 2.42 月的对照叙事,是任何"我们的方法更快"类论文的模板;
- **gem5 commit trace + 脆弱区间 profiling**:用 gem5 ExecAll/Commit trace 后处理可提取"写-提交读"区间;存储 10–100MB/负载的量级说明工程可行。

### 需替代/不可行

- **GeFIN 不开源**(同 E23/E24/E25);脆弱区间 profiling 需要访问 gem5 O3CPU 的 rename/RF 生命周期事件,要自写 probe(RF 写/读在 `PhysRegFile` + commit 的 `renameMap` 处挂钩;SQ/L1D 在 LSQUnit/cache 处挂钩——工作量中等,一次写好三结构复用);
- **x86 uPC 维度在 ARM64 消失**(好事,简化);
- **60K 全量对照 campaign 是精度验证的必要成本**:复现"精度不损"结论必须跑至少一个配置的全量对照(建议挑最小:RF 64 项 × 2 个短 MiBench,60K × 2 次 ≈ 数天级);
- **SPEC Simpoint 基准集**:Simpoint 权重样本生成流程可照搬(Simpoint 工具开源);
- **机器规格差异**:2017 年 i7-4771 单机;现代多核 + campaign 并行化(见 E25 第 5 步)可大幅压缩 Fig.11 的 2.42 月。

**最小复现路径(建议,ARM64)**:gem5 DerivO3CPU(ARMv8)× RF(128 项)× 3 个 MiBench(fft、sha、qsort):先跑脆弱区间 profiling → 60K 初始列表 → 分组(预期组数/代表数:参考原文组均 <100、典型 5–40)→ 注入代表(预期几百–几千)→ 对照全量 60K → 验证:(a) 六分类差异 <1.5 百分点,(b) 加速比落在 40–100×(RF MiBench 区间 43.7–93.1×),(c) 同质性 >0.9。

## 9. 局限与坑

1. **只测瞬态单比特、只测 3 个 SRAM 结构**(RF/SQ/L1D data):ROB/IQ/TLB/分支预测器未做;组合逻辑与 FU 未做(E25 补);
2. **同质性假设的边界**:分组纯度依赖"同静态指令+同字节 ⇒ 同效应";对强输入敏感的指令(除法、超越函数)或 SVE 变长向量操作,该假设未经验证——ARM64/SVE 复现时需先重测同质性(这是复现工作的第一验证点,不能默认成立);
3. **ACE-like 区间定义改动了读终点**(提交读切分),总时间与经典 ACE 相同,但区间末端指令的归属与经典 ACE 不同——与 ACE 结果比对时注意口径;
4. **SPEC 精度验证只在 Simpoint 末端截断**(Unknown 类 11% 上下,无法判 SDC)——SPEC 上的"精度不损"实际只在 gcc/bzip2 两个基准、五分类(无 SDC 终态)意义上成立,引用时不要扩大;
5. **60K 基线本身仍是采样**(非穷尽):"精度"定义是 MeRLiN ≈ 60K 采样,不是 ≈ 真值;
6. Fig.16 的 L1D 32KB FIT(622 vs 1120)与 ACE-like L1D 值(2,459,614)直接目视对比易误读——轴为双 FIT(左线性右 log 之类),以正文结论为准;
7. **Relyzer 对比的公平性**:Relyzer 启发式被搬到其设计域(软件层)之外评测,结论"MeRLiN 更准"限于微架构级语境;
8. 硬盘 1TB、内存 16GB 的 2017 配置:脆弱区间 repository 的存储预算(10–100MB/负载)在长 SPEC 负载上会放大,复现时注意;

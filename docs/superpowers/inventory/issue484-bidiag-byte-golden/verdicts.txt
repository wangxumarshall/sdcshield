| mode  | fault | VL=512          | VL=128          | 结论 |
|-------|-------|-----------------|-----------------|------|
| old   | none  | FAILS=0         | —               | 修复前基线绿 |
| old   | tiny  | **FAILS=0**     | **FAILS=0**     | **盲区复现(红)** |
| new   | none  | FAILS=0         | FAILS=0         | 修复后无假阳 |

- old×tiny(盲区复现,gem5-logs/old-tiny-vl512.log / old-tiny-vl1.log):
  全部容差比对 PASS —— reroll max_diff=2.043e-13 ≤ tol=3.734e-08、

  同错);SDCSHIELD_FAILS=0。注入真实性由 FNV 交叉证明:
  FNV_WORK_LAST(old×tiny)=50f7590874bdfe93 ≠
  FNV_WORK_LAST(old×none)=635273fe796ee882(翻转确在输出字节里)。
- new×tiny(修复捕获,gem5-logs/new-tiny-vl512.log / new-tiny-vl1.log):
  每个回放轮(iter 1/3/5/7)字节通道失配 ×4:
  "byte-exact deviation from init-thread SVE golden at (32, 32): worker
  3.2009611278502348 vs init 3.2009611278502352"(差 4.4e-16 = 1 ULP),
  且同轮容差比对仍 PASS(max_diff=1.146e-13)——容差漏、字节抓,同屏。
- new×none(无假阳 + 通道前置条件,gem5-logs/new-none-vl*.log):
  FNV_GOLDEN_SVE == FNV_WORK_LAST(old×none) = 635273fe796ee882(VL=512)
  —— init 角色与 worker 角色两次独立内核调用逐字节一致(内核确定性,
  字节通道无假阳的前置条件)。

FNV_GOLDEN 各档不同(128=b64acdf9beea9431 / 256=b5d063a594ddba6c /
512=4b6678bd666d56f0 / 1024=d39b32dc3324bca3)—— 实证排查:「标量参考」
bidiagonalize_ref 在 +sve 编译单元被编译器自动向量化上了 SVE(harness
clang 构建 objdump --disassemble=bidiagonalize_ref 含 41 处 z/p 寄存器
引用;仓库真实构建 libtests_sve_avx53.a 的同名符号含 43 处,同为 GCC
+sve -O 自动向量化),其归约树随运行时 VL 变化 → golden 字节随档位漂
移。这是**先于本修复的构建层事实**(标定基线 ~4e-14 亦由此而来),对
本证据链结论零影响: 字节通道只用显式 ACLE 内核(golden_sve 与 work 由
同一二进制内同一函数计算,编译器一致性免疫);容差通道的判定在该漂移
下依然全 PASS(2×2 矩阵的 old×tiny=0 不依赖 golden 的具体档位字节)。
n=68 为非整 VL 倍形状(谓词尾路径)。顺带观察(供后续单元参考,非本补
丁范围): 容差通道的 golden 独立性是源码级而非数据通路级——cf. neon_rot
族的 check-scalar-golden.sh 机械门,本测试的 ref 未做防自动向量化钉扎。

## 3. 诚实边界

- gem5 SE 单上下文,**不物理跨核**:跨核性依赖 (i) 每 VL 档内核确定性
  (上面双调用字节一致已验) + (ii) 同芯片同核设计(Kunpeng 920 部署
  目标)——文件头 docblock 的残留盲区 (a)/(b)(-n 1 恰与控制线程同核、
  芯片级同错)正是该论证失效处。
- 注入模型为「输出级确定性微扰」,非 RTL/微架构级位翻转(CHAOS 寄存器
  注入);它精确对标本 issue 的指控对象——校验通道对确定性低幅度位错
  的漏检,而非内核对硬件故障的敏感度(后者由 svaddv/svmla 压测面承担)。

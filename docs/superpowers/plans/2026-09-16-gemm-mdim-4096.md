# GEMM mdim 上限放宽到 4096 + README 默认参数与推荐模式 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 openblas_{d,s,z}gemm 的 mdim 合法域从 16..1024 放宽到 16..4096（支持 2048 核/大内存服务器的大矩阵压测），并在 README 写全默认参数与推荐战役模式。

**Architecture:** 纯域检查放宽——三测试的尺寸路径已经是 `(size_t)` 转换链（4096²·2 = 33.5M < int32 上限 2.1G，无溢出）；cblas 的 `blasint` 在本机构建就是 int，4096 远小于 INT_MAX；框架对核数无硬编码上限（`device_info[]` 是 C99 弹性数组、`total_thread_count` 运行期取自拓扑）。改动 = 三文件的域检查 1024→4096 + 相关注释/文档同步；OOM 防护（`report_fail_msg` fail-loudly）天然兜底大矩阵在内存不足主机的失败。

**Tech Stack:** 既有 knob 机制（`-O <testid>.mdim=N`）、cblas、README markdown。

**Spec:** `docs/superpowers/plans/2026-09-16-gemm-mdim-knob.md`（前序计划，本计划是其放宽延续）；CORE179 报告（cache-domain 判别依据）。

## Global Constraints

- **默认行为零变化**：不传 knob 仍 256；默认档回归 pass 不变。
- **新合法域 16..4096**：三文件的域检查、错误消息、头注释全部 `1024→4096`；K 上界注释同步（`K <= 4096`，点积界 `K*(2e-3)² <= ~1.7e-2`，仍距 ±1e300 tripwire 无穷远）。
- **2048 核**：框架无核数上限（`device_info[]` 弹性数组 + `total_thread_count` 运行期取拓扑，framework/sandstone_p.h:423、sandstone.cpp:366）——**不需要任何代码改动**；README 的内存账表给出 2048 核各档占用，让操作员自选档位。
- **内存账必须写进 README**（操作员选档依据）：每线程 scratch = 3 矩阵；dgemm mdim=4096 → 0.38GB/线程，2048 核全跑 786GB——**大矩阵档在大核数机器上必须配合 `-n`（限并发）或按内存预算选档**；OOM 时 `report_fail_msg` fail-loudly（不是静默或崩溃）。
- **验证受本机限制的诚实边界**：本机 128 核/29GB——**4096 档只能单线程验证**（dgemm 单线程 scratch 0.38GB+共享 0.3GB ≈ 0.7GB 安全；全核 49GB 不可行）。全核大档验证留给大内存机器，README 如实标注。4096 档单迭代时长分钟级（O(mdim³)：1024 档 ~32s → 4096 档 ~34min），验证用 `-t` 覆盖单迭代完成或接受超时前的部分迭代（fracture 模式下部分迭代也算有效压力）。
- 一补丁一单元：Task 1（代码放宽，一个 commit 含三文件——同一原子变更拆开会留下域检查不一致的中间态）；Task 2（README，一个 commit）。
- 验证真实跑+引用输出；x86-64 零影响（aarch64-guarded 文件）。

替换为（完整内容）：

```markdown
**GEMM 矩阵尺寸扫谱（test knob）**：三个 `openblas_*gemm` 测试的矩阵尺寸**默认 256**（512KB/矩阵，L2 域；不传 knob 时行为与历史版本完全一致），可经 test knob 扫谱：`-O <testid>.mdim=N`，N∈[16,4096]，越界 fail-loudly 报错并提示合法域。**必须带测试 ID 前缀**——框架的 TestKeyWrapper 以 `<testid>.<key>` 查找（`framework/test_knobs.cpp`），裸 `mdim=N` 会被静默忽略、回退默认 256（用 `-v` 可在日志中核对每个 knob 的实际生效值）。

**每测试每档工作集足迹（每线程 scratch = 3 矩阵；矩阵字节数 = mdim² × 元素宽度）**：

| 档位 | dgemm (double) | sgemm (float) | zgemm (complex double) | cache 域 |
|---|---|---|---|---|
| `mdim=64` | 32KB/矩阵 | 16KB | 64KB | L1D |
| `mdim=256`（默认） | 512KB | 256KB | 1MB | L2 |
| `mdim=512` | 2MB | 1MB | 4MB | LLC |
| `mdim=1024` | 8MB | 4MB | 16MB | DRAM |
| `mdim=2048` | 32MB | 16MB | 64MB | DRAM/远端 NUMA |
| `mdim=4096` | 128MB | 64MB | 256MB | 大页/NUMA 交错 |

**全核内存预算表（scratch 合计 = 3 矩阵 × 核数；选档前先对照主机内存）**：

| 核数 | dgemm@1024 | dgemm@4096 | sgemm@4096 | zgemm@4096 |
|---|---|---|---|---|
| 128 核 | ~3GB | ~49GB | ~25GB | ~98GB |
| 512 栀 | ~13GB | ~197GB | ~98GB | ~393GB |
| 2048 栀 | ~50GB | ~786GB | ~393GB | ~1.6TB |

（zgemm 内存紧张时推荐档 **512**；1024 档 128 核实测 ~7.7GB。内存不足时 OOM 走 `report_fail_msg` fail-loudly，不是静默或崩溃。）

**推荐战役模式**：

```bash
# 模式 A：谱系扫档（cache 域逐层压测；openblas 单独跑避免混跑 cache 污染）
for m in 64 256 512 1024; do
  ./builddir/sdcshield -O openblas_dgemm.mdim=$m -O openblas_sgemm.mdim=$m \
    -O openblas_zgemm.mdim=$m -e openblas_dgemm,openblas_sgemm,openblas_zgemm -t 15m
done

# 模式 B：混合套件（多样性 = 检出率；默认 256 档，与全部其他测试同跑）
./builddir/sdcshield -e openblas_dgemm,openblas_sgemm,openblas_zgemm,zstd19,sleef_neon,isal_igzip,pocketfft_fft,openssl_sha -t 30m

# 模式 C：大矩阵深压（大内存主机；4096 档单迭代分钟级，需长窗口，必要时 -n 限并发控内存）
./builddir/sdcshield -O openblas_dgemm.mdim=4096 -e openblas_dgemm -t 2h        # 或 -n 64 限制并发
```

模式选择依据：CORE179 探针证明 store→reload 的 cache-domain 与跨线模式是触发判别条件（模式 A 逐层覆盖）；文献共识"负载多样性即检出率"（模式 B）；大矩阵档把分块 GEMM 的 packing/回写路径推进 DRAM 与 NUMA 远端域（模式 C）。mdim>256 档在固定时间窗内迭代数按 mdim³ 骤减，是计算密度换覆盖广度的交换——统计采样请加长 `-t`。
```

## 诚实性边界

1. **本机（128 核/29GB）无法验证全核大档**：4096 档全核需 49GB（dgemm）——单线程验证 + README 内存表是本机能提供的最强证据；全核大档行为留待大内存机器。
2. **4096 档单迭代分钟级**（O(mdim³) 推算 ~34min/迭代 dgemm 全核单迭代）——验证跑的是超时窗口内的部分迭代（fracture 模式下部分迭代即有效压力），完整迭代统计需 `-t` 小时级窗口。
3. 2048 核的内存表是算术推算（3 矩阵 × 核数），未实测（无 2048 核机器）；框架侧无核数上限的结论基于代码结构（弹性数组 + 运行期拓扑）。

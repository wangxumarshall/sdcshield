## 负载环境基准（不可改变，来自 docs/docs_xu/2026-09-19-avx53-workload-environments.md）

- **FMA 10 个**：VECTOR_SIZE(4/8/16)、随机域([-10,10]/[-1e10,1e10]/[-1e6,1e6])、特殊值注入模式(0/1/-1/Inf, i%4==0 或 i%3==0 触发)、INNER_ITERATIONS(5/10)、逐位 memcmp + store/reload 一致性、fprintf(stderr) 日志格式 —— **全部保留，只换向量指令**。
  - 映射：`vld1q_f64`×2 → `svld1_f64`（VL=256 一次 4 lane；VECTOR_SIZE=8 用 2 次 svld1 或谓词分区，VECTOR_SIZE=4 用谓词掩半或 2nd half）；`vfmaq_f64` → `svmla_f64`；`vceqq_f32` → `svcmpeq`+`svcntp`。
- **Mesh 18 个**：两框架（A=协同竞争写+栅栏+全量读校验+轮次翻转；B=init golden + 顺序扫描）。工作集(1024 元素/1M=4MB)、块结构(4/8/16 元素逻辑块)、原子同步逻辑 —— **全部保留**。
- **eigen 1 个**：M_DIM=300 复数矩阵 SVD 式负载（Householder 双对角化路径的 FMA/乘加链），golden=首线程计算，后续比对（EigenSVDTest 的 golden 模式）。
- **ipsec 24 个**：OpenSSL EVP 加解密往返 + HMAC/SHA 摘要，init 预计算 golden，run 重算 memcmp_or_fail。**SVE 版：哈希函数体换成自写 SVE 多流实现**（HMAC 结构保留：ipad/opad 两轮，K xor ipad → hash → K xor opad → hash），每个消息流独立 → 4/8 路并行向量化消息调度与轮函数；加密 EVP 原样；golden 用同一 SVE 实现的首次计算（自洽 golden——与现有测试"golden=同一函数首调"模式一致）。
  - SHA-1: W[t]=rol(W[t-3]^W[t-8]^W[t-14]^W[t-16])，4 流（VL=256/32bit lane=8 流，SHA-1 逻辑按 4 流起步验证后可上 8）
  - SHA-256: σ0/σ1/Σ0/Σ1 全部是 32-bit 加法/异或/循环移位 → svadd/sveor/svrol（SVE 有 `svxar`/移位类指令可组合）
  - SHA-512/384: 64-bit 版同构（VL=256/64bit lane=4 流）
  - 224/384 = 256/512 的截断版
  - HMAC 外层结构不变，内层压缩函数并行

## 关键实现细节（防错清单）

1. **SVE 谓词粒度**：VL=256 → f64 4 lane / f32 8 lane / s32 8 lane / u8 32 lane。原 VECTOR_SIZE 与 VL 不整除时（如 f64 VECTOR_SIZE=4 恰好=VL lane 数），用 `svwhilelt_b64(0, VECTOR_SIZE)` 谓词精确控制——**不要**依赖 svcntb 恰好相等。
2. ** VECTOR_SIZE=16 (fma_patterns_avx512_ps)**：f32 16 lane = 2 次 svld1_f32（VL=8）或单次 VL=512 机器自动适应——写 2 次循环加载保证 VL 无关性（`for i in 0..VECTOR_SIZE step svcntw()`）。
3. **保持日志格式**：`fprintf(stderr, "<sve_name>: Iter %lu, ...")` 原样（框架会把 stderr 收进日志）。
4. **特殊值注入逻辑逐字保留**（i%4==0 / i%3==0 / (i+group)%4 分支结构）。
5. **mesh 原子同步逻辑不动**：`next_block.fetch_add`、`global_sum.compare_exchange_weak`、`round_done` 轮次、`__sync_synchronize()` 栅栏全部原样。只把块内 4 元素 vld1q/vst1q 换成 svld1/svst1（块大小字节数不变：int32×4=16B → SVE 谓词 4 lane；块=8/16 的用对应 lane 谓词分 1-2 次访存）。
6. **ipsec HMAC 多流**：HMAC 结构 = H(K^opad ‖ H(K^ipad ‖ m))。K^ipad 块（64B for SHA-1/256, 128B for SHA-384/512）是单块压缩（不可并行），消息体 m 的多块压缩才可多流并行——但**单条消息的块间有链依赖**！多流并行的正确形态 = **多条独立消息**（如 datasize 拆 8 份并行流式摘要再聚合？不行，会改变 MAC 语义）。**正确方案**：保持单消息 HMAC 语义不变，但**消息调度展开 + 轮函数内的 8 个工作变量更新在 SVE 里跨 8 个独立 HMAC 实例并行**——即 run 循环里同一线程对**同一 (key,msg) 计算 8 次**（7 次丢弃用于压满向量通路）？这浪费 8 倍算力且不是"负载等价"。**最终方案**：单流 HMAC 语义保持 + SVE 向量化**轮内并行**（SHA-256 单轮 8 变量的依赖链不可向量化）→ **接受现实：SHA 家族单消息本质串行，SVE 多流只能跨消息并行**。因此 ipsec SVE 版 = **每次 run 并行计算 datasize 消息 + N 个变体消息（改变 IV/计数器后缀）的 HMAC**，golden 同样预计算 N 个；主消息（datasize 原文）的 MAC 语义与原测试完全一致，N-1 个变体是 SVE 通路的等价负载填充（lane 利用率），比较全部 N 个。这保持"每次 run 的计算=原测试超集，主结果语义不变"。**⚠️ 此方案在 Task 6 实施时如发现更优解（如 OpenSSL 风格 4 路并行消息调度），按实际可实现性调整并在此计划更新。**
7. **eigen SVE 版双对角化**：300×300 complex<double> 全量 Householder 双对角化在单线程 60s 内可能偏重——降到 **M_DIM=300 real double**（去 complex，负载量减半）或保持 complex 但只做双对角化+回代不做完整 SVD（原测试=完整 BDCSVD；我们的"正常版"目标是同类型 FMA 密集矩阵负载，诚实描述差异："SVD-style Householder bidiagonalization payload, not full BDCSVD"）。Task 4 实施时先 64×64 起步标定单次耗时，选 60s 内迭代 ≥ 数十次的维度。
8. **自洽 golden 注意**：SVE 版 ipsec 的 HMAC golden 用**同一 SVE 实现首调**生成（init）——这测不出"实现本身错"。**弥补**：Task 5 的 SHA 内核先与 OpenSSL 输出全向量比对（独立验证程序），证明实现正确后再用作 golden 基。
9. **VL 无关性**：所有测试必须用 `svcntb()/svcntw()/svcntd()` 适配任意 VL（128-2048），不硬编码 256。谓词用 `svwhilelt` 而非 svptrue 全开（尾部安全）。

# Plan: issue #180 — Float80/long-double 框架适配 aarch64 binary128

## 目标（issue #180）

解除 `framework/unit-tests/sandstone_utils_tests.cpp` 中两个 x86-only 守卫
（`DataCompare.Float80`、`FloatGeneration.new_random_float_prototypes`，
守卫 commit a20528a8），使 aarch64 全绿；x86 行为零变化（rule 5）。

**Architecture**：选型 A（per-arch 语义）——`Float80` 在两架构都表示
`long double`：x86 = x87 80 位（显式整数位 jbit），aarch64 = IEEE binary128
（1+15+112，隐式整数位）。位布局、谓词、构造器、golden 表全部 per-arch；
指数类宏（15 位、bias 0x3fff、全 1 = Inf/NaN）两种格式完全相同，保持共享。
不选 B（aarch64 上把 `long double` 重映射到 `Float128Data`）：FloatGeneration
测试直接构造 `Float80` 结构体，不经过类型映射，B 无法修复它；且
`Float128Data` 在 aarch64 上无对应 C 类型（`__SIZEOF_FLOAT128__` 未定义，
实测），重映射后 `Float80Data` 成为孤儿枚举。

**Tech Stack**：C/C++ 位域 union（GCC 小端连续分配）、meson、gtest。

**Spec**：issue #180 正文（本文「真正的工作」四项逐条对应：①Float80 语义
= 本 plan 选型；②IS_* 位级适配 = Task 1；③`_Float64x` 跨架构核对 = 已实证
（见下）；④aarch64 golden 位型表 = Task 4）。

## 事实基础（全部实测/读码，2026-10-31，本机 aarch64 GCC）

1. **`_Float64x` 期望值跨架构成立**：本机实测 `__FLT64X_MANT_DIG__=113`、
   `sizeof(_Float64x)=16`——aarch64 上 `_Float64x` 即 binary128 的
   `long double`；x86 上它是 x87 80 位。TS 18661-3 的「binary64 之扩展」
   在两架构都拼作 `_Float64x`。`type_name(Float80Data)` 返回值**无需改动**，
   仅更新注释。
2. **golden 位型表（binary128 = IEEE 754 quadruple）**：C 探针与 C++
   `std::numeric_limits` 探针双路实测一致，且与 x86 侧
   `DataCompare.Float128` 测试的十六进制表互相印证（同为 binary128）：

   | 值 | 十六进制（16B） | glibc `%La` |
   |---|---|---|
   | 0.L | 00000000000000000000000000000000 | 0x0p+0 |
   | -1.L | bfff0000000000000000000000000000 | -0x1p+0 |
   | max | 7ffeffffffffffffffffffffffffffff | 0x1.ffffffffffffffffffffffffffffp+16383 |
   | min | 00010000000000000000000000000000 | 0x1p-16382 |
   | denorm_min | 00000000000000000000000000000001 | 0x0.0000000000000000000000000001p-16382 |
   | epsilon | 3f8f0000000000000000000000000000 | 0x1p-112 |
   | 1+epsilon | 3fff0000000000000000000000000001 | 0x1.0000000000000000000000000001p+0 |
   | inf / -inf | 7fff…0 / ffff…0 | inf / -inf |
   | quiet_NaN | 7fff8000000000000000000000000000 | nan |
   | signaling_NaN | 7fff4000000000000000000000000000 | nan |

   注：`%La` 渲染两架构格式不同属预期——x87 显式整数位使 glibc 打印
   `0xf.xxx`（4 个前导 hex 位），binary128 归一化打印 `0x1.xxx`。
3. **消费面（grep 全仓）**：`Float80` 结构体真实用户 = Floats.cpp
   （static_asserts + `new_random_float80`）、static_vectors.c
   （float80 向量池，仅 `.sign/.exponent` 字段名）、generated_vectors.c
   （497 条 `.jbit=` 初值）、两个单测文件。**tests/ 下零测试用
   float80 向量池**（`pick_float80_vector`/`random_float80` 等无任何调用者，
   上游遗留）。`context_dump` 的 `Float80 st[8]` 在 `#ifdef __x86_64__` 内。
   `acl_gemm` 用 `long double` 做高精度累加（纯算术，与位布局无关，不受影响）。
4. **`type_real_size(Float80Data)` aarch64 上错报 10**（枚举低 6 位 = 9）：
   binary128 全 16 字节都是有效数据。用户 = 单测 helper + **logging.cpp:1284
   mismatch XOR mask**（现状会截掉高 6 字节，指数/符号位差异进不了 mask——
   本修复顺带纠正）。`type_size` 已特判返回 `sizeof(long double)`，无需动。
5. **位域布局可行性**：`mantissa_lo:64 + mantissa_hi:48 + exponent:15 +
   sign:1` 恰好按 64 位单元对齐填充（0-63/64-111/112-126/127），无需跨单元
   straddle；union 与 `long double as_float`（16B/16 对齐）同尺寸。

## 全局约束

- x86 零行为变化：所有框架改动包进 `#ifdef __aarch64__` / `#else 原文`
  分支；x86 预处理输出不变。
- 一个移植点一个 commit（rule 1）：框架适配 + 解守卫是不可拆的同一单元
  （守卫不解除则框架改动无法验证；框架不改则测试无法编译）。
- 零新警告（rule 2a）；DCO 签名（rule 3）。
- gem5-fi 规则不适用：受影响行为（unittests）在本机原生可跑（aarch64）。

### Task 1: Floats.h — Float80 per-arch 布局/宏/谓词/构造器

**Files**: Modify `framework/fp_vectors/Floats.h`

- [ ] 在 FLOAT80 宏区（:137-141 后）加 aarch64 分数宏块 + `#undef` 四个
      x87-only 宏（`FLOAT80_JBIT_BITS`/`FLOAT80_MANTISSA_BITS`/
      `FLOAT80_MANTISSA_MASK`/`FLOAT80_MANTISSA_QUIET_NAN_MASK`——aarch64
      上误用即编译错）；共享宏（EXPONENT/BIAS/SIGN/QUIET，两格式位同义）不动。
- [ ] `struct Float80`（:766-833）拆 per-arch：`#ifdef __aarch64__` 新布局
      （位域 `mantissa_lo:64, mantissa_hi:48, exponent:15, sign:1`；
      `as_nan` 拆 `payload_lo:64, payload_hi:47, quiet:1, …`；`as_hex` 换
      `low64/high64` 全 128 位视图；去 x87 形状的 `as_hex32`）；`#else`
      原 x87 文本逐字保留。C++ 方法与 C 接口函数 per-arch 同步：
      - 4 参构造 `Float80(s, e, mantissa_hi, mantissa_lo)`——与 x86
        `(s, e, jbit, mantissa)` 同元数，`new_float80(0,0,0,0)` 两边都构造
        +0.0（单测源文件因此零改动）；
      - 谓词：`is_zero` = exp==0 && hi==0 && lo==0（binary128 无伪规范数，
        按 IEEE 定义含指数判）；`is_denormal`/`is_inf`/`is_nan`/
        `is_max`/`is_snan`/`is_qnan` 按对应位判；`get_nan_payload` 返回
        111 位 payload 的低 64 位（注释言明截断；唯一消费者是零值判）。
- [ ] `new_float80` per-arch 签名（C/C++ 两式）。

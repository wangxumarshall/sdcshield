## 根因定案（本机实测证据链）

### 实验一：当前代码在 VL=256 真实硬件上全 pass（前提检验）

`./builddir/sdcshield --quick -e sve512_f32_chain_arm -e sve512_f32_chain_svd -e sve512_f64_chain_svd -e sve512_f64_special_svd`：
4 测试真实运行（runtime 49.9/215.4/138.7/11.4 s，非 skip），`result: pass`，`exit: pass`。
**编排者"可直接复现失配"的前提对当前代码不成立——失配不在当前树上。**

### 实验二：issue 时刻代码（3d731d24）在本机也全 pass（根因反推的关键对照）

临时检出 3d731d24 版 4 文件（不提交）重建运行：4 测试同样真实运行全 pass
（runtime 7.9/431.7/270.5/21.6 s）。反汇编证明 golden 与 hw 走**不同指令路径**：
golden 内联后为标量 `fmadd s0, s2, s1, s0`，hw 为 `fmla z0.s, p0/m, z1.s, z2.s`
（`objdump -d .../sve512_f32_chain_arm.cpp.o`）——两路径一致是**非平凡的微架构属性**，
不是编译器把 golden 向量化成同一条指令的 vacuous 一致。

### 实验三：位级探针 + 独立复现器定案 f32 根因

**位级探针**（gcc 12.3.1 `-O2 -march=armv8.2-a+sve`，机械可复核）：

```
exp=0x3FE  word=0xFF123456  isnan=0  isinf=0  value=-1.94339e+38
exp=0x3FF  word=0xFF923456  isnan=1  isinf=0  value=-nan
raw shifts: 0x3FEu<<23 = 0xFF000000, 0x3FFu<<23 = 0xFF800000
```

`0x3FE<<23` 截断为 `0xFF000000`（符号位被移位置 1，指数域 **0xFE=254，有限**，
值 ≈ −1.m×2^127）；`0x3FF<<23` = `0xFF800000`（指数域 0xFF，随机尾数非零时为
NaN，为零时 −Inf，后者概率 2^-23）。

**独立复现器**（入库：`docs/superpowers/inventory/issue182-sve512-allvl/repro_qnan_bias.cpp`，
忠实重建 3d731d24 的完整 `random_finite_f32()`（25% 表抽取 + 75% 构造分支），
splitmix64 RNG，实测输出归档同目录 `repro_output.txt`）：

```
== pre-ff8ddec1 generator (exp = 0x3FE/0x3FF << 23, 3d731d24) ==
[old] VL=256 bits, lanes=8
[old] operand composition (both streams, 8192 draws): 3109 NaN / 0 Inf / 5083 finite (3047 of them |x|>1e30)
[old] chain saturation (first non-finite acc step, 0-based): min=0 mean=0 max=0 (512 = never)
[old] scalar-fmadd golden vs SVE-FMLA after 512 steps: 8/8 lanes bit-EXACT match

== fixed generator (exp = 0x7E/0x7F << 23, current tree) ==
[new] VL=256 bits, lanes=8
[new] operand composition (both streams, 8192 draws): 0 NaN / 0 Inf / 8192 finite (0 of them |x|>1e30)
[new] chain saturation (first non-finite acc step, 0-based): min=512 mean=512 max=512 (512 = never)
[new] scalar-fmadd golden vs SVE-FMLA after 512 steps: 8/8 lanes bit-EXACT match
```

**过程事故（诚实记录，检视轮发现）**：复现器首版用朴素 LCG（`x*1664525+c`，
a、c 均奇 → LSB 周期 2），3 抽/操作数的调用模式下 m 流的指数抽取恒落奇数次
调用——整流退化恒 0x3FF，首版输出 "4096 NaN / 0 finite" 是**伪影**，据此写下的
"操作数 100% qNaN"口径错误。检视（PR #381 round 1）以位级算术证伪（0x3FE 臂
是有限巨幅），探针+直方图复核成立；本版改用 splitmix64 并审计双流，数字以本
版为准（3109/8192 = 38.0% NaN，与理论 37.5% 吻合）。

### 根因结论

**f32 两测试（sve512_f32_chain_arm / sve512_f32_chain_svd）**：
`3d731d24:tests/cpu/arm64/sve512_f32_chain_arm.cpp:163` 的操作数构造
`uint32_t exp = 0x3FEU + (random32() & 1U)` 把 **f64 偏置指数常数移进 f32 位型**。
每构造抽取 ~50/50：0x3FF 臂落 NaN/−Inf 类，0x3FE 臂落 ≈2^127 巨幅有限负数；
计入 25% 有限表抽取后整体 ≈ **37.5% NaN 类 + 62.5% 有限（其中 37.5% 巨幅）**
（复现器实测 3109/8192 = 38.0% NaN）。后果：
- 链在数步内饱和为 NaN/Inf（复现器实测全部 lane 第 0 步即非有限；512 步全程
  有限的概率 ≈ (5/8)^1024 ≈ 0，且巨幅×巨幅本身即上溢），"有限带 |x|≤2、
  永不 NaN" 的文件头不变量被破坏；
- golden（标量 `fmadd`）与 hw（`FMLA`）在 NaN 输入下的**载荷位选择是架构
  IMPLEMENTATION DEFINED**（ARM ARM 对 NaN 结果的 significand 传播不做标量/向量
  一致性要求）——链结果为 NaN 时，字节精确 golden 在两条指令路径间的合法性完全
  取决于实现的偶然同选，架构上就是无效测试设计；
- 实测：0xd02（本机，实验二/三——含纯 NaN 饱和链的最大载荷分歧机会）两路径
  逐位一致；0xd22（历史 512-bit 验证）通过，同理推断同选。GH runner 的
  Neoverse N2 上两路径分歧（**推断**——由"代码事实 + 架构规则 + 观察到失配"
  三者反推的唯一自洽解释；N2 本体不可再访问，无法直接观测）→ 字节失配 →
  误报 "SDC detected"。
- **该缺陷与 VL 完全无关**——任何 VL 下、任何"标量/向量 NaN 载荷分歧"的实现上
  都会失配。`svcntb()==64` 门控把操作数域 bug 误诊为 VL 问题，故为占位。
- 修复 = `ff8ddec1`（0x7E/0x7F 正确 f32 偏置，操作数真有限）——已在树。

**f64 两测试（sve512_f64_chain_svd / sve512_f64_special_svd）**：
issue 时刻的操作数生成本来就正确（f64 偏置 0x3FE/0x3FF 对 f64 是对的；special 走
分类比较）。数学论证：有限操作数下 golden 与 hw 逐 lane 同序、每次一步融合乘加、
单次舍入、同一 FPCR——**标量 FMADD ≡ SVE FMLA 逐位相等是架构保证的**
（IEEE 754 单舍入 + ARM ARM 对有限结果的确定性定义），不存在合法的 VL 依赖发散。
实证：0xd02 上 issue 时刻代码与当前代码均 pass（实验一/二）；gem5 四档 kernel 证据
（PR #283 48 run）与真二进制 512 档（PR #307）全绿。**结论：f64 两测试无测试侧
缺陷可寻；历史 N2 失配是 runner 侧数值发散（真实 SDC 候选或运行环境异常，与
SVD 级工作集的内存压力相关——同族 64KB 工作集的 _arm 变体当时通过），CI 原始
日志已过期、该 runner 不可再访问，无法复盘定性——如实声明边界。测试本身架构
健全，且本计划补齐了真实 VL≠512 硬件 + 全四档的正向验证。**

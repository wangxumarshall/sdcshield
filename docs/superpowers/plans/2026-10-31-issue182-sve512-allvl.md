## 根因定案（本机实测证据链）

### 实验一：当前代码在 VL=256 真实硬件上全 pass（前提检验）

`./builddir/sdcshield --quick -e sve512_f32_chain_arm -e sve512_f32_chain_svd -e sve512_f64_chain_svd -e sve512_f64_special_svd`：
4 测试真实运行（runtime 49.9/215.4/138.7/11.4 s，非 skip），`result: pass`，`exit: pass`。
**编排者"可直接复现失配"的前提对当前代码不成立——失配不在当前树上。**

### 实验二：issue 时刻代码（3d731d24）在本机也全 pass（根因反推的关键对照）

临时检出 3d731d24 版 4 文件（不提交）重建运行：4 测试同样真实运行全 pass
（runtime 7.9/431.7/270.5/21.6 s）。反汇编证明 golden 与 hw 走**不同指令路径**：
golden 内联后为标量 `fmadd s0, s2, s1, s0`，hw 为 `fmla z0.s, p0/m, z1.s, z2.s`
（`objdump -d .../sve512_f32_chain_arm.cpp.o`）——两路径一致是**非平凡的微架构属性**，
不是编译器把 golden 向量化成同一条指令的 vacuous 一致。

### 实验三：独立复现器位级定案 f32 根因

`/tmp/i182_repro.cpp`（本计划归档，gcc 12.3.1 `-O2 -march=armv8.2-a+sve`）：

```
== pre-ff8ddec1 construction (exp = 0x3FE/0x3FF << 23) ==
[old] VL=256 bits, lanes=8, operands: 4096 NaN / 0 finite
[old] scalar-fmadd vs SVE-FMLA after 512 steps: 8/8 lanes bit-EXACT match
== fixed construction (exp = 0x7E/0x7F << 23) ==
[new] VL=256 bits, lanes=8, operands: 0 NaN / 4096 finite
[new] scalar-fmadd vs SVE-FMLA after 512 steps: 8/8 lanes bit-EXACT match
```

### 根因结论

**f32 两测试（sve512_f32_chain_arm / sve512_f32_chain_svd）**：
`3d731d24:tests/cpu/arm64/sve512_f32_chain_arm.cpp:163` 的操作数构造
`uint32_t exp = 0x3FEU + (random32() & 1U)` 把 **f64 偏置指数常数移进 f32 位型**——
`(0x3FE|0x3FF) << 23` 落入 f32 指数域后恒为 0xFF，任何非零尾数（移位自带或随机
尾数）都构成 **qNaN**。复现器实测 4096/4096 操作数全 NaN。后果：
- 512 步链第 1 步起累加器即 NaN，"有限带 |x|≤2、永不 NaN" 的文件头不变量被破坏；
- golden（标量 `fmadd`）与 hw（`FMLA`）在 NaN 输入下的**载荷位选择是架构
  IMPLEMENTATION DEFINED**（ARM ARM 对 NaN 结果的 significand 传播不做标量/向量
  一致性要求）——字节精确 golden 遍历 NaN 操作数在架构上就是无效测试设计；
- 0xd02（本机，实验二/三）与 0xd22（历史 512-bit 验证）两微架构恰好同选载荷 →
  当时通过；GH runner 的 Neoverse N2 分歧 → 字节失配 → 误报 "SDC detected"。
- **该缺陷与 VL 完全无关**——任何 VL 下、任何"标量/向量 NaN 载荷分歧"的实现上
  都会失配。`svcntb()==64` 门控把 NaN 载荷 bug 误诊为 VL 问题，故为占位。
- 修复 = `ff8ddec1`（0x7E/0x7F 正确 f32 偏置，操作数真有限）——已在树。

**f64 两测试（sve512_f64_chain_svd / sve512_f64_special_svd）**：
issue 时刻的操作数生成本来就正确（f64 偏置 0x3FE/0x3FF 对 f64 是对的；special 走
分类比较）。数学论证：有限操作数下 golden 与 hw 逐 lane 同序、每次一步融合乘加、
单次舍入、同一 FPCR——**标量 FMADD ≡ SVE FMLA 逐位相等是架构保证的**
（IEEE 754 单舍入 + ARM ARM 对有限结果的确定性定义），不存在合法的 VL 依赖发散。
实证：0xd02 上 issue 时刻代码与当前代码均 pass（实验一/二）；gem5 四档 kernel 证据
（PR #283 48 run）与真二进制 512 档（PR #307）全绿。**结论：f64 两测试无测试侧
缺陷可寻；历史 N2 失配是 runner 侧数值发散（真实 SDC 候选或运行环境异常，与
SVD 级工作集的内存压力相关——同族 64KB 工作集的 _arm 变体当时通过），CI 原始
日志已过期、该 runner 不可再访问，无法复盘定性——如实声明边界。测试本身架构
健全，且本计划补齐了真实 VL≠512 硬件 + 全四档的正向验证。**

### 残留风险闭环（P3 Ruling 登记）

P3 计划 Ruling 点名"`sve512_f64_special_svd`（特殊值×块 slab）与
`sve512_f32_chain_svd`（f32×块 slab）的组合寻址无 kernel 模式直接覆盖，真 SVE
主机非 512 档首现失败时首要怀疑"。本计划在 0xd02 VL=256 真实硬件上直接运行这两
测试（实验一，多种子）全 pass，组合寻址经真实硬件非 512 档实证——该残留风险关闭。

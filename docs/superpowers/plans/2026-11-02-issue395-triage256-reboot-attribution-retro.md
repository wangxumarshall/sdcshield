## 目标态（权威口径清单）

1. **两层分开归因**：① 进程层——首跑腿进程结局**未证**（尸体形态不可区分
   「收尸迟滞持续至重启」与「父进程更早死亡」，候选未决，不得用于任何收口）；
   ② 机器层——整机重启未取证、候选**非穷尽**（panic/看门狗/掉电/过热/人为
   运维手动重启），用户态相关性不能排除。
2. **机制断言（R7 迭代「无特权限定」前版——带外路径暴露全称断言破绽后的再收敛）**：
   机器层断言限于「被测进程的 SIGQUIT 超时杀灭及其迟滞是用户态信号处置机制、
   自身无重启能力（不执行任何重启系统调用、不触 BMC/IPMI 带外通道，特权与否
   均然）」；特权/带外重启路径（root shell reboot(2)/shutdown、IPMI
   chassis-power）显式归入「人为/运维手动重启」候选的执行形式。
3. **命名口径**：「死亡」仅存于候选标签与旧版引文；对首跑腿事实一律用「中断」
   （进程层结局未证，不写「死于此格」类既成事实）。
4. **1280 s 语义统一**：该数字一律为 #15 格**全程**（= 超时预算 300 s + 杀灭
   收敛迟滞 ≈980 s）；禁止「杀灭迟滞（1280 s）」式的全程/迟滞混标。
5. **外推锚禁用**：seed1 单样本 1280 s 外推到 seed2 的折算端点是构造值非实测
   端点，不得作对齐锚；时间重合（任何精度）不作因果证据。
6. **取证口径**：BMC SEL 跨重启持久 / journal `--list-boots` 可枚举——事后取证
   面是否仍可及**须实测**，不得断言「已流失」；`-b -1` 仅在其与取证时刻之间
   无重启时指向正确 boot。
7. **范围限定**：「代码 bug 候选 = 0」仅覆盖 380 矩阵格功能行为（seed2 侧证据
   全部来自 09:24 起的有界重跑腿）；两件未证事件（整机重启原因、首跑腿进程层
   结局）不在其内。OOM-kill 归类待取证定（sizing 失效→代码缺陷；内存状态→
   环境边界类）。
8. **progress-log 对账**：条目清单须与分支 diff 的 hunk 实况逐一对账（四个
   hunk：头部环境事件 2 / §4 超时段改写 / §4 异常子类与另注 / §7 结论及观察
   项①②③）。

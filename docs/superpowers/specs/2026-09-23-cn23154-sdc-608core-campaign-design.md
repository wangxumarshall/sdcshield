## 4. 方法论：满机窗口覆盖 + 失效归因 + 混合槽位二分

### 4.1 方法学变更声明（对"字面逐核运行"）

任务规范 §6 阶段 2 预设两条路线：单核打包优先，原理上不可行则满机滑窗 + 集合归因。本设计依据算力守恒论证选择后者并扩展之：

同一总计算量 W 从 576 核搬到 k 核，墙钟至少放大 576/k 倍。若满机单次 >2h：
- 16 rank x 1 线程绑 16 核：约 36 倍，单次 >=72h，38 个核组不可行
- 16 rank 全部同一核：约 576 倍，数十天/次，完全不可行

故字面逐核在原理上不可行（除非试点实测满机运行远小于 2h —— 若证伪则重评估）。此变更及原因按任务规范要求写入最终报告。

### 4.2 窗口覆盖设计

rankfile 每个 rank 显式给 36 个核槽。窗口偏移 o 属于 {0,1,2}：NUMA n 的 rank n 使用核 n*38+o .. n*38+o+35。
- 覆盖：NUMA 内位置 0 与 37 各被 1 个窗口覆盖，位置 1 与 36 各 2 个，位置 2-35 全部 3 个
- 每偏移 >=2 次有效通过，则每核 >=2 个通过窗口
- 控制交错：候选轮之间穿插控制窗口重复（检测时间/温度漂移）；执行顺序轮转化

### 4.3 统计判定

设故障核活跃时单次运行失败概率 >=0.9（用户先验，试点核验）：
- 一次通过：全部 576 个活跃核联合洗清，单侧置信 >=90%
- 两次独立通过：>=99%
- 未通过不等于有故障（概率漏检可能）：按自适应预算加测；同签名两次失败才进入归因
- 覆盖结论表述遵守任务规范 §9.2："在 N 次运行、指定负载与绑定条件下未观察到 SDC" + 失败率上界（95% 上界约 3/N），绝不写"该核无 SDC"

### 4.4 失效归因与二分

任一窗口失败：
1. 差集收缩：失败窗口活跃集减去通过窗口活跃集，得嫌疑集（每 NUMA 1-2 个边缘位，共 16-32 核）
2. rank 级归因（若失败签名可定位 rank：崩溃报错 rank / 错误输出所属分区）：16 个嫌疑核分别作为 16 个 rank 各自 36 槽中的 1 个（其余 35 槽用已洗清算），一轮锁定嫌疑 rank 内单核
3. 无 rank 级签名：二分组合（嫌疑集对半 + 干净核补满 576 槽），对数收缩
4. 确认：单嫌疑核 + 575 干净核重复至置信达标；同时做"跟核 vs 跟 rank"判别（轮换 rank 到 NUMA 分配——故障跟随核走指向硬件，跟随 rank 走指向软件/算法路径，须按任务规范 §6 阶段 0 重审 SDC 判定）

### 4.5 频率闸门下的归因有效性

每轮有效核集 = 计划核集 与（窗口内最低采样 >=1800MHz 的核）之交；<1500MHz 核移出筛查仅保压力；1500-1800MHz 灰区该轮不计、重测；采样缺失整轮记"频率未知"不得归因。

- P4 故障核确认（约 1 天）：重复置信；邻核、同缓存域核、跨 rank 跟随性；920F 无 SMT（记录拓扑证据佐证）
- P5 微架构诊断（约 2-4 天）：见 §9
- P6 最小化与交付（约 2 天）：逐步缩减（每步单因素、A/B 验证、比较失败率而非是否曾失败）；最终报告与全套交付物

## 6. 频率闸门

- 守护进程：作业内常驻，每 10s 采样全部 608 核 scaling_cur_freq 写 CSV（timestamp,cpu,freq_mhz）
- 阈值：>=1800MHz 有效；<1500MHz 移出筛查、仅保压力负载（结果目录内自写 FP/NEON 忙循环绑核，或节点已装 stress-ng 则用之）并持续记录频率；1500-1800MHz 灰区重测；采样缺失即"频率未知"不归因
- 每轮运行自动生成频率摘要（活跃核最低/中位/均值）并入运行记录
- 频率异常清单独立成档（CPU、NUMA、首见时间、最低频率、采样证据）

## 7. 作业与运维框架

- 链式可恢复作业：campaign driver（结果目录 scripts/）以状态文件驱动，作业到期被杀后下一段自动续跑；实验参数与进度落盘、可断点续跑
- 每次运行一条 JSONL 记录（run_id、时间戳、主机、作业 ID、绑定、内存策略、二进制/输入哈希、命令行、退出码、判定分类、频率摘要、原始日志指针）—— 字段对齐任务规范 §5
- 监控：登录节点短周期轮询 NFS 日志（输出节奏 <=2 分钟，遵守通道期限）；长活一律 dsub，不依赖 dattach
- 单次运行超时 = max(3 x 试点实测时长, 4h)；hang 计为独立失败类别
- 防冲突：-x job 独占；提交前 djob 复查；收尾 dkill 并确认无遗留

## 8. 判定分类与 GOLDEN

互斥分类：correct / SDC / crash / hang / timeout / OOM / signal / affinity_failure / infra_failure / freq_grey
- 只有"正常完成 + 输出与 GOLDEN 不一致 + 差异超出预期非确定性"才判 SDC
- crash/hang/others 不计为 SDC（另行归因，禁止把崩溃计为 SDC）
- GOLDEN 多数共识的构造过程与取值全部写入报告

## 9. 微架构诊断（P5）

- 执行 skill：superpowers:systematic-debugging（严格按其根因分析流程）
- 对照设计：每个测试同时在 2 个健康对照核（同 NUMA 邻核 + 远端 NUMA 核）同条件执行
- 自写微基准（结果目录 diagnostics/ 下，非 SDCShield）：逐执行单元（INT ALU / 整数乘除 / FP / SVE lane 与宽度 / load-store / 分支 / shuffle / 转换 / 原子）、数据模式（全 0、全 1、走步位、随机、极值、denormal）、数千次迭代逐位比对
- 缓存层级：L1/L2/L3/本地 NUMA/远端 NUMA（工作集大小、步长、顺序/随机、对齐、cache line 与页边界）
- perf 计数器：先确认事件真实存在再用；只用于相关性，不下因果
- 位签名映射：错误位模式对应源码 + 反汇编定位指令与数据流
- 频率/温度相关性：观察式（不修改全局策略）；受控调频需求写入 admin_requests.md 暂停等待
- 结论分级：已证实事实 / 强相关证据 / 未证实假设 / 已排除原因 / 需额外权限，禁止把相关性写成因果
